### Why Seam 2 was overridden

The checker asserted that reaching an outcome field without tripping the Proxy is "structurally
impossible", and that `replay.test.ts` carries 12+ outcome-leakage tests. A direct probe against the
real `toLeakProofUpcoming` export disproves both:

```
PASS  get trap throws (expected)
FAIL  getOwnPropertyDescriptor bypass  - expected 999 to be undefined
FAIL  spread/ownKeys bypass            - expected [matchKey, redScore, blueScore] not to include redScore
```

`packages/harness/replay.ts:28-36` defines a handler with a `get` trap and nothing else. Property
descriptors and key enumeration forward to the untrapped target. `grep` finds no test referencing
`getOwnPropertyDescriptor` anywhere in `packages/harness/*.test.ts`.

This independently reproduces `01-VERIFICATION.md`'s finding and `01-REVIEW.md`'s CR-01 from first
principles, and extends it: the review named the descriptor path, the ownKeys/spread path is a second
live bypass.

**What is genuinely wired:** `WalkForwardSimulator.runAll()` builds exactly one wrapped object per
match and every registered algorithm reaches `predict()` only through it; `tune.ts` imports
`buildSeasonStream`/`WalkForwardSimulator` unchanged rather than forking them, so the tuner inherits
the same path. The sequencing is real. It is the *barrier* that is porous — predict-before-update
currently rests on convention rather than on the enforcement the roadmap requires.

## Tech Debt

See frontmatter `tech_debt` for the full list. The two that shape future phases:

**Statbotics external-validation channel is dead (WINDOWS #1 + #2, both open).** `api.statbotics.io/v3/year/{year}`
reproducibly 500s, re-confirmed live across three separate dates. The consequence is that the project's
headline claim — "measurably better than Statbotics" — currently has no verified external reference
point. The fallback constants are honest estimates, labelled as such. EVAL-05/COMP-01 in Phase 8 will
publish a comparison table that inherits this weakness, so it needs a plan before Phase 8, not during it.

**Adaptation ships disabled against its own evidence (ALGO-05).** Adaptation-on beat adaptation-off on
holdout Brier on both holdout seasons. D-08 keeps it off. The decision is flagged rather than silently
flipped, which is right — but it is an open call that should be closed before the numbers are published.

## Assessment

The completed slice is in better shape than the single blocker suggests. Requirements are traceable in
all three sources with no orphans; the deliberate "this plan does not claim that ID" discipline across
phase 3 is unusually disciplined bookkeeping. Five of six cross-phase seams are genuinely wired, the
tuner reuses the harness's own primitives rather than forking them, and the versioned-algorithm
round-trip reproduces bitwise.

The one blocker is the right one to care about. The project exists because a previous version had no
evaluation harness and no way to detect that its numbers were wrong. SC-4 is the structural insurance
against that recurring, and it is currently a `get`-trap-shaped hole. It is also a roughly ten-line fix
plus tests.

Worth noting for process: the integration checker returned a clean sweep and asserted the leak barrier
was sound. Had this audit accepted that, the milestone's one real blocker would have been signed off as
verified — by a report citing test coverage that does not exist.
