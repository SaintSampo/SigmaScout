<objective>
Resolve each team's robot photo for each year, offline, and store it in the corpus so the publisher
can bake the URL into the team artifact (D-03).

Purpose: TEAM-02 asks for "its robot image for the selected year". Robot photos live at opaque
Imgur/Instagram keys learnable only from TBA's authenticated media API — they are not derivable
from team plus year. Browser-direct was verified working and then rejected, because it puts the API
key in the shipped bundle and adds a round trip to an already-breached load budget.

Output: a `team_media` corpus table, one new TBA client call, a photo-type allowlist picker, an
`--media-only` ingest pass, and a real run that fills the table for 2022-2026.

No publisher wiring here — `packages/harness/publish.ts` belongs to plan 06-04, and no schema field
either (`packages/harness/pageArtifacts.ts` belongs to plan 06-02), which is what lets all three
wave-1 plans run in parallel.
</objective>
