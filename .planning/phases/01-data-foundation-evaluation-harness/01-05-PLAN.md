<objective>
Build the measurement layer: the metrics D-10 names, the calibration curves that keep them honest, the
tune/holdout discipline D-09 locks, and the two output artifacts D-01 and D-02 specify.

Purpose: This is the plan that makes "measurably better than Statbotics" a number. The tracer proved one
event can be scored; this makes scoring trustworthy. Three things do that work. Winner accuracy is the
headline because it is what the FRC community intuitively compares, with Brier always beside it because
accuracy alone hides overconfidence, and calibration curves beside both because they are the only view
that shows overconfidence directly. The tune and holdout labels exist so a future optimizer physically
cannot launder a tuned number into a headline claim. And the exclusion counts exist because a score
computed over a quietly narrowed population is the easiest way to be accidentally dishonest.

Per D-02 the JSON is canonical and the HTML renders from it — never the reverse. The Phase 8 Compare page
reads this exact JSON, so its shape is a contract from today.

Output: Scored, calibrated, tune/holdout-labelled results in a versioned JSON artifact, and a
self-contained HTML report that reads like a scoreboard against Statbotics.
</objective>

## Flagged assumptions carried into execution

- **Edge probe, EVAL-03 (unclassified — unresolved):** The probe could not classify EVAL-03 and left it
  unresolved rather than guessing. Reviewed manually: the real unsettled question is bin count. Ten
  equal-width bins is the conventional reliability-diagram default and is what this plan implements, but
  bin count materially changes what a calibration curve appears to say — too few bins hide miscalibration,
  too many make every bin noisy. This plan fixes the boundary-assignment and empty-bin contracts by test;
  it does not settle whether ten is the right number for FRC's probability distribution. Revisit when
  Phase 2 has three algorithms to compare curves across.
- **Edge probe, EVAL-04 (unclassified — unresolved):** Left unresolved by the probe. Reviewed manually:
  Phase 1 has no optimizer, so the tune/holdout split has nothing to protect against yet. This plan
  implements the labelling and the headline-eligibility marking so the discipline exists before the
  optimizer arrives in Phase 3 — but nothing in this phase can *test* that an optimizer respects it. That
  enforcement is Phase 3's obligation and should be written into Phase 3's plan as an explicit gate, not
  assumed to be inherited from these labels.
- **A4 (RESEARCH.md):** The Statbotics endpoint may be unresolvable. Task 2 branches on what Plan 01's
  recon actually observed and falls back to a dated constant rather than blocking.
