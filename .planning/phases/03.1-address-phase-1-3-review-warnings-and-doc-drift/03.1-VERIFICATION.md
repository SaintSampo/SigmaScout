### Gaps Summary

**One systemic gap, three instances, all in `01-REVIEW.md`.** All nine Phase 1-3 review warnings plus the phase's own four code-review-gate findings (CR-01, WR-01, WR-02, WR-03 in `03.1-REVIEW.md`) are genuinely fixed in the tree, each with a regression test proven red against pre-fix source (confirmed directly for the code-review-gate's own findings via `03.1-REVIEW-FIX.md`'s recorded red-then-green output, and directly for the nine original warnings by reading the current code against each finding's original description). No published number moved (`data/algorithm-versions/` byte-identical; full suite 667/1). That is the phase's technical work, and it holds up.

What does not hold up is the second half of success criterion 1 and the whole of success criterion 5: **the resolution record itself, not the fix, is stale for three of nine warnings.** The root cause is a wave-ordering gap that is structural, not a one-off mistake: plan `03.1-05` (the doc-reconciliation plan) landed its corrections in commit `f719750c`, and only afterward did this phase's own code-review gate (`03.1-REVIEW.md`) run, find four further issues, and fix them (`d73d5aba`, `280b1e7e`, `11087dd8`, `c09b4b57`) — three of which (all but `11087dd8`, the `makeSigma1` fix, which touches a code path `01-REVIEW.md` never described) touch the exact functions `01-REVIEW.md`'s WR-01 (OPR guard), WR-02 (workspace glob), and WR-03 (write-lock TOCTOU) resolution subsections describe. Nobody looped back to update those three subsections after the code-review gate landed, and the phase's own `reviewFrontmatterLint.ts` — by its own documented design — cannot catch this, because it checks only that a review file's frontmatter agrees with its own body, never that either agrees with the code.

Concretely:
- **WR-02 is the most severe**: its resolution subsection states `pnpm-workspace.yaml` "now lists `packages/*` alongside `apps/*`" — false at HEAD, where both globs are commented out entirely.
- **WR-01** describes the guard's condition as "`residual is non-finite or denom <= 0`" — the pre-CR-01, narrower (and, per CR-01's own finding, buggy) condition, not the widened one actually shipped.
- **WR-03** attributes full closure of the TOCTOU race to a single commit that, per the code-review gate's own later finding, did not in fact close it entirely — a second commit did.

The fix is narrow and mechanical: three append-only corrections to `01-REVIEW.md`'s existing WR-01/WR-02/WR-03 `#### Resolution` subsections, in the same append-never-rewrite style the file already uses elsewhere (and the same style `STATE.md`'s T-03-18b correction in this very phase used). This does not require touching any source code, re-running any test, or revisiting any engineering decision — the decisions recorded in `03.1-REVIEW.md` (e.g., commenting out the workspace globs "to state a fact about the repo rather than an aspiration") are sound and don't need to change. They need to be cross-referenced from `01-REVIEW.md`, which currently doesn't know they happened.
