<decisions>
## Implementation Decisions

### Measurements taken during discussion (bind the planner — do not re-derive)

Run against the live 104,772-match corpus at HEAD on 2026-08-19:

- **WR-06 population** (played, non-tied, empty `winning_alliance`): **0** corpus-wide, **0** in both digest slices.
- **WR-04 population** (matches with no matching `events` row): **0** corpus-wide.
- Scored population is 104,207 of 104,772 total matches.

Consequence the planner must honor: neither WR-04 nor WR-06 can move a committed digest today. Both fixes are forward-looking guards against TBA data quirks and re-ingestion ordering, **not** repairs to a currently-corrupted corpus. No published figure changes as a result of either.

### Silent drops (01-REVIEW WR-04, WR-06)

- **D-01:** When a match is played, scores differ, and `winning_alliance` is empty or invalid, `normalizeMatch` **derives the winner from the score comparison** (`redScore > blueScore ? "red" : "blue"`). TBA's empty field is treated as a reporting gap, not as a statement about the match, so the match stays in the scored population instead of being dropped by `selectMatchesChronological`'s `WHERE m.winner IS NOT NULL` clause.
- **D-02:** `openCorpus` sets **`PRAGMA foreign_keys = ON`**. A future ordering bug that writes a match before its event row must fail at write time, where the bug is, rather than silently at read time through the inner join. Accepted risk: an ingest path that currently completes could begin aborting; measured orphan count is 0, so nothing existing is affected.
- **D-03:** A derived winner is recorded as an **explicit corpus flag column, `winner_imputed`**, alongside the existing `replayed` / `has_score_breakdown` / surrogate flags. This follows DATA-02's established discipline that every data quirk appears as an explicit flag. Ingest-time counts and any harness-side reporting are **reads of that one stored fact** — two independent counters were rejected for the same reason Phase 3's D-10 rejected storing both a pmf and a precomputed summary: two representations of one fact can drift. — **Reversibility:** costly — adds a column to `packages/corpus/schema.sql`, which per established project practice means deleting and rebuilding `data/corpus.sqlite` rather than migrating (no ALTER-based migration path exists). `digest.test.ts`'s committed fixture fallback covers the rebuild window.
- **D-04:** Regression baseline is **asymmetric by design**. Orphan matches are asserted at **0** in a test — an orphan is never legitimate, so it must stay 0 forever. Imputed winners are **reported, never asserted** — a nonzero count there is valid TBA data the project wants surfaced, and asserting 0 would eventually turn correct behavior into a red suite and create pressure to hand-edit an expected number. Both checks skip cleanly when `data/corpus.sqlite` is absent (it is gitignored, so CI skips; the checks fire locally after a re-ingest, which is exactly when these rows would first appear).

### Failing loudly (01-REVIEW WR-05, 01-REVIEW WR-01, 03-REVIEW WR-02)

- **D-05:** `pRedWin` is validated **at prediction emission** — where `predict()` returns, before the prediction is recorded, persisted, or scored. Rejected: validating only at `scoreSet`/`calibrationBins` entry, because Phase 2 writes per-match prediction JSONL sidecars, so a scoring-boundary check lets a non-finite or out-of-`[0,1]` value reach an artifact on disk before anything notices. Emission-time validation also lets the error name the algorithm and match key rather than reporting only that a final score is `NaN`.
- **D-06:** A failing prediction is **quarantined and counted**, not fatal on its own. The quarantine count travels **alongside the Brier score** in the scored result — this is not optional, and follows `score.ts`'s existing convention of returning qualifying counts next to the headline number.
- **D-07:** Quarantining is **bounded**. Past a threshold the run **throws** rather than publishing a score computed on a materially narrowed population. Rationale: a non-finite `pRedWin` usually means a team's state is already corrupt, so one glitch cascades across that team's remaining matches; an unbounded quarantine could hollow out a season and produce a Brier score that looks good precisely because the hard cases left — the exact silent-narrowing failure the project exists to prevent. **The threshold value is planner discretion** (a count, a share of the season, or both).
- **D-08:** The OPR incremental-solve safeguard is **detect-only**: a season-scale property test (thousands of sequential synthetic updates) asserting ratings stay finite and within a documented tolerance of a periodically-refreshed `solveRidgeOpr` batch solve, **plus** a runtime throw in `applyObservation` when `denom <= 0` or `residual` is non-finite. **Explicitly rejected: periodic resynchronization or symmetrization of `P`** — self-healing would move OPR's ratings, and Phase 3's D-04 froze OPR and EPA as fixed baselines precisely because "every SC-3 number is measured against these baselines; changing them invalidates the comparison and every published figure derived from it." Detect-only leaves every published number byte-identical unless drift is real. Test tolerance is planner discretion.
- **D-09:** Note the deliberate asymmetry between D-06 and D-08: a `denom <= 0` in the OPR solver means the **shared model state** is unrecoverable, so the run aborts; a single bad `pRedWin` is a **per-prediction** anomaly, so it quarantines. Different failure classes, different responses — this is intentional, not an inconsistency to be normalized away.
- **D-10:** When every candidate value for one parameter is rejected by `isValidParamSet`, `runScreenStage` **aborts with a named error** identifying the parameter and pointing at `SIGMA1_SEARCH_SPACE`'s bound for it. Rejected: skipping the parameter and marking it unscreenable — a fully-rejected grid means the search space is misconfigured, and continuing would publish a screen artifact with a silent hole in it.

### Version pipeline (03-REVIEW WR-01, WR-03)

- **D-11:** `isValidParamSet` becomes **unskippable by construction** rather than being called at each boundary. A `Sigma1Params` that violates the cross-parameter invariants must not be constructible in the first place. Rejected: patching the three known-missing call sites (`planJointCandidates`'s singleton branch, `promote.ts`'s `main`, `cli.ts`'s `loadSearchWinnerSigma1`), because that leaves enforcement a convention a fourth boundary can forget — which is exactly how this gap arose. This mirrors the project's own reasoning for the leak-proof Proxy: a runtime fact, not a convention a cast can bypass. — **Reversibility:** costly — touches every construction site of `Sigma1Params` across `tune.ts`, `promote.ts`, `cli.ts`, and `params.ts`.
- **D-12:** The promoted-version path **stays explicitly pinned** to a named file, and `applyPromotedOverrides` **logs a loud warning** when `data/algorithm-versions/` holds a `sigma1@*.json` with a newer `provenance.promotedAt` than the pinned one. Rejected: globbing for the newest version automatically — Phase 3's D-13 makes version identity load-bearing for Phase 4 artifacts, the Phase 5 dropdown, and the Phase 8 Compare page, and an explicit pin is a reproducibility feature, not an oversight. Also rejected: hard-failing on a newer file, since deliberately scoring an older version (e.g. to compare it against a new one) is legitimate work.
- **D-13:** **Standing rule: a committed digest is never hand-edited.** If any change in this phase legitimately alters a prediction stream, the result is a **new promoted version with its own digest and provenance**; the prior version keeps its bitwise-reproducibility claim intact. This is what Phase 3's D-13/D-14 already imply, and `digest.test.ts`'s own header explicitly warns against "relaxing, or hand-editing a committed digest to make a failing [test pass]". Current risk is low — the two structural fixes measure zero impact and detect-only OPR changes no numbers — but the rule stands regardless.

### Doc drift

- **D-14:** The four stale artifacts are corrected: `01-REVIEW.md` frontmatter (`critical: 1` / `status: issues_found` → resolved, with a resolution block crediting quick task `260819-2x6`), `01-VERIFICATION.md`'s `human_verification[0].status: outstanding` (closed by `01-UAT.md` tests 30 and 31), `03-REVIEW.md` (add the missing resolution block), and `STATE.md`'s Blockers/Concerns claim that T-03-18b "remains formally open until `/gsd-secure-phase 3` is re-run" (it was re-run; `03-SECURITY.md` reads `status: verified` / `threats_open: 0`).
- **D-15:** Corrections **trust the 2026-08-19 audit's re-confirmation** rather than re-verifying each claim against the code first. This is a deliberate trade made acceptable by D-16 — the linter becomes the ongoing guard, so a one-time transcription step is not the only thing standing between the docs and reality.
- **D-16:** Add a **narrow linter** covering exactly one mechanical invariant: a `*-REVIEW.md` whose frontmatter `findings` counts disagree with how many findings in the body actually carry a `#### Resolution` subsection. Scoped deliberately tight. **Rejected: a full cross-artifact consistency checker** (REVIEW↔resolutions, VERIFICATION↔UAT, STATE blockers↔SECURITY) — it would have caught all four cases, but it means parsing prose in STATE.md and is a meaningful tooling build that risks becoming its own phase. **Rejected: relying on existing GSD tooling** — `gsd-tools audit-open` was run during this discussion and reports "All artifact types clear. Safe to proceed." while two REVIEW.md files carry `status: issues_found`, so it does not detect this class of drift.

- The drift-test tolerance and update count in D-08's season-scale property test.
- How D-11's construction-time validation is structured (branded type, factory function, Zod `.superRefine`, or constructor) — the requirement is that an invalid `Sigma1Params` cannot exist, not any particular mechanism.
- Wave/plan decomposition across the nine fixes plus the doc work.
- Whether D-16's linter runs as a Vitest test or a standalone script.
- WR-02 (`pnpm-workspace.yaml` glob) and WR-03 (atomic `wx` lock create) were not separately discussed — both have unambiguous fixes stated in `01-REVIEW.md` and no competing policy choice. Implement as the review prescribes.

## Existing Code Insights

### Reusable Assets
- `packages/harness/score.ts` — existing exclusion accounting; the established home for "a match was not scored, and here is why". D-06's quarantine count should follow its convention of returning qualifying counts next to the headline figure.
- `packages/core/algorithms/breakdown/constants.ts` — dependency-free leaf module where `assertFiniteComponents` was hoisted during Phase 2's WR-01 fix so `epa.ts` and `sigma1/index.ts` share one implementation. The same hoisting pattern applies to D-05's validation helper.
- `packages/harness/fixtures/extract-digest-slice.ts` + `packages/harness/fixtures/digest-slice.json` — committed fixture fallback that lets `digest.test.ts` run without the gitignored corpus. The model for D-04's corpus-present-guarded tests.
- `packages/corpus/schema.sql` — already carries explicit quirk flags (`replayed`, `red_surrogates`/`blue_surrogates`, `red_dqs`/`blue_dqs`, `has_score_breakdown`). D-03's `winner_imputed` slots in beside them.

### Established Patterns
- **Explicit-flag discipline (DATA-02):** quirks are stored as columns on the match row, not inferred at read time or counted in a side channel.
- **Structural enforcement over convention:** `toLeakProofUpcoming`'s Proxy was chosen so leakage is "a runtime fact, not a type-level convention that a cast could bypass" — the direct precedent for D-11.
- **Resolution blocks append, never rewrite:** `02-REVIEW.md` appends a `#### Resolution` subsection per finding and leaves the original finding text unchanged. D-14 must follow this.
- **Corpus is disposable:** schema changes are handled by deleting and rebuilding `data/corpus.sqlite`, not by migration. Relevant to D-03.
