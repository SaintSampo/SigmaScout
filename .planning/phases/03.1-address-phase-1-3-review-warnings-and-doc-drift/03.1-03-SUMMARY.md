# Phase 03.1 Plan 03: OPR incremental-solve numerical breakdown guard and season-scale drift proof Summary

**Closed 01-REVIEW WR-01 by making `applyObservation` throw on a non-finite residual or non-positive `denom`, and adding a 5,000-synthetic-match property test measuring the incremental Sherman-Morrison/RLS solve's drift against a fresh batch solve at three checkpoints — maximum observed deviation 4.27e-12, six orders of magnitude inside the 1e-6 documented tolerance.**

## Accomplishments
- `applyObservation` in `packages/core/algorithms/opr.ts` now throws immediately after computing `residual` and `denom`, before the ratings-vector loop, when `residual` is non-finite or `denom <= 0` — the exact condition 01-REVIEW.md's own WR-01 fix prescription names.
- The thrown message names the module (`opr:`), the offending `allianceScore`, the computed `residual`, and `denom`, so a failure is attributable without re-running.
- The guard is provably detect-only: no resynchronization, no symmetrization, and `IncrementalInverse`/`rank1Update`/`solveRidgeOpr` are byte-for-byte unchanged (`grep -c "IncrementalInverse"` unchanged at 11; the class stays private).
- A new season-scale property test drives 5,000 deterministic synthetic matches (400-team pool, seeded PRNG reimplemented locally, no import from `packages/harness`) through `opr.update`, comparing against a fresh `solveRidgeOpr` batch solve at 1,000/3,000/5,000 matches. Every rating stayed finite at every checkpoint; measured maximum absolute deviation from the batch solve was 1.73e-12 (1,000), 4.27e-12 (3,000), and 4.02e-12 (5,000) — far inside the documented `1e-6 * max(1, |batchRating|)` relative tolerance.
- A determinism assertion (two runs of the generator with the same seed over a 200-match prefix) pins the generator's reproducibility, so a future failure in this test is a real signal, not flakiness.
- Full suite (`npx vitest run`) exits 0 at 654 passed / 1 skipped (the pre-existing, expected corpus-integrity skip), including `packages/harness/digest.test.ts` reproducing every committed digest bitwise — the direct evidence that no published OPR number moved.

## Decisions Made
- **Regression test placement:** drives the guard indirectly through `opr.update` (the shipped public surface), per the plan's recorded open-design-question resolution — `IncrementalInverse` and `applyObservation` stay module-private; exporting a private class purely to test it was rejected as widening the module's public API against its own encapsulation choice.
- **Team pool held at 400, not the review's 1,500-3,700 range:** the drift comparison calls the dense O(n^3) `solveRidgeOpr` three times per test run (once per checkpoint, over the full accumulated observation set each time); a full-season team pool would turn this into a multi-minute test instead of a fast CI gate. Match count (5,000) was held at the review's own low end instead, since match count — not team count — is the axis along which floating-point drift actually accumulates.
- **`denom <= 0` branch is defense in depth, not directly tested:** in exact arithmetic `denom` is `1 + a positive quadratic form`, which is provably `> 1` while the maintained inverse stays positive-definite. There is no reachable path through the public surface (`opr.update`) that forces a non-positive `denom` on well-formed input, so manufacturing a fake reachability path for it was explicitly rejected per the plan's own instruction. The season-scale property test's finiteness assertions are what would surface a real loss of positive-definiteness in practice; the residual branch (reachable via a non-finite alliance score) is the one proven red-then-green.
- **Per-test timeout raised to 30,000ms for the drift test** (Vitest's default is 5,000ms) — the test's own 30-second wall-clock escape-valve check inside the test body would otherwise never get the chance to run before Vitest's harness-level timeout fired first. This is a test-runner configuration detail, not a plan deviation: the escape valve's 30-second ceiling and the `it()` timeout argument are the same number by design.
