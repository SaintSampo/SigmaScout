<objective>
Turn the RP rules from plan 03-02 into an actual per-match prediction: a parallel
threshold-variable state that learns each team's contribution to whatever its season's bonuses
threshold on, and a correlated joint draw that produces a full discrete RP pmf for both
alliances.

Purpose: ALGO-08 requires ranking points predicted per match WITH VARIANCE. D-10 makes the
representation the full pmf (RP is a small integer, so the pmf is a handful of numbers and
Phase 8's rank simulation can draw from the exact distribution instead of rounding Gaussian
samples into impossible values). D-11 requires winning and clearing thresholds to be modelled
as correlated, because a dominant alliance both wins and clears its bonuses and independence
would systematically bias `P(maximum RP)`.

Output: `eventType` on `UpcomingMatch`; `rp/state.ts`; `rp/distribution.ts`; RP fields on
`Prediction`; predictions sidecar schema v2; artifact schema v3 carrying D-13's version
identity.

**Reversibility note (D-09, rated `costly` in CONTEXT.md):** this defines a second state vector
that must be initialized, carried, versioned, tuned, and rendered. It is kept deliberately
separate from the score-component vector so that `reconciliation.test.ts`'s invariant and
`docs/models/sigma1-identifiability.md`'s conclusions are untouched; folding it into the score
vector later would re-open the identifiability argument. Flagged, not gated — the decision is
already locked.
</objective>

**`packages/core/algorithms/sigma1/rp/state.ts` (new) — D-09's parallel state.**

Per team, alongside (never inside) the existing score-component structures:
- `rpBeliefs: Record<string, TeamComponentBelief>` — one Gaussian per threshold variable named
  by the season's rule module, updated by the SAME `updateAllianceSum` alliance-sum Kalman step
  the score components use. Reuse `kalman.ts` unchanged; do not write a second Kalman.
- `rpCovariance: number[][]` — T×T EWMA covariance across the season's threshold variables,
  folded with the existing `ewmaCovariance` using `params.covEwmaAlpha` / `params.covShrinkage`.
- `rpCrossCovariance: number[][]` — C×T, the EWMA of the outer product of the score-component
  residual vector against the threshold-variable residual vector. THIS is what makes D-11's
  correlation fall out of the data instead of being asserted: it is the only place the model
  learns that a team which over-performs on score also over-performs on the counts its bonuses
  threshold on.

Keep all three OUT of the existing `Sigma1TeamState.covariance`. `teamTotalVariance` must keep
summing the score-component matrix alone, so the published team-page `±` and the identifiability
write-up's conclusions are numerically untouched — that is the whole point of D-09's separation
and it must be provable, not asserted.

Exports:
- `emptyRpTeamState(variableCount, componentCount)`
- `foldRpObservation(...)` — the alliance-sum Kalman update over threshold variables plus the
  two covariance folds, mirroring `applyAllianceUpdate`'s structure including its gain-weighted
  per-team residual attribution. Call `assertFiniteThresholdVariables` before folding.
- `predictAllianceRpMoments(state, teams, ruleModule)` — returns, for one alliance, the mean
  vector over threshold variables, the T×T variance block (summed across teammates under the
  independent-teams assumption), the alliance score mean and variance (taken from the values
  `predict` already computes, passed in — never recomputed here), and the length-T cross-
  covariance vector between the alliance's total score and each threshold variable, obtained by
  summing each teammate's `rpCrossCovariance` column sums.

Season handling: threshold variables are season-specific (2022's cargo count has no 2023
analog), so RP state does NOT carry across a season boundary. `carrySeason` resets it to
`emptyRpTeamState` for the incoming season's variable list, and the module header records the
reason: carrying a cargo count into a charge-station point total is meaningless, and a
league-prior cold start is the honest alternative. Cold-start seeding mirrors the score path:
seed from the league's running per-variable `ExpandingStats` mean once any team has been
observed, and from a documented flat share before that. Add the RP-side league aggregates to
`Sigma1League` as a third record.

Missing-breakdown handling: when `parseBreakdown` returns null for a match (the
`has_score_breakdown = 0` population, measured at 0.00% for four seasons and 0.12% for 2024),
the RP state fold is SKIPPED entirely for that match — never a coerced zero, never an imputed
split. The score-component fallback path stays exactly as it is. Record the skip in a counter
on the state so it is observable.

**`packages/core/algorithms/sigma1/rp/distribution.ts` (new) — D-10/D-11/D-16.**

`rpPmfForMatch(input): { redPmf: number[]; bluePmf: number[] }` where `input` carries both
alliances' moments from `predictAllianceRpMoments`, the season's `RpRuleModule`, the match's
`eventType`, `matchKey`, `compLevel`, and `params`.

1. **Non-qualification short-circuit.** If `compLevel !== "qm"`, return `[1]` for both
   alliances — the degenerate `P(RP=0)=1` pmf, grounded in plan 03-02's full-population
   elimination invariant. No draws, no cost.
2. **Zero draws short-circuit.** If `params.rpMonteCarloDraws === 0`, return `[]` for both
   alliances and emit no RP fields at all downstream. This is what lets the hyperparameter
   search in plan 03-05 run at full speed: the search objective is Brier on win probability,
   which does not read the pmf, so disabling draws cannot bias the search. That independence
   must be a TEST, not a claim.
3. **Joint draw.** Assemble the joint mean vector and covariance over
   `[redScore, blueScore, redVar_1..T, blueVar_1..T]`. Within an alliance, the score/threshold
   cross-covariance comes from `predictAllianceRpMoments`; across alliances the blocks are zero
   under the independent-teams assumption the whole model already rests on (say so in the
   header rather than leaving a reader to infer it from a zero block). Decompose with
   `ml-matrix`'s `CholeskyDecomposition`, reading `lowerTriangularMatrix` — the same
   wrap-an-`ml-matrix`-call style `identifiability.ts` uses for its SVD. If the matrix is not
   positive definite (a legitimate early-season possibility over a rank-deficient residual
   history), add a small documented ridge to the diagonal and retry once, then throw with the
   match key if it still fails — never silently fall back to an independent draw, which would
   quietly discard exactly the correlation D-11 exists to capture.
4. **Seeded normals.** `mulberry32` copied verbatim from `identifiability.ts` (cite the source),
   plus a standard Box-Muller pair transform with the formula cited in a comment, matching
   `linkFunctions.ts`'s Abramowitz-Stegun citation discipline. The seed is per match:
   `params.rpMonteCarloSeed` combined with a 32-bit FNV-1a hash of `matchKey` (implement and
   cite FNV-1a; it is a few lines and well-known). Per-match seeding is load-bearing, not
   hygiene — seeding from a running stream position would make a match's pmf depend on how many
   matches preceded it, and the bounded-slice digest in plan 03-01 would then never match a
   full-corpus run.
5. **Tally.** For each draw, apply the season rule module's threshold predicates at the match's
   tier to the drawn threshold variables, decide win/tie/loss from the drawn scores, sum
   `winRp`/`tieRp` plus cleared bonuses, and increment that RP value's bucket. Divide by the
   draw count. The result is a `maxRp + 1` length array indexed by RP value 0..maxRp, in that
   order, summing to 1.
6. **Degenerate alliances.** An alliance with no rating-eligible teams (every slot a surrogate)
   has no moments to draw from: return the pmf implied by win/tie/loss alone with every bonus
   false, rather than an empty array or a NaN-bearing one.

Also export `pmfMean(pmf)` and `pmfStandardDeviation(pmf)`. D-10 stores the pmf ONLY — mean and
SD are derived at read time, never stored alongside, so there is exactly one representation of
one fact.
