<objective>
The offline publisher: the four state facts, the baked pmfs for unstarted events, and the award
tables, all reaching the wire through the contract 10-03 committed and the machinery 10-04 built.

Today `scripts/publishDistricts.ts` reads the corpus, composes earned district points and lock
verdicts, and uploads. It carries no per-event state, no prediction, no award table, no byte gate,
its own private copy of the verdict pass and its own private copy of the TBA `event_points` schema,
and it counts object size in UTF-16 code units. This plan closes all of that at once and adds the
two things SC-5 and SC-6 need from the pipeline:

1. **The four state facts** (qualification matches played and total, alliances picked, playoffs
   done, awards posted) per team per event, derived from the corpus at the same instant the rest of
   the artifact is derived, so a grey cell is a published fact (CONTEXT "The four state facts,
   sourced"; the offline half of the same field 10-05's Worker writes live).
2. **The baked per-team, per-event pmfs for an event nobody has played**, produced by 10-04's
   `simulateDistrictEvent` over priced synthetic qualification schedules from walk-forward SPR
   state — the pipeline tier RESEARCH's Architectural Responsibility Map assigns them to, mirroring
   `preSchedule.ts`'s existing offline bake exactly (SC-5: "zero simulation compute for finished and
   unstarted events").
3. **The season award base-rate table and each team's award profile**, published from 10-02's
   measured module so the browser can price an award cell with no corpus (SC-6's award half; the
   numbers themselves were measured and pinned in 10-02, and this plan does not restate one).
4. **A measured byte gate and a local dry-run output mode**, because districts have had no
   payload-budget coverage since the page shipped (RESEARCH Pitfall 6) and because executors have
   no network, so the only honest verification available here is composing every object, writing it
   to a gitignored folder, and measuring it.

Purpose: 10-07 cannot paint an unstarted event, a grey cell or an award cell without these fields,
and 10-09's republish is what puts them in R2. Nothing here uploads, deploys, pushes or fetches.

Output: the artifacts in `must_haves.artifacts`, plus a real measured run recorded in
`docs/publish-budget.md` and in this plan's SUMMARY.

**Run this plan in the MAIN checkout, never a git worktree.** Every verification here reads
`data/corpus.sqlite`, which is gitignored and does not travel into a worktree (project memory
`project_worktree_gitignored_state`), and `better-sqlite3`'s node-gyp build fails in a fresh
worktree on this machine (`project_pnpm_install_exit1_worktrees`). A skipping corpus test proves
nothing, and this plan's whole verification story is a real run over real data.
</objective>
