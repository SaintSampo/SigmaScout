<objective>
Extend the rankings ingest to stop discarding what it already fetches (D-18.6): widen `tbaEventRankingSchema` consumption and `ingestSeasonRankingsOnly` to persist TBA's authoritative `record {wins,losses,ties}` and the RP value, guarded by a loud `sort_order_info[0].name === "Ranking Score"` assertion (verified stable across all 5 seasons and 8 event types) rather than a silent hardcoded index-0 read — so a future season's TBA drift fails visibly instead of publishing the wrong column as "RP".

Purpose: D-07 orders the Insights tab by TBA's official rank and shows record and RPs beside the model's own metrics. Rank is already stored (06.1-01/06.1-04, 47,695 rows across 1,322 of 1,581 events). Record and ranking score are already *fetched* on every one of those 1,581 requests and then thrown away — `packages/ingest/schemas.ts` models both and its own doc comment states that only `rank`/`team_key` are ever read. This plan closes that gap at the only layer where TBA's authority over the value is still intact.

The guard is the load-bearing part, not the plumbing. `sort_orders` is a positional array whose vocabulary genuinely changes by season — 2022 carries `Avg Hangar`, 2024 carries `Avg Coop`, 2026 carries `Avg Tower` — and `schemas.ts:131` already models it `.nullable()` for exactly that reason. RESEARCH.md Question 1 was run to settle whether position 0 is nonetheless stable, and it is: `sort_order_info[0].name` read as the same string in all 40 live-sampled events across 2022–2026 and all 8 TBA event types. That finding licenses reading position 0 — it does not license reading it silently. A hardcoded index with no assertion would, on the season TBA reorders, publish some other statistic under the label "RP" and look entirely normal doing it.

Output: `normalizeEventRankings` widened to carry TBA's record and ranking score with a named, throwing drift guard; an offline case set pinning the null, empty, drifted and equal-value shapes; a bounded live-TBA integration test proving the guard's premise against real 2022–2026 responses; and `ingestSeasonRankingsOnly` writing all four values into the columns 07-02 created.

**Execution constraint:** this plan must run in the **main working tree, not a git worktree.** `data/corpus.sqlite` is gitignored, is not copied into a worktree, and Task 3's forced ingest applied inside one does not merge back. Tasks 2 and 3 cannot execute at all without the real corpus present.
