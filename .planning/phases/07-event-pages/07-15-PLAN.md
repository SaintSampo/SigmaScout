<planner_decisions>

- **PD-01 — the header reads the artifact it was handed, and the artifact only.** Its prop contract
  is `{ artifact }` — a single `EventArtifact`, the inferred type of `EventArtifactSchema`, never a
  hand-shaped interface with the four identity fields copied onto it. This is what makes the E1
  `empty`-dismissal argument checkable: the header can only be constructed from something that
  already passed `.parse()`, so `.min(1)` has already run and "present but empty" is not reachable.
  A structurally-typed local interface would silently reopen it. The header does NOT take
  `algorithmId` or `season` — it renders no metric and no season-dependent column set, so the frozen
  three-prop tab contract 07-01 established deliberately does not apply to page chrome.
  — <reversibility rating="reversible">A component prop shape with no published contract behind it.</reversibility>

- **PD-02 — the nullish operator is correct at the client for exactly the reason it was wrong at the
  publisher, and that is stated rather than left to look like an inconsistency.** 07-08 PD-05 proved
  the publish-side `name` fallback must be a non-empty test: `EventMetaRow.name` is `string | null`
  and a corpus row holding `""` would sail through `??` into a `.min(1)` parse failure and abort a
  whole publish run. At the client the SAME operator is right, because the parse has already
  happened — `EventArtifactSchema` rejected `""` before the header existed, so the only value `??`
  can catch is `undefined`, which is precisely the case that needs catching. Writing a redundant
  non-empty test here would imply the schema guarantee is not trusted, and a later reader would
  reasonably conclude one of the two layers is wrong. Both are right; they guard different inputs.
  — <reversibility rating="reversible">A one-operator choice, argued rather than assumed.</reversibility>

- **PD-03 — `location` is genuinely single-sourced through a pipeline export; `week` is copied under
  this repo's established copy-with-attribution convention. The asymmetry is deliberate.**
  `composeEventLocation` exists in `pageArtifacts.ts` (07-07 PD-01) specifically so one composition
  rule serves both surfaces, and `EventsList.tsx` delegating to it is the mechanism that makes
  UI-SPEC's "reused, not reinvented" true rather than hoped for. There is no pipeline-side week
  composer and there should not be: `composeEventLocation`'s own doc comment records that the
  em-dash is deliberately NOT its output because that is a rendering decision — and `Offseason`,
  `Week 3` and `—` are display copy, which does not belong in a browser-safe schema leaf. The two
  surfaces also present the same rule differently on purpose: the Events list shows a
  `Badge variant="secondary"` in a dense sortable column, the header shows plain muted text in one
  continuous metadata sentence, where a badge mid-line would read as an unexplained chip. So the
  RULE (`week === null` ⇒ offseason) is copied into `EventHeader.tsx` with a doc comment naming

## Flagged planner assumptions

1. **The rank header reads `Sigma1 Rank` for three waves, and that is the mechanism working.**
   Between this plan's commit and 07-18's D-04 relabel, `algorithmDisplayLabel("sigma1")` returns the
   pre-rename name, so the Teams page's leading header reads that word followed by `Rank`. UI-SPEC's
   Copywriting Contract states the end state (`VPR Rank` / `EPA Rank` / `OPR Rank`), which is reached
   at 07-18 with no edit to `columns.tsx`. Recorded so a reader between waves does not file a correct
   intermediate state as a bug, and so nobody "fixes" it by hardcoding the post-rename label — which
   this plan's second prohibition forbids and which would read wrong for OPR and EPA forever.

2. **`location: null` is representable but has no live instance, so the em-dash branch is proven by
   fixture only.** Measured this session across all five published events artifacts (1,581 events):
   **zero** events carry a null `country` or a null `stateProv`, so `composeEventLocation` returning
   `null` — and therefore the header's location em-dash — is not reachable from today's corpus. The
   branch is still required (07-07 typed the field nullable and 07-08 publishes a real null when both
   source columns are null), and it is tested, but the test is the only evidence it will ever have
   until a real event lacks both. Recorded so a later reader does not mistake an untriggered branch
   for dead code and delete it.

3. **07-10's subset event key is read from `07-10-SUMMARY.md` at execution time, not pinned here.**
   Task 1's precondition names the check rather than the key, because 07-10 owns which events it
   republished. Any ordinary regional from that list satisfies it. If no subset artifact carries
   `name`, the precondition halts — which is the correct outcome, since this task's whole claim is
   that a real published identity reaches render.

4. **The `week` rule is copied rather than imported, and the copy is a decision with a cost.**
   PD-03 explains why (no pipeline-side week composer should exist, and the two surfaces present the
   rule differently). The cost is that a future change to the offseason rule must land in two files.
   The mitigation is the same one this repo already relies on for `formatRecord`, `formatWinRate` and
   `metricLabel` — an attribution doc comment naming the source — plus a test asserting both surfaces
   branch on `week === null` and nothing else. Recorded rather than hidden, because "copied with a
   comment" is a weaker guarantee than `composeEventLocation`'s genuine single-sourcing one segment
   over, and the asymmetry should be visible to whoever changes it next.

5. **Making the year dropdown's handler async is a real behavioural change on a globally mounted
   control, scoped to one route family.** On `/teams`, `/events`, `/compare` and `/team/{n}` the
   handler stays exactly as synchronous as it is today. Only on an event detail route does navigation
   land after an await, which on a cold cache is one artifact fetch and thereafter is a cache read.
   The alternative — narrowing the dropdown's options up front — was rejected in PD-07 as five
   render-time fetches on the page whose top constraint is load speed.
