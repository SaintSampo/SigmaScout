## Decisions this plan makes (Claude's Discretion, recorded not assumed)

1. **RP renders as a plain `numeric-cell` span, never through `MetricValue`.** UI-SPEC's Insights
   table leaves this to discretion ("tier-boxed like any other metric IF a percentile is ever
   published for it; otherwise bare"). Decided: bare, and structurally so rather than by omitting a
   prop. Three reasons point the same way. `MetricValue`'s own contract is the published `TeamMetric`
   shape — a modeled value with an optional model spread — and `rp` is a `z.number().optional()` scalar
   that is neither. `TeamMetricSchema.percentile`'s doc comment defines a percentile over "the full
   season team pool for this (algorithm, season) pair — never over a visible subset (e.g. ... an
   event's roster)", so the only percentile an event page could compute for RP is exactly the one that
   definition forbids. And 07-07 gave RP its own `ROUNDING_RULE.rankingPoints` key specifically
   because it is a different field class that happens to share `metric`'s decimal count — routing it
   through `MetricValue` would borrow the wrong rule's display contract to get the right number by
   luck. A bare span cannot accidentally grow a tier box in a later phase; a `MetricValue` call with
   no `tier` prop can, by one line.
   — <reversibility rating="reversible">A cell renderer. If the pipeline ever publishes an RP
   percentile, swapping to `MetricValue` is a one-cell change with no published contract behind it.</reversibility>

2. **In fallback mode the Rank column header names the algorithm; the plain `Rank` header is used
   only when the ordinals are TBA's.** CONTEXT.md's Claude's Discretion covers "the fallback
   treatment for teams or events with missing data on any tab" and "where D-08's notice sits and how
   it is worded"; this is that discretion applied to the column itself rather than to the banner
   alone. The alternative considered and rejected was rendering a column of em-dashes on all 259
   no-ranking events, which spends the leftmost pinned column on nothing and leaves row order as the
   only signal — the "silently" D-08 explicitly rejects. Rendering a model-derived ordinal under a
   bare `Rank` header was rejected outright as the false attribution 07-07's own prohibition names.
   The header text is built from `algorithmDisplayLabel(algorithmId)` (07-01's export), which is the
   same accessor 07-18's D-04 relabel changes in one place, so this header follows the rename for
   free. This is deliberately the SAME convention D-20 applies to the Teams page, and deliberately
   NOT the D-20 edit itself — `teams-table/columns.tsx` is untouched here and stays 07-15's.
   — <reversibility rating="reversible">Header text derived from an existing accessor.</reversibility>

3. **The fallback predicate is "no team in `artifact.teams` carries a `rank`", not "some team is
   missing one".** A team that registered and withdrew has no `event_rankings` row inside an
   otherwise fully-ranked event; treating that as an event-wide fallback would relabel a whole
   correct table because of one row. So a partially-ranked event stays in official mode, and the
   unranked team renders an em-dash Rank cell and sorts last — the same "missing sorts last" rule
   `rowModel.ts` already applies to a missing metric key.
   — <reversibility rating="reversible">One predicate in one pure function, covered by its own test case.</reversibility>

4. **The route's page-state decision tree is extracted into ONE shared helper rather than copied
   into the Insights panel.** 07-01 built that tree inline inside the `breakdown` `TabsContent`.
   Three more tabs (07-12, 07-13, 07-14) follow this one into the same file; four copies of an
   invalid-key / 404 / error / pending branch order is four chances for E3–E7's "inherits the
   page-level error" rows to become false for one tab and true for the others. Extracted now, at the
   first plan that needs it twice, rather than at the fourth.
   — <reversibility rating="reversible">A local refactor inside one route file, pinned by the route
   test asserting Breakdown's four states are unchanged.</reversibility>

5. **The banner is static page content, not a live region.** No `role="alert"`, no `role="status"`,
   no dismiss control. UI-SPEC is explicit that it "describes the table's current state, not a
   one-time event"; a live-region role would make an assistive-technology user hear it announced on
   every re-render of a table it is permanently attached to. The `Info` icon is `aria-hidden` and the
   sentence carries the whole meaning.
   — <reversibility rating="reversible">Attributes on one element.</reversibility>
