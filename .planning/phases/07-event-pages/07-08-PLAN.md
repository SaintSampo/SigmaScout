<objective>
Populate the new fields in `buildEventArtifact` (`packages/harness/publish.ts`): thread per-alliance
own predicted-score variance from `prediction` onto played and upcoming match rows, event identity
(`name`/`startDate`/`location`/`week`) from the corpus `events` row, `alliances[]` from
`event_alliances`, and `rank`/`record`/`rp` from the extended `event_rankings` onto each
`EventTeamSchema` entry, and `sortTime` onto played and upcoming match rows from the
`selectScheduledMatchTimes` map this run already reads. Keeps `EventArtifactSchema.parse(candidate)`
as the final line so an invalid artifact can never reach `putObject`. Also enforces the folded `republish-playoff-bonus-arrays`
criterion: playoff rows carry neither `actualRedBonusRp`/`actualBlueBonusRp` nor
`redBonusRp`/`blueBonusRp` as properties (`not.toHaveProperty`).

Purpose: 07-07 declared nine optional fields; today every one of them would be `undefined` in every
artifact this publisher writes, because nothing fills them. This plan is the fill. It is what turns
07-07's contract from a declaration into published data, and it is the hard prerequisite for 07-10's
subset publish — which in turn is what 07-11 through 07-15 build and verify against. Without it the
Insights, Quals, Elims and Alliances tabs have no data to read no matter how well they are written.

The `sortTime` addition is folded in from a finding routed by 07-12 (Quals tab): the field is
published on `TeamSeasonMatchSchema` but not on either event match schema, and no match row of the
live `2024casf` artifact carries it — so `07-UI-SPEC.md`'s scheduled-time string in an upcoming row's
Actual column would ship as an em-dash. This plan was named owner because it already consults the map
holding that value in the same run; the data is in hand and simply is not threaded onto the row.

Output: four new optional parameters on `BuildEventArtifactParams`, ten filled fields, both call
sites extended, and a test file that asserts each field on the PARSED artifact and on real published
JSON bytes through the seeded-corpus `publishSeasons` harness. **Nothing is published by this plan** —
no R2 object is written or deleted and no publish run is authorized.

<planner_decisions>

- **PD-01 — `rank`/`record`/`rp` are merged inside `buildEventArtifact` from a new `rankings`
  parameter, NOT threaded through `buildEventTeamsStanding`.** Two independent reasons point the same
  way. First, 07-09 (the very next wave) restructures `buildEventTeamsStanding`'s metrics source and
  both of its call sites; keeping this plan's diff out of that one function is what lets the two plans
  edit adjacent code without editing the same body, which is exactly what the shared-file constraint
  asks for. Second, and more durably: that function's single responsibility is the MODEL's per-team
  output, while `rank`/`record`/`rp` carry TBA's authority in their names. Assembling both in one
  expression would put the model's numbers and the fields that assert official provenance in the same
  scope at the same moment — the precise spoofing surface `<threat_model>` T-07-08-01 names, and the
  one 07-07's second prohibition says must be closed at the published boundary specifically.
  **Reversibility: reversible** (a parameter shape; no published byte depends on where the merge
  happens).

- **PD-02 — each new field copies the SPELLING its own precedent already uses, even though that means
  two conventions inside one function.** `redScoreVarianceOwn`/`blueScoreVarianceOwn` are assigned
  directly with a ternary falling to `undefined`, because `buildTeamSeasonArtifact` spells those exact
  two fields that way. `rank`/`record`/`rp` use a conditional spread, because `rank`/`totalTeams` are
  spelled that way and the file's own comment calls conditional spread their convention. Copying each
  field's own precedent beats imposing one house style: one field spelled two ways across two
  artifacts is the drift that actually hurts a reader; two field families each matching their own
  precedent is not. **Consequence for tests, stated here so it is not discovered as a surprise:** an
  in-memory event match row for OPR HAS the variance keys with value `undefined`, so absence must be
  asserted with `toBeUndefined()` in memory and with `not.toHaveProperty` only after a
  `JSON.parse(JSON.stringify(...))` round-trip — which is what actually reaches R2. A team row with no
  ranking has no key at all in memory, so `not.toHaveProperty` applies to it directly.
  **Reversibility: reversible.**

- **PD-03 — the `alliances` key is present exactly when the caller consulted the corpus, and `[]`
  means exactly zero rows.** The two tempting shortcuts fail in opposite directions. Emitting the key
  only when the array is non-empty collapses "this event held no alliance selection" into "I have no
  information" — and 07-02 measured BOTH absent cases live (a null TBA body at `2022ispr`, an empty
  array at `2025bc` and `2026wvrox`, the latter two being events that ran qualification matches and
  published rankings but never held a selection). Emitting `[]` unconditionally is the mirror-image
  fault: it fabricates a "no selection was held" claim out of a caller that never asked the corpus.
  So the parameter is optional, the key is emitted iff the parameter was supplied, and both real call
  sites supply it unconditionally — which is what makes an absent key mean only "this artifact
  predates the field" after 07-17. This is 07-07's own key link ("the publisher must never rely on
  that permission") discharged, and it is this plan's first prohibition. **Reversibility: costly**
  (a published field's absence semantics; changing them later needs a republish).

- **PD-04 — identity arrives as ONE `eventMeta` parameter mirroring `EventMetaRow` field-for-field,
  and `composeEventLocation` is called exactly once, inside `buildEventArtifact`.** The rejected
  alternative was composing the location at each call site and passing a finished string; that puts
  the composition in two places and lets the two call sites disagree about one event, which is the
  precise failure 07-07 PD-01 exported the composer to prevent. Passing the raw nullable
  `country`/`stateProv` through and composing once inside the pure function makes the composition
  unit-testable through `buildEventArtifact` itself, keeps both call sites as dumb pass-throughs of a
  corpus row, and means the single-sourcing argument actually holds rather than being hoped for.
  **Reversibility: reversible.**
