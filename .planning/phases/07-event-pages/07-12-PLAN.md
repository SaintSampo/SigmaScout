## Decisions this plan makes (Claude's Discretion, recorded not assumed)

1. **The merge produces a NORMALIZED row type, not a union of the two schema types.**
   `EventMatchSchema` requires `actualWinner`/`actualRedScore`/`actualBlueScore`; `EventUpcomingMatchSchema`
   has none of them. A union would force every consumer — this plan's table, 07-13's Elims, any
   future one — to re-derive "is this played?" from field presence, which is three independent
   presence checks that can each be got subtly wrong. `mergeEventMatches` instead emits one
   `EventMatchRow` carrying an explicit `played` boolean set from WHICH ARRAY the row came from,
   which is the fact that is actually known, plus optional actuals. 07-13 renders the identical type.
   — <reversibility rating="costly">Two later plans are written against this type's field names. Changing it after 07-13 and 07-14 exist means editing three consumers and re-reviewing two plans; changing it before costs one file.</reversibility>

2. **The comp-level filter is a predicate parameter, with two named predicates exported, rather than
   a `compLevel` list argument.** `isQualCompLevel` is membership of `qm`; `isElimCompLevel` is
   membership of the closed set `ef`/`qf`/`sf`/`f` — stated as an explicit set rather than as "not
   `qm`", so that if a future season adds a competition level to the published enum it does not
   silently become an elimination match on 07-13's tab. 07-13 passes the second predicate and writes
   no filter of its own.
   — <reversibility rating="reversible">A parameter shape; both call sites are in this repo.</reversibility>

3. **The plot width is promoted into `matchAxis.ts` rather than duplicated or imported from a
   component.** The alternative — importing the value from `MatchTable.tsx` into a pure lib module —
   inverts the dependency direction (a lib importing a component) for a number that is pure
   geometry. Promoting it keeps `matchAxis.ts` as the one home for plot geometry, which is what
   `chart-craft.md`'s coupled-geometry rule is actually asking for, and reduces `MatchTable.tsx`'s
   change to deleting a line and widening an existing import.
   — <reversibility rating="reversible">Two lines in one shipped file, provably behaviour-preserving because that file's own tests are untouched and stay green.</reversibility>

4. **The padding-and-floor policy is extracted to a shared helper rather than reimplemented for the
   event domain.** `matchAxis.ts` holds three module-private constants (a 5% proportional pad, a
   minimum absolute pad, and a zero floor with a documented reason — an FRC alliance score cannot be
   negative, so a tick reading below zero labels a region no mark can occupy). Copying those three
   values into a second module is precisely the drift `chart-craft.md` names. What genuinely differs
   between the two axis functions is only how extents are gathered from differently-shaped rows.
   — <reversibility rating="reversible">A refactor inside one module, proven behaviour-preserving by the pre-existing unmodified test file.</reversibility>

5. **An unplayed event row's Actual column renders an em-dash, not a scheduled time.** The team
   page's match table renders `Sat 10:32 AM` from `TeamSeasonMatchSchema.sortTime`; the event
   artifact publishes no `sortTime` on either match schema and 07-07 did not add one. The shipped
   `MatchTable` already has exactly this branch for the same reason (a row with no `sortTime` renders
   an em-dash), so this is the established treatment rather than a new one. It IS a deviation from
   07-UI-SPEC.md's Quals-tab paragraph, which names the scheduled-time string — surfaced as a flagged
   planner assumption below with a recommended owner rather than silently absorbed.
   — <reversibility rating="reversible">If a later plan publishes the field, the column gains a branch; nothing here has to be undone.</reversibility>

6. **`QualsTabProps` declares the full frozen `{ artifact, algorithmId, season }` contract even
   though this tab reads only two of the three.** 07-01 Task 2 froze that shape for all four
   expansion tabs; declaring a narrower one here would make the route's four `TabsContent` call sites
   structurally different from each other for no reason. The component destructures only what it uses.
   — <reversibility rating="reversible">A props interface.</reversibility>
