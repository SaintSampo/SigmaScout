## Decisions this plan makes (Claude's Discretion, recorded not assumed)

1. **A new `phone-390` Playwright project rather than reusing `iphone-17` or `pixel-10`.** Neither
   existing project is 390px wide — the descriptors are 402x681 and 360x732 — and 390 is the width
   UI-SPEC, `no-page-pan.spec.ts`'s header, Phase 5 D-04 and Phase 6 D-10 all name specifically. The
   new project pins `viewport: { width: 390, height: 844 }` over the `iPhone 17` descriptor while
   keeping its `hasTouch`/`isMobile` flags, and pins `browserName: "chromium"` for the same reason
   `iphone-17` already does: `context.newCDPSession()` exists only for Chromium, and WebKit's public
   surface here is `page.touchscreen.tap()` alone, which cannot express a drag. The scroll spec ALSO
   runs on `pixel-10` at 360px, so the evidence spans two widths and the narrower one is the more
   adversarial.
2. **`touchDrag` is extracted rather than duplicated.** A pure move to `apps/web/e2e/support/`, with
   `touch-scroll.spec.ts` re-pointed at the import and re-run green to prove the move was pure.
   The file lives under `support/` and carries no `.spec.` segment, so it matches no project's
   `testMatch` and is never collected as a test.
3. **The sibling proof is an ancestor walk, not only `.contains()`.** `.contains()` in both directions
   rules out one region containing the other, which is what the component tests in 07-12/07-13/07-15
   already assert. It does NOT rule out a third scroller between them — a wrapper that quietly grew an
   `overflow-x-auto` would still pass both `.contains()` checks while re-creating exactly the nesting
   Open Question 5 resolved against. The runtime walk closes that.
4. **Row counts are asserted as exact equalities, not lower bounds.** `>= 60` would pass on a 15-row
