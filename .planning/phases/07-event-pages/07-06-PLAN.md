  published `±` becomes partly a function of the adaptation knob. D-01 is a locked, one-way user

- **PD-04 — `minConsistencyVariance`'s floor stays exactly where it is, applied to R only, with P
  added on top.** D-03's instruction is that R keeps being computed; the floor is part of how R is
  computed today (`consistency.ts` documents it as a floor on the shrunk consistency VARIANCE, and
  `shrinkConsistency` applies it internally for the per-component case). Removing it would be a
  second, unrequested semantic change riding the same commit. Consequence, stated so it is not
  mistaken for a bug: where the floor binds — a cold-start team whose covariance matrix is still
  all zeros — the published spread is slightly LARGER than the alliance identity would imply, never
  smaller. That direction is correct for an honest-uncertainty product and is what `minConsistencyVariance`'s
  name already promises. Task 1's identity case therefore asserts non-vacuously that the floor does
  not bind for its fixture teams, and Task 1 adds a separate case pinning the floor-binding
  direction. **Reversibility: reversible** (the clamp is one `Math.max` call).

- **PD-06 — The per-component P term uses `belief?.variance ?? 0`, matching what the match path

  per-component site makes the publish path agree with the match path exactly, which is what keeps
  the additivity identity exact rather than approximate. A component with no belief degrades to
  today's `√R` behaviour, which is the correct and already-shipped treatment for that case.
  **Reversibility: reversible.**

- **PD-07 — The phase-group P term is accumulated inside the EXISTING group loop, not through the

  exactly the same index set or the two terms describe different component sets. Accumulating
  `groupPosterior` in the same loop iteration that pushes `index` and adds to `groupValue`

  helper cannot see `componentOrder`. This mirrors the relationship `covariance.ts` already
  documents between `teamTotalVariance` and `subsetVariance`. **Reversibility: reversible.**

consistency quadratic form — the same two terms `redScoreVarianceOwn` sums across an alliance —
by extracting the posterior sum once and calling it from both paths.

knows how a team's P is summed, and both the match path and the publish path read it — that is what
makes the additivity identity hold by construction rather than by two implementations agreeing by
