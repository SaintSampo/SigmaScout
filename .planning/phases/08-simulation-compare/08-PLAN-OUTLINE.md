## Notes

### Why the Compare page is the tracer, and the publisher change is not

The phase contains two nearly-disjoint stacks. The **Simulation stack** runs pipeline → R2 → route → tab component → Web Worker → pure core; the **Compare stack** runs an already-published artifact → route → components. A tracer is supposed to be the thinnest path that touches every layer *and is verified before anything expands on it* — and the Simulation stack cannot be wired end-to-end on the first commit, because `08-UI-SPEC.md`'s Data Dependencies gate orders D-03's publisher work strictly before any Worker or tab component, and that publisher work is only real once a 23–25 minute republish has actually shipped it.

Compare can. `v1/compare/{year}.json` is published and live for all five seasons today, so 08-01 proves routing, the `artifactUrl()` fetch discipline, TanStack Query wiring, artifact-shaped consumption, wide-table rendering **and** the phase's own SC-4 parity proof against real production bytes, on commit one — the same criterion Phase 7 used to pick Breakdown as its tracer ("the only tab whose complete contract renders from fields the artifact publishes today"). After 08-01, a real user can load `/compare` and read winner accuracy and Brier for every algorithm for every year: SC-3 satisfied, SC-4 provable, on the first commit.

**08-02 (the publisher change) is deliberately not the tracer.** It is a 2-line mirror of an exact in-file analog (`EventUpcomingMatchSchema`'s own pmf pair, `TeamSeasonMatchSchema`'s own actual-RP pair) with zero architectural unknowns and no new computation — a tracer through it would prove nothing its own unit tests do not.

**The Simulation stack's real unknown is retired early anyway.** 08-07 — the app's first Web Worker, first Vite worker-bundling seam, first jsdom Worker mock — lands in wave 2 with a tracer-shaped end-to-end verification (main thread → worker → real core → ordered progress → final histogram) before four plans of tab UI depend on it. That is where an architectural dead-end in this phase would actually live, and it is proven two waves before anything builds on it.

### One republish, and why it carries no `checkpoint:decision`

CONTEXT rates D-03 and D-12 as **costly**, not one-way, and both ride the same republish by design — D-12's fields are "publisher plumbing, not new computation," explicitly costed as "no second republish, no additional Class-A op cost." 08-02 therefore lands both schema/publisher halves together and 08-05 runs the single pass. **No plan in this phase implies a second republish, and none is authorized.**

Under `REVERSIBILITY_GATES`, `one-way` earns a `checkpoint:decision` and `costly` is flagged only. Beyond that rule, this republish is structurally the same class of operation Phase 7's outline explicitly recorded as *not a door*: it adds four optional fields to existing `vpr@` keys the deployed client already reads, overwrites in place, introduces no new key, deletes nothing, and is idempotent — re-runnable to correctness at any point. A pre-existing artifact still parses either way, so there is no wave in which the live site is degraded. Phase 7's own gates sat at its **destructive** half (18,222 object deletions, a D1 row delete); this phase has no destructive half.

What 08-05 does carry is a **hard stop**, which is not the same as a gate: D-03 (~13,000 B) plus D-12 (~5,000 B) against 22,739 B of headroom is tight, and a breach of the 350,000 B ceiling at any event halts and reports rather than being absorbed by trimming another field. `payloadBudget.test.ts` must run against post-republish artifacts with `docs/publish-budget.md`'s committed JSON block updated first, or it asserts against Phase 7's numbers.

### Reading of the Data Dependencies gate (stated, not assumed)

The gate reads: sequence D-03's publisher/schema/republish work "before any Web Worker or Simulation-tab component work." Its stated purpose is that a tab must never read fields no artifact carries. Applied literally to every file, it would also block 08-03's pure math module and 08-07's worker file, neither of which reads a published artifact at all — 08-03 is a pure function over pmf arrays, and 08-07 receives a message payload the caller assembled.

So the gate is honored **strictly for everything that reads `redRpPmf`/`blueRpPmf` off a fetched artifact**: 08-09 (tab registration + shell), 08-11 (picker + input assembly), 08-13 (run control), 08-14 (rank table) all sit at wave 3 or later, downstream of 08-05. 08-03 and 08-07 run in waves 1–2. The gate's operative meaning is fully satisfied — no tab, and nothing the tab feeds, exists before the artifacts do — while the two artifact-independent modules are not held hostage to a 25-minute publish they never touch. Recorded here so a later reader sees a decision rather than an oversight.

### Assumptions made

1. **The tracer is the Compare page, not a Simulation slice or the publisher change** — reasoning in full above. The trade accepted: the tracer does not touch the pipeline or the Worker, because no single path in this phase can reach both stacks before D-03 is published. 08-07 is scheduled and verified as the Simulation stack's own risk-retirement slice to compensate, two waves ahead of anything that depends on it.
2. **08-01's accuracy table renders every cell at plain weight**, with D-11's bolding arriving in 08-06. This is a functionality gap, not an architectural one — nothing about the table's structure changes when bolding lands, and plain weight asserts nothing false, whereas naive max/min bolding would assert a winner D-11 says the data may not support.
3. **`apps/web/src/routes/__fixtures__/compare-2026.json` is the parity fixture, one year.** D-10 and RESEARCH Pattern 7 both describe a single committed artifact. Whether additional years are committed (~14 KB each) is an executor call sized against fixture bytes; if the parity claim is later read as covering all five years, adding four more fixtures is additive and needs no plan change.
4. **`simQuantile.ts` stays at the path UI-SPEC and PATTERNS both name (`apps/web/src/lib/`)**, and 08-08's Node control-run script imports it directly by relative path rather than duplicating it — it is a pure function with no DOM or Node dependency, and the "identical function, never two hand-synced copies" rule that put `rankSimulation.ts` in `packages/core/` applies to it just as strongly. If that import proves awkward under `tsx`, the fallback is to relocate it beside `rankSimulation.ts` in `packages/core/algorithms/simulation/`; the port itself is unaffected either way.
5. **No subset publish.** Phase 7 needed one because its republish was entangled with a key rename that would have 404'd the deployed client mid-phase. Here the republish is additive under existing key names, so publishing early in wave 2 costs nothing and a subset pass would buy nothing but a second write against R2 — which is exactly the shape the brief rules out.
6. **`EventArtifact.teams[]` is assumed to be a complete roster** (RESEARCH assumption A2, medium risk). If a team appears in `matches[]`/`upcoming[]` but not in `teams[]`, 08-11's baseline map needs an on-the-fly fallback entry (0 earned RP, 0 matches played) rather than sourcing it from `teams[]`. 08-14's mock-before-build pass against real data is the cheapest place this would surface, and its rewind-event sampling rule makes that likely.
7. **The sixth tab sits last, after Elims** — Claude's Discretion, resolved to CONTEXT's own stated expectation and to PATTERNS' verified registration ordering. The six-tab strip's phone behaviour keeps Phase 7's horizontally scrollable `overflow-x-auto` pattern unchanged rather than introducing a new responsive treatment; 08-15's S0 row is where that assumption gets tested rather than asserted.
8. **The simulation waits for an explicit "Run simulation" press rather than auto-running on tab open** — Claude's Discretion, resolved this way because the picker has no pre-selected row on the 97% of events that are fully played, so there is nothing to auto-run from, and because a 1000-draw Worker spawning on tab focus would burn a visitor's CPU for a result they may not have wanted.
9. **The Compare page's compLevel switcher state is local component state, not a URL search param.** The site's rule is that URL-shareable state lives in typed router search params; this is a genuine judgement call, and it is recorded rather than silently made. 10. **`docs/models/` is the home for D-02's measurement doc**, siblings `offseason-inclusion-remeasurement.md` and `opr-baseline-change.md` — the established location for a measured-result document that a copy string or a decision rests on.
