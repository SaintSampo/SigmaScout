## Decisions this plan makes (Claude's Discretion, recorded not assumed)

1. **The switcher is three `Button`s in a labelled `role="group"`, not Radix `Tabs`.**
   UI-SPEC leaves the choice open ("three `Button`s in a `ButtonGroup`-style row, or `Tabs` styled as
   a switcher; either is fine"). Resolved to buttons on two grounds. First, semantics: Radix `Tabs`
   emits `role="tab"` with an `aria-controls` pointing at a `tabpanel`, and this control does not swap
   one panel — it re-slices two sibling sections that stay mounted, with a methodology note sitting
   between them. Tab semantics would misdescribe the control to assistive technology, and the
   workaround (three identical panels, or one panel whose value always matches) is a hack that exists
   only to satisfy the primitive. Second, geometry: `TabsList` hard-codes a 32px height through
   `group-data-[orientation=horizontal]/tabs:h-8`, which fights UI-SPEC's 44x44 tap-target exception
   for exactly this control. Three `Button`s carrying `aria-pressed` inside a labelled group use the
   already-installed primitive, add no shadcn component (Registry Safety declares none this phase),
   and take `.tap-target` cleanly.
   — <reversibility rating="reversible">Markup and ARIA on one small control; the state contract above it is unchanged either way.</reversibility>

2. **The group's accessible name is `Match type`.**
   The Copywriting Contract fixes the three segment labels and names no label for the group itself,
   which would leave a group of three toggle buttons with no accessible name. `Match type` is chosen
   over `Competition level` because the segment labels are already the plain-language forms
   (`Qualification` / `Elimination`) rather than the artifact's `compLevelView` vocabulary, and the
   group name should match the register its own options are written in.
   — <reversibility rating="reversible">One `aria-label` string.</reversibility>

3. **`compareTie.ts` owns both display formatters, and `AccuracyTable.tsx` deletes its local pair.**
   D-11's Brier test is defined as "equal as displayed". The cheapest guarantee that the test and the
   printed digits can never disagree is that exactly one function in the codebase produces the
   displayed Brier string and both callers use it — a second formatter anywhere makes the guarantee a
   convention instead of a fact. The Winner Accuracy formatter is co-located for the same
   one-home reason even though its tie test operates on raw values, because splitting the pair across
   two modules would leave a reader guessing which module owns "how a Compare figure is printed".
   — <reversibility rating="reversible">Two function moves within one package; every call site is in this plan's own file list.</reversibility>

4. **The methodology note's figures are derived from the artifacts, not transcribed.**
   UI-SPEC is explicit that "the sentence structure is what's contractual, not the literal digits",
   and that a re-measurement means using the current committed artifact's numbers. Deriving is the
   only implementation that satisfies that instruction without a human remembering to. It also keeps
   the note inside 08-01's standing prohibition against rendering a number the artifact did not
   publish: five hand-typed digits on a public page are neither computed nor read, and would drift
   silently past every test on the page.
   — <reversibility rating="reversible">A pure builder function with its own tests; hard-coding is a strictly smaller change if it is ever wanted.</reversibility>

5. **The note's figures stay pinned to the combined view while the table follows the switcher.**
   D-08's claim is about the tune/holdout split and SC-3's verdict is measured on the combined view;
   the note is evidence about the split, not about a compLevel sub-slice. This is not a stylistic
   call — measured against the five committed artifacts, re-slicing the note to the elimination view
   makes its own "single best season" clause false, because VPR's 2022 elimination Brier is lower
   than its 2026 one. A note that changed its claim when the reader pressed a filter would be
   asserting something the filter has no bearing on.
   — <reversibility rating="reversible">One argument at one call site.</reversibility>

6. **The D-11 caption ships verbatim from the Copywriting Contract, including its "the threshold
   below" phrasing.** The contract string is binding and checker-approved; a reworded string would be
   a copy defect against a signed-off contract, and the planner's job here is not to edit approved
   copy. Placement follows UI-SPEC's own instruction ("a short caption beneath the table"), with the
   caption first and D-08's paragraph second, since the caption explains the ink the reader has just
   looked at.
   — <reversibility rating="reversible">One authored constant.</reversibility>

7. **Both paragraphs live in one `MethodologyNote.tsx` rather than two components.**
   UI-SPEC permits folding the caption into the note ("beneath the table (or folded into the
   methodology note)"), and both are the same thing structurally: an always-visible muted Body 14/400
   paragraph in the block directly beneath the table. One component keeps that block's spacing rhythm
   in one place and gives 08-12 one sibling to position its own section against.
   — <reversibility rating="reversible">A component boundary with no data contract behind it.</reversibility>

    **Formatters.**
    - `formatBrierDisplay` returns the four-decimal fixed-point text of its input;
      `formatWinnerAccuracyDisplay` returns the input scaled by one hundred at one decimal with a
      trailing percent sign. Assert against expressions computed in the test from the same inputs,

    **`resolveBrierLeaders` — lower is better.**
    - Three candidates with distinct values: the single lowest is returned, alone.
    - The real 2022 elimination pair, `0.14721222242674725` against `0.14717091997830647`: both round
      to the same four-decimal string, so an EMPTY leader set is returned. Assert the two formatted
      strings are equal in the same test, so the case documents itself.
    - One step above that threshold: two values whose four-decimal strings differ by one unit in the
      last place return the lower value's algorithm alone.
    - Two candidates whose values are strictly equal return BOTH, and a third strictly-worse candidate
      is not included. Exactly equal merges into joint leadership; merely rounding alike does not.
    - Candidates with a `null`-sourced or non-finite value are excluded before comparison. Fewer than
      two comparable candidates — zero, one, or one plus one non-finite — return an empty leader set.
    - Output order is `PUBLISHED_ALGORITHM_IDS` order: feed a joint tie with the candidates supplied
      in reverse and assert the returned pair is still in the constant's order.

    **`naiveStandardError`, `combineStandardErrors`, `isNearTie`.**
    - `naiveStandardError(p, n)` is the square root of `p * (1 - p) / n`; assert against the
      expression, not a digit string.
    - `naiveStandardError` returns a non-finite value when `n` is zero, for both an interior `p` and a
      `p` at the unit boundary — the two zero-count shapes differ (one divides a positive by zero, the
      other divides zero by zero) and both must be caught downstream by the same guard.
    - `combineStandardErrors(a, b)` is the square root of the sum of squares.
    - `isNearTie(gap, combinedStandardError)` is a strict `<`: equal inputs return false, a gap one
      step below returns true, a gap one step above returns false. Assert all three with the same
      standard-error value so the boundary and its two neighbours are one contiguous case.
    - `isNearTie` returns true whenever the combined standard error is not a finite number — a bound
      that cannot be computed cannot establish a winner, so the honest default is to withhold.
