<objective>
Build the phase's core math once, in one place, as a genuinely shared browser-safe leaf: a new
`packages/core/algorithms/simulation/rankSimulation.ts` exporting `simulateRanks`, plus its unit
suite and a sixth entry-point registration in `packages/harness/browserSafeSchemas.test.ts`.

The function draws one total-RP value per alliance per remaining qualification match from that
match's pmf, accumulates into per-team typed-array accumulators, ranks each draw by average RP per
match played, and returns a per-team rank histogram. **D-13 binding:** it simulates every row it
is handed and applies no row-exclusion rule of its own. **D-14 binding:** simulated ties are
recorded as ties, separated only by a lexicographic team-key comparison that exists for
reproducibility and asserts nothing about how a real event would resolve them.

Purpose: this module has **two** callers — 08-07's browser Web Worker and 08-08's Node control-run
script — and D-02's measured rewind-overconfidence figure is only meaningful if both feed the
*identical* function. That is the whole reason it lives in `packages/core/` rather than
`apps/web/src/lib/`. Getting the shared, DOM-free, Node-safe shape right here is what stops the
phase's headline honesty claim from quietly becoming a comparison between two implementations.

Output: one pure module with zero runtime imports, one unit suite whose pmf fixtures are produced
by the real pipeline function rather than typed by hand, and one cross-package guard proving the
browser bundle stays Node-free. Nothing is published, nothing is fetched, no credential is touched.
</objective>

<planner_decisions>

- **PD-01 — `simulateRanks` takes an already-selected list of matches and an already-computed
  baseline per team. It computes neither.** The two decisions the module deliberately does not own
  are D-13's row selection (which `qm` rows are at or after the start match) and D-12's earned-RP
  precedence (TBA Ranking Score, else summed per-match actual RP). Both belong to 08-11's
  `simulationInputs.ts`, because both require fields — competition level, per-match actual RP,
  `EventTeamSchema.rp` — that exist on the *artifact*, not in a pure ranking simulation. Pushing
  either into this module would make it artifact-shaped, and 08-08's Node control run does not have
  an artifact; it has two in-memory prediction sets. **Reversibility: reversible** (a parameter
  boundary, no published contract).

- **PD-02 — `SimTeamBaseline.earnedRpSum` is a TOTAL and the field's doc comment says so in the
  first sentence.** This is the single highest-consequence unit ambiguity in the phase: D-12's
  precedence-1 source, `EventTeamSchema.rp`, is TBA's Ranking Score, which is a per-match
  *average* (`pageArtifacts.ts:414-429`'s own doc comment says so), while precedence 2 is a *sum*.
  A caller that forwards the average unconverted mis-ranks the entire field by a factor of
  `matchesPlayed`, and no test on either side of the boundary would catch it — this module's tests
  would pass on self-consistent inputs and 08-11's tests would pass on a plausible-looking map.
  Stating the unit at the type, and repeating it in the key-links contract above, is the mitigation.
  **Reversibility: reversible.**

- **PD-03 — An unknown team key throws a named error; it does not silently no-op.** RESEARCH's
  worked example uses `teamIndex.get(teamKey)!`, which at runtime yields `undefined` and makes the
  subsequent typed-array write a silent no-op — the team's matches simply vanish from the
  accumulation and the resulting distribution looks entirely normal. Assumption A2 rates the
  underlying risk (a team in `matches[]` but not `teams[]`) as medium and explicitly makes an
  on-the-fly baseline entry 08-11's job. A named throw is what forces that fallback to actually
  exist rather than being quietly satisfied by wrong numbers. **Reversibility: reversible.**

- **PD-04 — Input shape is validated once, before the draw loop, not per draw.** A pmf of length
  zero would make `drawCategorical`'s residue fallback return `-1`, which is a valid array index
  going the wrong way. The publish-boundary schema (`isValidPmf`, `pageArtifacts.ts:282-287`)
  already rejects that shape, so this is defense-in-depth and not a second source of truth — which
  is exactly why it belongs in an up-front pass costing O(matches) once, rather than in the hot
  path costing O(draws x matches). The check is deliberately narrow: non-empty, finite entries. It
  does not re-validate the sum-to-1 tolerance, because that is the schema's job and duplicating a
  numeric tolerance in two places is how two tolerances drift apart. **Reversibility: reversible.**

- **PD-05 — A team with zero matches played ranks with an average RP of 0 rather than NaN.** Real
  case: a team on the roster that played no qualification match and has none remaining. `0/0` is
  `NaN`, and `NaN` in a comparator produces an ordering that is neither stable nor meaningful. Zero
  is also the honest value — it is what TBA's own rankings page shows for such a team — so this is a
  correctness fix that happens to agree with the convention the audience already reads.
  **Reversibility: reversible.**

- **PD-06 — `mulberry32` is copied verbatim a third time rather than imported.** `rp/distribution.ts`
  exports it, but that module imports `ml-matrix` at module scope, so importing the 10-line PRNG
  from it would drag a matrix library into the browser bundle and would fail this plan's own
  browser-safety guard. Verbatim copying with a citation is this repo's established convention for
  exactly this primitive — `packages/harness/identifiability.ts:123` and
  `rp/distribution.ts:53` already carry it, and `distribution.ts`'s own header documents the
  "cite, don't rederive" discipline. **Reversibility: reversible.**

- **PD-07 — No `<precondition>` on any task in this plan, deliberately.** Every test fixture is
  built in-process: the pmf arrays come from calling `rpPmfForMatch` with hand-built
  `AllianceRpMoments`, the same pure-unit shape `rp/distribution.test.ts` already uses with no
  corpus access and no network. There is no external service, no prior-phase artifact, no
  environment variable and no credential in this plan's path. A precondition asserting nothing
  would be noise; its absence is recorded here so a reader sees a decision.

- **PD-08 — This plan is wave 1 and does not wait on 08-05's republish, which is a stated reading
  of the UI-SPEC Data Dependencies gate rather than an oversight.** That gate exists so no surface
  reads `redRpPmf`/`blueRpPmf` off an artifact that does not carry them yet. This module reads no
  artifact at all — it receives pmf arrays as function arguments. The outline records the same
  reading in full under "Reading of the Data Dependencies gate (stated, not assumed)"; everything
  that genuinely touches a fetched artifact (08-09, 08-11, 08-13, 08-14) sits at wave 3 or later.

- **PD-09 — No `checkpoint:decision` in this plan.** `REVERSIBILITY_GATES` is on, and a `one-way`
  rating earns a gate. Every task here is rated `reversible`: this plan writes one new source file
  and one new test file, adds one case to an existing test file, publishes nothing, writes no R2
  object, changes no schema, and adds no dependency. `git revert` undoes the whole plan completely.
