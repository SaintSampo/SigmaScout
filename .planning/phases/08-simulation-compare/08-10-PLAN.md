Ship the Compare page's Calibration section sentence-first: one plain-language sentence carries the
section, and the reliability diagram beneath it is deliberately demoted to supporting evidence.

sitting underneath a headline accuracy of 74.8%, only four points behind VPR. Sketch 006 established

scouts, so the sentence leads and the chart supports.

concept explainer, the clickable OPR/EPA/VPR legend doubling as the sentence's algorithm switcher,
a local year `Select`, and a demoted Recharts `LineChart` with mandatory sparse-bin radius scaling —
plus three new `--compare-algo-*` tokens in `theme.css` and this plan's own palette re-validation
against the shipped tier tokens.

## Decisions this plan makes (Claude's Discretion, recorded not assumed)

1. **The measured tier collision is resolved by SEPARATION and an automated guard, not by re-hueing either palette.**
   This plan ran the dataviz validator against the shipped `theme.css` values, which is the work the
   outline said must not be hand-waved. Two runs, both recorded verbatim in Task 1: the trio alone
   passes every check under `--pairs all`; the trio plus the three `--tier-*-fg` tokens FAILS on
   `--compare-algo-epa #7C3AED` against `--tier-epic-fg #7E22CE` at OKLab ΔE 6.0 normal vision and
   5.4 deutan. Neither value may move — the trio is locked by sketch 006's own CVD-validated result
   and `colour-and-tiers.md` locks the tier palette with an explicit "do not fix this" warning — and
   `08-CONTEXT.md` forbids any `--tier-*` value change this phase outright. The six are also never
   asked to be told apart: the Compare page renders no tier box and no metric-tier concept, which
   UI-SPEC's Color section already states. Running the six as one categorical palette therefore asks
   a question no reader is ever posed. What makes that a decision rather than an excuse is that it is
   enforced: `comparePalette.test.ts` asserts no `--tier-` reference and no `metric-tier` class
   reaches any compare surface, so a later contributor who adds a tier box to this page trips a test
   instead of shipping two indistinguishable purples side by side.
   — <reversibility rating="reversible">Three additive tokens plus a guard test; if the two systems are ever genuinely needed on one surface, the guard fails loudly and the decision is reopened with the measurement already in hand.</reversibility>

2. **The concept explainer's diagonal orientation is CORRECTED; the UI-SPEC's Copywriting Contract has it inverted.**
   That row reads "A line above the diagonal means the algorithm was more confident than it should
   have been; a line below means it was too cautious." With observed frequency on y and predicted
   probability on x, a point above the 45-degree line has observed > predicted, which is the model
   being too cautious, not too confident. The UI-SPEC's own worked case settles it: OPR predicted
   85.3% and observed 52.8%, which plots *below* the diagonal, and the same document calls it "a
   32.5pp overconfidence gap." Shipping the contract's literal string would label this page's
   flagship finding as caution. The corrected clause — below means more confident than it should
   have been, above means too cautious — is what ships, every other word of the string unchanged,
   and Task 4 asserts the corrected orientation against that same OPR bin so the two can never drift
   apart again.
   — <reversibility rating="reversible">One authored string in one exported constant.</reversibility>

3. **The sentence renders entirely at Body 14/400 — no figure inside it is bolded.**
   Sketch 006's variant C bolded the three numerals, but that mockup predates D-11's page-wide rule.
   On the shipped Compare page, weight 600 on a number means "the published data can establish a
   winner here"; spending it on three figures inside a prose sentence about one algorithm's own
   calibration would dilute the only typographic signal this page has. UI-SPEC's Typography row
   fixes the sentence at Body 14/400 in `--color-text-primary` and authorizes no weight change. The
   numerals still get `numeric-cell` for tabular figures, matching every other number in the app.
   — <reversibility rating="reversible">A className on three spans.</reversibility>

4. **Section order: heading + year `Select`, sentence, explainer, legend/switcher, chart, size key.**
   This reconciles two constraints that pull apart. UI-SPEC puts the explainer "beneath the concrete
   sentence," and `chart-craft.md`'s proximity rule wants the colour legend adjacent to the marks it
   names. Placing the explainer directly under the sentence satisfies the first literally; placing
   the legend directly above the chart satisfies the second. The legend keeps its double duty —
   clicking an entry visibly changes the sentence two elements above it — which is what UI-SPEC asks
   for and is why no new control is introduced.
   — <reversibility rating="reversible">Element order in one component.</reversibility>

5. **The chart takes ONE merged, x-ascending `data` array with three nullable y keys and `connectNulls`, not per-`<Line>` `data` props.**
   Each algorithm's points sit at its *own* `meanPredicted` x values, so the three series do not
   share x positions. Recharts can take `data` on each `<Line>`, but `MetricHistoryChart.tsx` — this
   app's only prior Recharts component and therefore its only proven Recharts path — passes a single
   top-level `data` array, and this plan does not want its first unknown to be a Recharts feature
   nothing here has exercised. One merged array of up to 30 rows, each row carrying exactly one
   non-null series value plus that point's own count and radius, with `connectNulls` on each `<Line>`
   and a numeric `XAxis`, renders identically and keeps the "one axis" rule visibly true.
   — <reversibility rating="reversible">The shape is produced by `buildCalibrationRows`, a single pure function with its own tests.</reversibility>

6. **This plan is four tasks, not the usual two-to-three.**
   The palette re-validation, the pure model, the chart and the section each carry their own proof
   and their own files. Folding the chart and the section together would make one six-file task, and
   folding the palette work into the chart would let the obligation the outline singled out as
   "must not be hand-waved" ride along inside a larger task. Chunked mode allows exactly one plan
   file here, so a fourth task is the available way to keep every task at four files or fewer.
   — <reversibility rating="reversible">Task boundaries, no product surface.</reversibility>

7. **The sparse-bin radius floor deliberately goes below the dataviz skill's ≥8px marker guidance.**
   `calibrationPointRadius` is ported from sketch 006's own `sizeScale` (`MIN_POINT_R = 3.5`,
   `MAX_POINT_R = 16`, `t = sqrt(count)/sqrt(maxCount)` so *area* rather than radius tracks count).
   A 3.5px radius is a 7px mark, under that floor — which is the encoding working, not failing: the
   whole point is that a 1-match bin must not read with the visual authority of a 5,950-match one.
   The floor is never zero and the point is never hidden. If the demoted chart's rendered width
   makes 16px crowd its neighbours, `MAX_POINT_R` is the one constant to tune and 08-15's C3 row is
   where the 390px evidence lands; `MIN_POINT_R` does not rise.
   — <reversibility rating="reversible">Two exported constants feeding one function that both the marks and the size key read.</reversibility>
