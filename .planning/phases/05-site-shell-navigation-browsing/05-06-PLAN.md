  <behavior>
    - `winRate({ wins: 7, losses: 3, ties: 0 })` returns `0.7`.
    - `winRate({ wins: 0, losses: 0, ties: 0 })` returns `null` — a rate over zero matches is undefined, and a caller must be able to tell that from a real zero.
    - `winRate({ wins: 0, losses: 5, ties: 0 })` returns `0` — a real zero rate is a measurement and must not be confused with an absent one.
    - `winRate({ wins: 1, losses: 1, ties: 1 })` counts ties in the denominator and not the numerator.
    - `buildTeamRows` assigns rank 1 to the team with the highest total metric and increments from there.
    - `buildTeamRows` breaks a rank tie by ascending team number, and two teams with the identical total receive two distinct consecutive ranks — never a shared rank and never a merged row.
    - `buildTeamRows` assigns a rank to every input row, so the count of rows out equals the count of rows in.
    - A row whose `metrics` lacks a key the declared set contains yields `undefined` for that cell rather than being dropped or defaulted to zero.
    - A row whose `metrics` lacks the total key sorts last under a descending total sort rather than throwing.
    - `sortTeamRows(rows, key, "desc")` orders by that key descending and breaks ties by ascending team number; calling it twice on the same input produces identical output.
    - `sortTeamRows` on a key absent from every row leaves the order determined by the tie-break alone, deterministically.
    - `sortTeamRows` does not renumber ranks — rank is a property of the artifact, not of the current sort.
    - `buildTeamRows` on an empty team array returns an empty array without throwing.
    - `buildTeamRows` on a single-team array returns one row at rank 1.
  </behavior>
  <action>
Write `rowModel.test.ts` first — every behaviour above is a concrete input/output pair.

Implement `rowModel.ts` as pure functions over the published artifact, importing no React and no
TanStack anything:

- `winRate(record)` returns a number in zero-to-one or `null` when the three counts sum to zero. Return
  the raw fraction; the percentage formatting is the column's business, not the model's. The null case
  is the one this project would otherwise ship as a not-a-number, because a zero-match team is not a
  hypothetical in a real season.
- `buildTeamRows(artifact, algorithmId)` maps each published row to a `TeamRow` carrying the team key,
  number, nickname, record, win rate, the metrics record as published, and a rank. Rank is the
  team's position when ordered by the total metric descending with ascending team number as the
  tie-break — computed once here and never recomputed by a sort. That choice is a planner decision
  worth stating in a comment: it makes rank a stable property of the algorithm-and-year pair, so
  sorting by a component column changes the row order without renumbering anyone, which is the
  behaviour this table's users already expect from comparable FRC tools.
- `sortTeamRows(rows, key, direction)` sorts by the metric value at `key`, placing rows missing that
  key last regardless of direction, with ascending team number as the final tie-break so the result is
  a total order. That total order is what makes the sort stable across re-sorts and reloads without
  relying on the engine's sort stability guarantees.

Nothing in this file derives a statistic the artifact does not carry. Win rate is arithmetic over three
published integers, which NAV-06 permits as presentation; anything requiring match-level data would not
be.

**Columns.** `buildColumns(algorithmId, season)` returns the leading group — rank, team number,

win rate. The metric columns come from the declared key set and from nothing else; a row missing one

**Table.** `TeamsTable.tsx` composes TanStack Table's column pinning with TanStack Virtual's row
virtualizer over exactly ONE native scrolling element that scrolls on both axes and is also the
virtualizer's scroll element. The table is sized to the total column width so the horizontal axis
overflows naturally; the header row is stuck to the top; pinned cells are positioned sticky at their
computed left offset with an opaque background token. There is exactly one element with a scrolling
overflow rule in the component — a second one is the failure shape D-04 named.

layout with an ellipsis and expose the full string through the native title affordance, never by
slicing the string in code. Numeric cells carry the tabular-figures class from plan 05-03.

The table renders all rows the model gives it. It does not page, does not cap, and does not window the
data itself — virtualization is a rendering technique here, not a data limit.
