<objective>
Stand up the design system the rest of the phase composes from: the shadcn primitives the UI contract
names, the token layer D-06 requires, and the one display primitive that carries this project's
differentiator onto every table it will ever draw.

Purpose: `05-UI-SPEC.md` names `npx shadcn init` the first action item once `apps/web` exists, and D-06
attaches an engineering requirement to the light-only theme decision — every colour is a token from the
first component, never a literal. Both are cheap now and expensive to retrofit. The `MetricValue`
primitive is here rather than inside the Teams table because Phases 6, 7 and 8 all render the same
`value ± spread` string, and the rule for when the suffix appears is a schema-level fact worth
encoding once with tests rather than re-deriving per table.

Output: `components.json` and eight official-registry primitives, a reconciled token layer, shared
responsive and tabular-numeral utilities, and a tested `MetricValue`.
</objective>

Make the token layer single-sourced, then add the two shared utilities every later component needs.

**Reconcile the tokens.** shadcn's initializer writes its own CSS variable block (its `--background`,
`--foreground`, `--primary`, `--muted-foreground` and friends). Plan 05-01 wrote the UI contract's own
`@theme` tokens. Leaving both means two definitions of "the page background" that can drift. Resolve
it by making shadcn's variables *derive from* the contract's tokens — the contract's names stay
authoritative and shadcn's names alias them — so a future dark pass changes one block. Every one of the
UI contract's four colour roles, its seven-step spacing scale and its radius must be present and
reachable by name. Record the mapping in a comment at the top of the file so the derivation direction
is stated rather than inferred.

**Typography utilities.** Declare the four type roles from the contract's table as reusable classes or
token pairs: body 14/400, label 12/600, heading 20/600, display 28/600. Add the one deliberate
exception the contract names — the spread suffix is 12px at weight 400, Body's weight at Label's size —
as its own named class so it reads as intentional wherever it appears. Only weights 400 and 600 exist;
no other weight may be declared.

**Tabular figures.** A shared numeric-cell class applying `font-feature-settings: "tnum"` so every
column of digits aligns vertically — rank, team number, metric values, win rate, week number.

**Tap targets.** A shared class applying a 44 pixel minimum width and height, per the contract's WCAG
exception, expressed as minimums rather than visible padding so a small glyph still sits inside a large
hit area without looking oversized.

**Breakpoint.** Create `src/lib/breakpoints.ts` exporting `MOBILE_BREAKPOINT_PX` and a `useIsMobile()`
hook built on `window.matchMedia`. This is the single definition of the phone/desktop boundary: CSS
responsive utilities and any JavaScript that needs to know which layout is active both resolve to it,
so two components can never disagree about which side of the line they are on. State the boundary
condition explicitly in a comment — which side of the exact boundary value counts as mobile — because
"at exactly the breakpoint" is precisely where a layout ambiguity would otherwise hide. The hook must
subscribe to changes and unsubscribe on unmount, and must not crash when `matchMedia` is absent
(jsdom provides no implementation by default, so the test setup will need a stub).

**Skeletons.** Create `src/components/Skeletons.tsx` exporting `SkeletonRows({ rows, columns })`,
composing the generated skeleton primitive into the D-16 first-load state: header and column headers
render immediately from the shell while body rows show placeholders. Both the Teams table and the
Events list consume it in wave 4, so it takes a row and column count rather than hard-coding either.

**Empty and error views.** Create `src/components/StateViews.tsx` exporting `EmptyState` and
`ErrorState`, using the UI contract's Copywriting Contract rows verbatim with their placeholders
parameterized: the empty state takes a heading and a body plus an optional clear-filters action, and
the error state takes a resource name and a year and renders the contract's two copy lines plus a
Retry button that invokes a passed callback. Both wave-4 tables consume these, which is why they live
here rather than being written twice with drifting wording. Add `StateViews.test.tsx` asserting the
rendered copy matches the contract's strings exactly, that the retry callback fires on click, and that
the clear-filters action is absent when no callback is supplied.

    - `MetricValue({ metric: { value: 88.2, spread: 3.1 } })` renders the text `88.20 ± 3.10`, with the value and the suffix in separate elements so they can carry different type and colour.
    - `MetricValue({ metric: { value: 88.2 } })` renders exactly `88.20` — no suffix element, no placeholder dash, no stray separator character.
    - `MetricValue({ metric: undefined })` renders a single em-dash and nothing else.
    - `MetricValue({ metric: { value: 0 } })` renders `0.00`, not an em-dash — a real zero is a measurement and must not be confused with an absent one.
    - `MetricValue({ metric: { value: 88.239 } })` renders `88.24` and the component performs no rounding of its own beyond the two-decimal digit restoration; the input is already rounded by the pipeline, so this case exists only to pin the formatting call, not to sanction re-rounding.
