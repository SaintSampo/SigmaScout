## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn — **confirmed by the user 2026-08-23**, official registry only; `npx shadcn init` not yet run because `apps/web` does not exist |
| Preset | base color `neutral`, CSS variables **on** (mandatory — matches 05-CONTEXT D-06's token-discipline requirement), radius `0.375rem` (6px) |
| Component library | Radix primitives via shadcn |
| Icon library | lucide-react |
| Font | Inter (self-hosted via `@fontsource-variable/inter` or `next/font`-equivalent Vite plugin), with `font-feature-settings: "tnum"` (tabular figures) applied to every numeric table cell — rank, team #, metric values, win rate, week number — so columns of digits align vertically |

**Why shadcn was not actually initialized this session.** `apps/web` does not exist yet (greenfield —
confirmed: no `components.json`, no `package.json` React/Vite/Tailwind dependency anywhere in the
repo). `npx shadcn init` requires a scaffolded Vite project to detect against, and its `--preset`
flow requires a human to visit ui.shadcn.com/create and paste back a preset string — neither
precondition exists yet and this research pass has no interactive channel to the user. **This is
the first action item for Phase 5's scaffolding plan**: create `apps/web` (Vite + React 19 +
Tailwind v4), then run `npx shadcn init` with the preset above (or the user's own substitution),
before any component work starts. Until that happens this file's `shadcn_initialized: false` is
accurate, not stale.

**Why shadcn at all, given CLAUDE.md's stack table doesn't name it.** CLAUDE.md fixes React/Vite/
Tailwind/TanStack Router/TanStack Query/Zustand/Recharts but is silent on a component/primitives
layer. This phase needs several accessible interactive primitives with real keyboard/ARIA
behavior out of the box — a combobox-style instant search dropdown (D-08), a `Select` for two
global dropdowns (NAV-02), a mobile filter sheet (D-15), a skeleton loader (D-16) — and shadcn
(Radix underneath, Tailwind-native styling, code lives in the repo rather than a node_modules
black box) is the standard 2025/2026 choice for exactly this shape of app. **The user confirmed this
on 2026-08-23**, choosing it over depending on `@radix-ui/*` directly and over hand-rolling the
primitives; official registry only, no third-party registries. Running `npx shadcn init` with the
preset above remains the first action item of Phase 5's scaffolding plan.

**Component inventory needed this phase (all shadcn official registry — no third-party registry):**
`select` (year + algorithm dropdowns), `command` (search instant-results, built on `cmdk` — matches
D-08's keyboard-navigable dropdown-of-top-matches exactly), `sheet` (mobile filter sheet, D-15),
`badge` (offseason tag, active-filter count), `skeleton` (D-16 first-load state), `button`,
`separator`, `table` (markup/styling primitive only — see Teams table note below).

**Teams table virtualization — resolves 05-CONTEXT Open Question 1.** Use **TanStack Table** (for
column definitions + **column pinning**, pinning `rank`, `teamNumber`, `nickname` as the leading
frozen group) composed with **TanStack Virtual** (row virtualizer over the ~3,750-row array). This
is TanStack's own documented pattern for "virtualized + pinned columns": the pinned columns render
in a separate, non-horizontally-scrolling DOM region while the scrolling body owns the horizontal
axis, so vertical (virtualized) touch-scroll and horizontal (overflow) touch-scroll never compete
for the same gesture on the same element — the exact conflict D-04 flagged as a real risk, not a
default. Both libraries are already implied by the fixed stack's TanStack family; no new dependency
family is introduced.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inline padding |
| sm | 8px | Compact element spacing, table cell vertical padding |
| md | 16px | Default element spacing, table cell horizontal padding |
| lg | 24px | Section padding, ribbon vertical padding |
| xl | 32px | Layout gaps between major page regions |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: **44×44px minimum tap target** for every icon-only control on mobile (search trigger,
filter-sheet trigger, sort-direction toggle, column-scroll affordance) — WCAG 2.5.5/2.5.8 target
size, and this app is explicitly required to be phone-usable (NAV-04). Applied as `min-width`/
`min-height`, not as visible padding, so a small icon can still sit inside a 44px hit area without
looking oversized.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 600 | 1.3 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Two weights only: 400 (regular) and 600 (semibold) — no 500 or 700 anywhere.

**Usage map:** Body 14/400 — table cell values, body copy, sigma spread suffix. Label 12/600 —
column headers, filter-chip labels, badges, the ribbon's active-page indicator text. Heading
20/600 — page titles ("Teams — 2026", "Events — 2026"). Display 28/600 — reserved for the ribbon
wordmark/logotype only; this phase has no other display-scale content (no hero numbers on a
browsing page).

**Sigma display format (D-07 — locked, this is the project's core differentiator):** render as
`{value} ± {spread}` where both numbers arrive from the artifact **already rounded to 2 decimals**
(`packages/harness/rounding.ts`'s D-06 rule — never re-round client-side; format with `toFixed(2)`
only to restore any trailing-zero digits JSON serialization dropped, e.g. `88.2` → display `88.20`).
The value renders at Body 14/400 in the primary text color; the ` ± {spread}` suffix renders at
Label 12/400 (note: 400, not 600 — the one deliberate use of Body's weight at Label's size) in a
muted secondary color (`--color-text-muted`, see Color below). This is smaller AND lighter-colored
than the value, satisfying D-07's "visible but never competes with the value for attention." OPR
and EPA rows carry no `spread` field at all — render the bare value with no `±` suffix and no
placeholder dash; a missing spread is not a missing value.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F8FAFC` (slate-50) | Page background, table row background |
| Secondary (30%) | `#F1F5F9` (slate-100) | Ribbon/nav bar, filter sheet surface, card backgrounds, alternating-row tint (if used) |
| Accent (10%) | `#4F46E5` (indigo-600) | See reserved-for list below |
| Destructive | `#DC2626` (red-600) | Error-state icon/text, retry-button border — never a fill on a primary action in this phase (no delete/remove exists) |

**Accent reserved for:** the active ribbon link's underline/indicator, the primary CTA button
("Apply filters"), focus rings on every interactive control (inputs, dropdown triggers, table
sort headers), the sort-active column header's arrow glyph, the search dropdown's keyboard-
highlighted row background (at 10% opacity tint, not solid fill), and the active-filter-count
badge on the mobile filter-sheet trigger. Never used for: body text, table row backgrounds, or
any static/decorative surface — accent means "this is interactive and/or currently active,"
nothing else.

**Why this palette, not Statbotics'/TBA's blue.** 05-CONTEXT D-05 requires SigmaScout's palette
to read as its own identity while keeping Statbotics' information architecture. Both TBA and
Statbotics use blue-dominant navigation; indigo-600 sits close enough to feel like "a serious data
tool" but is visually distinct on a side-by-side comparison, and passes WCAG AA contrast (≈5.9:1)
against the white/slate-50 background for 14px body-weight text. All values are defined as CSS
custom properties (`--color-*`) per D-06's token-discipline requirement — never hardcoded hex
literals in component code — so the eventual dark-theme pass (deferred, v2) is a token swap.

**Live-tier honesty (constraint carried in from CLAUDE.md/04-CONTEXT):** `opr` and `epa` are not
folded live; only `sigma1` is. This phase does not surface per-algorithm freshness in the UI (that
is ENH-01/a deferred idea) — so the algorithm dropdown must NOT use color (e.g. a green "live" dot)
to imply equal freshness across the three options this phase. No accent-colored freshness indicator
exists anywhere in this phase's scope.

### Cross-phase prerequisite (blocking)

**Phase 4 artifact amendment, decided 2026-08-23.** The published `v1/events/{year}` artifact (`EventsListRowSchema` in `packages/harness/pageArtifacts.ts`) carries no `country`, `stateProv`, or `districtKey` field — confirmed by full-repo grep, zero matches — but EVNT-01 and 05-CONTEXT D-15 both require filtering by all three. **Resolution: amend `EventsArtifactSchema` and `buildEventsArtifact` to carry those three fields, sourced from TBA's `event.country` / `event.state_prov` / `event.district`, and republish the events artifacts before Phase 5's Events-filter work begins.** The fields are already present on TBA's event object, so this is a schema-and-republish task, not new data gathering. All three fields are nullable; the null handling is specified in the Events list `partial` and Events filter `empty`/`partial` rows above.

### Teams table column note — supersedes the earlier one-column reading of TEAM-01

**Decided 2026-08-23: the Teams table renders `total` PLUS the selected algorithm's named component metrics**, not a single "Rating" column. TEAM-01's "metric(s)" is read as plural. The consequence is that the table's column SET is algorithm-dependent — OPR contributes one metric column, EPA and Sigma1 several — which reopens 05-CONTEXT Open Question 3.

**Sort-fallback rule (resolves Open Question 3):** the active sort column is stored in the URL search params by metric key. On an algorithm switch, if that key is absent from the new algorithm's declared `teamMetrics`, the table falls back to `TOTAL_METRIC_KEY` descending and rewrites the search param to match — every algorithm guarantees `total` (D-27), so the fallback can never itself fail. The sort direction is preserved across the switch. No error, no toast: the column simply is not there any more and the table lands on the one sort every algorithm shares.

**Column-set derivation:** columns come from the selected algorithm's declared `teamMetrics`, never from inspecting row data — so a row missing a declared component renders an em-dash rather than silently shrinking the table. Per-component *history* charts remain Phase 6 team-detail scope.

### Icon-only control labels (closes the checker's Dimension 2 FLAG)

Every icon-only control carries an `aria-label` naming its action, in addition to its 44×44px hit area: `aria-label="Open search"` (mobile search trigger), `aria-label="Open filters"` (filter-sheet trigger, with the active count folded in when non-zero — `"Open filters, 2 active"`), and `aria-sort` on every sortable column header (`ascending` / `descending` / `none`) so the sort state is announced rather than conveyed by the accent-colored arrow glyph alone. Decorative lucide glyphs inside labelled controls carry `aria-hidden="true"` so the label is not read twice.
