<objective>
Prove the whole offline-to-published chain works on one real artifact before anything is widened to
five seasons and every page type, and close the two design questions the upstream artifacts left open.

Purpose: this phase's remaining six plans all rest on three unverified assumptions — that the
Cloudflare account can actually hold what the design needs, that a versioned artifact key survives a
round trip over plain HTTPS, and that the leak-proof prediction guard the Worker will need is
reachable from a Worker at all. Each is cheap to check now and expensive to discover in plan 06.

**Design question 1, resolved by direct inspection at planning time.** `04-PATTERNS.md` flagged, as
unresolved by both `04-CONTEXT.md` and `04-RESEARCH.md`, whether `packages/harness/replay.ts`'s
`toLeakProofUpcoming` Proxy is Worker-importable as-is. It is not, and this is verifiable in one line:
`packages/harness/replay.ts:17` is a **value** import — `import { selectMatchesChronological, type
Corpus } from "../corpus/db.js"` — and `packages/corpus/db.ts:13-16` imports `better-sqlite3`,
`node:fs`, `node:path` and `node:url`. Importing `replay.ts` from `apps/worker` would drag the whole
SQLite corpus layer into a Workers bundle. So Task 3 extracts `toLeakProofUpcoming` and `OUTCOME_KEYS`
into `packages/core/algorithms/leakProof.ts` — under the existing `isomorphic.test.ts` fitness test,
which already fails on any `node:`/`better-sqlite3` import anywhere in `packages/core` — and has
`replay.ts` re-export them, so all 45 existing test files keep their import paths and their behavior.

**Design question 2, resolved the same way.** `packages/harness/cli.ts`'s `applyPromotedOverrides`
(the rule that resolves which Sigma1 version `sigma1` means) is equally un-importable — `cli.ts:34-38`
imports `node:fs`, `node:path`, `node:util`, `node:url` and `node:perf_hooks`. The Worker therefore
cannot re-run that rule, and re-deriving it would be a second promoted-version resolution rule, which
is exactly the drift `04-CONTEXT.md`'s Integration Points section forbids. The resolution follows
D-12's own logic — the offline pipeline is the authority — so the promoted version's identity and
its `params` ride in an offline-published manifest, and the Worker rebuilds the module with
`makeSigma1` (which IS in `packages/core` and IS Worker-importable). That manifest is built in plan
04-03; this plan only records the decision and keeps the offline side honest.

Output: a Cloudflare account confirmed fit for purpose, the Cloudflare credentials under the same
secrets discipline as the TBA key, a `CLAUDE.md` that no longer contradicts the design, the shared
leak-proof module, and one real published artifact fetched back byte-identical over HTTPS.
</objective>
