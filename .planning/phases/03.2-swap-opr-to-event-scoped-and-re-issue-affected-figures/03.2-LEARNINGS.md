# Phase 03.2 Learnings: Swap OPR to Event-Scoped and Re-Issue Affected Figures

## Decisions

### OPR redefined as event-scoped, quals-only, no-ridge
`packages/core/algorithms/opr.ts` was rewritten (514 to 298 lines) to fit one event's qualification
matches via a bare minimum-norm pseudo-inverse, matching TBA's own `matchstats_helper.py`.

**Rationale:** FRC, TBA and Statbotics all mean event-scoped OPR. Publishing a season-pooled ridge
variant under the name "OPR" would ship a different quantity than readers expect.
**Source:** 03.2-CONTEXT.md (D-01/D-02/D-03/D-05/D-06), 03.2-02-SUMMARY.md

### Freeze the retired baseline before deleting the code that produced it
Plan 03.2-01 captured two committed fingerprints of the season-pooled baseline, and a checkpoint
gate blocked the rewrite until they existed.

**Rationale:** Once 03.2-02 landed, the season-pooled numbers could never be regenerated from
working-tree code. `docs/models/` was about to claim "the baseline moved, and here is what it moved
from" — that claim needs evidence that outlives the deletion.
**Source:** 03.2-CONTEXT.md (D-13), 03.2-01-PLAN.md

### The retired code got a final full run as a control, not just an archive copy
Rather than only fingerprinting the surviving `reports/tuned-v3/`, the retired implementation was
re-run end-to-end and both digests compared.

**Rationale:** Agreement proves the code at HEAD still reproduces every published number;
disagreement would have been a real fact about the record rather than something to reconcile away.
It cost ~96 minutes and was free information either way.
**Source:** 03.2-CONTEXT.md (D-13), 03.2-01-SUMMARY.md

### Live documents replaced outright; Phase 1-3 SUMMARYs annotated, never rewritten
`docs/models/`, `PROJECT.md` and `REQUIREMENTS.md` had figures swapped. Nine Phase 1-3 SUMMARYs
received dated superseded-by notes with original numbers untouched.

**Rationale:** SUMMARYs are the execution record of what a completed plan actually measured.
Rewriting their numbers would falsify that record. SC-2 was reworded through `/gsd-phase` before
planning and before any new figures were known, so the softer reading could not be mistaken for
fitting a criterion to a result.
**Source:** 03.2-CONTEXT.md (D-16), 03.2-06-SUMMARY.md

### 04-CONTEXT D-11 corrected as a dated errata block, original left visible
The wrong text stays in place; the correction is appended beneath it and dated.

**Rationale:** D-11 cited the *untuned* `sigma1-defaults` rows losing to season-pooled OPR. Its
arithmetic was right about those rows — it cited the wrong ones. Correcting in place rather than
editing silently preserves what Phase 4 was actually reasoning from, and the correction strengthens
D-11's argument rather than weakening it.
**Source:** 03.2-CONTEXT.md (D-17), 03.2-06-SUMMARY.md

### Fingerprints stored in `data/baselines/`, not the researched `data/retired-baselines/`
Both RESEARCH.md and PATTERNS.md recommended a `retireOprBaseline.ts` script writing to
`data/retired-baselines/`.

**Rationale:** Plan 03.2-03 needed the identical generator and schema for the NEW event-scoped
baseline, and SC-3's "both baselines side by side" reads better from one directory with one schema
than two near-duplicates. The load-bearing constraint both artifacts actually named — never inside
`data/algorithm-versions/` — was preserved and directly tested.
**Source:** 03.2-01-PLAN.md (documented deviation from 03.2-RESEARCH.md / 03.2-PATTERNS.md)

### The rewrite was subtractive, reusing ml-matrix's existing SVD threshold
No hand-rolled singular-value cutoff, no epsilon ported from another language.

**Rationale:** `SingularValueDecomposition.solve()` — already called by the pre-existing code —
already zeroes singular values below its own relative threshold, the same convention
`np.linalg.pinv` uses. Reimplementing it would have introduced divergence from TBA for no gain.
**Source:** 03.2-02-PLAN.md, 03.2-02-SUMMARY.md

### Code-review fixes chose the strict option over the convenient one twice
WR-01 removed a lossy round-trip rather than relaxing a strict equality gate to a tolerance.
IN-03 re-throws with file and line context on a truncated sidecar line rather than skipping it.

**Rationale:** Both gates exist to fail loudly. Loosening the comparison, or skipping a malformed
record, would have silenced the symptom while making the pipeline quietly less trustworthy —
skipping in particular would change the population being fingerprinted and yield a wrong-but-
plausible provenance digest.
**Source:** 03.2-REVIEW-FIX.md

## Lessons

### An estimate anchored to a pre-change measurement can be wrong by an order of magnitude
The plans budgeted ~3.5h for the full five-season, five-algorithm re-run, extrapolated from a prior
6h03m run. The actual was **8 minutes 10 seconds**.

**Context:** The old measurement was dominated by the very code this phase removed — season-pooled
OPR contributed ~2.5h at ~131ms per update across ~3,700 teams. The rewritten module solves ~39x39
per event in microseconds. Extrapolating a cost from a baseline that includes the thing you are
deleting produces a number with no relationship to reality.
**Source:** 03.2-03-SUMMARY.md, 03.2-RESEARCH.md

### A plan's precondition can go stale inside its own phase
Plan 03.2-04's precondition instructed a halt if `reports/event-scoped-v1/` was missing, "since
re-creating it costs hours" — but plan 03.2-03, executed earlier in the same phase, had already
measured that exact command at 8m10s.

**Context:** All six plans were written in one planning pass, before any of them ran. Later plans
therefore encode the *pre-measurement* estimate as fact. The executor recognised the staleness,
regenerated in 9m03s, and verified the result against the committed fingerprint before trusting it.
**Source:** 03.2-04-SUMMARY.md

### A gitignored file can change behavior, not just availability
`reports/tune-joint-on.json`'s absence silently resolves `sigma1-adapt` to `2.0.0+defaults-adapt`
instead of the published `2.0.0+tune-joint-on-winner`, via a fallback in
`packages/harness/cli.ts`. The run still succeeds and the numbers still look plausible.

**Context:** This is threat T-03.2-13 and it actually fired during plan 03.2-03 — a fresh worktree
lacks the file by construction. It was caught only because the plan explicitly instructed a check.
The committed figures would otherwise have been a different algorithm's, under the published name.
**Source:** 03.2-03-SUMMARY.md (deviation 3), 03.2-SECURITY.md (T-03.2-13, A-01)

### .gitignore deny-then-negate silently no-ops `git add` — this bit twice
`data/*` with explicit `!data/algorithm-versions/` meant new directories under `data/` were
invisible: `git status` never listed them as untracked and `git add` refused without failing.

**Context:** Hit first in plan 03.2-01 (`data/baselines/`) and again in plan 03.2-04
(`data/diagnostics/`). Each new committed-artifact directory under a deny-listed parent needs its
own negation line added at creation time, or the artifact silently never lands.
**Source:** 03.2-01-SUMMARY.md (deviation 1), 03.2-04-SUMMARY.md (deviation 2)

### Aggregate-metric equality is strong evidence of stream identity, but not proof
The retired re-run matched all five published seasons to full float precision, but per-season
bitwise digests could only be compared on 2022/2023/2026 — the 2024/2025 sidecars came out
empty/missing.

**Context:** A Brier score is a mean over ~17,000 predictions; matching to 16 significant digits is
essentially impossible if any single prediction differed. The SUMMARY recorded this as "strong
corroborating evidence short of bitwise-conclusive" rather than overclaiming — and the distinction
was surfaced explicitly at the point-of-no-return checkpoint so the decision was made knowingly.
**Source:** 03.2-01-SUMMARY.md, 03.2-02-SUMMARY.md (checkpoint resolution)

### Worktree isolation makes every gitignored input absent by construction
Every one of the six plans hit this: no `node_modules`, no `data/corpus.sqlite` (351 MB), no
`reports/`, no `.env`.

**Context:** The costs compound — pnpm's wrapper additionally triggers a dependency-state check
that fails on `better-sqlite3`'s native rebuild (no MSVC toolchain), blocking every pnpm-wrapped
command even though the shipped prebuild works fine at runtime. By plan 03.2-03 the workarounds
were a documented, reused precedent rather than a rediscovery.
**Source:** all six 03.2 SUMMARY files

## Patterns

### Freeze-before-delete
Capture a validated, committed fingerprint of what an implementation produces *before* removing the
implementation, and gate the removal on that fingerprint existing.

**When to use:** Any change that replaces a model, algorithm, or metric whose outputs are already
published. The gate is what makes it a pattern rather than an intention.
**Source:** 03.2-CONTEXT.md (D-13), 03.2-01-PLAN.md, 03.2-02-SUMMARY.md

### Committed fingerprint that outlives the gitignored run directory
Downstream work reads a small committed summary artifact, never the multi-hundred-MB `reports/`
tree that produced it.

**When to use:** Whenever an expensive run feeds later steps. It proved its worth immediately —
plan 03.2-04 found `reports/event-scoped-v1/` gone (deleted with 03.2-03's worktree) and recovered
without re-deriving trust.
**Source:** 03.2-03-PLAN.md (success criterion), 03.2-04-SUMMARY.md

### Verify regenerated ephemeral data against a committed artifact before trusting it
After regenerating a gitignored run directory, compare its figures against the already-committed
fingerprint *before* computing anything new from it.

**When to use:** Any time expensive intermediate output is recreated rather than restored. Plan
03.2-04 checked all five seasons' brier/accuracy/scoredCount at full precision first — making the
regeneration provably faithful rather than assumed so.
**Source:** 03.2-04-SUMMARY.md (deviation 1)

### Measure one unit before committing to the full run
Plan 03.2-03's Task 1 ran a single season across all five algorithms and recorded the cost before
Task 2 attempted five seasons.

**When to use:** Any long batch job whose cost estimate is inherited rather than measured. Here it
converted an assumed 3.5h into a measured 92 seconds/season before any large commitment.
**Source:** 03.2-03-PLAN.md, 03.2-03-SUMMARY.md

### Hard-link large gitignored inputs from the main checkout, read-only
`cmd.exe /c mklink /H` with an `MSYS_NO_PATHCONV=1` prefix (Git Bash mangles the paths otherwise);
never copy, never write to the source.

**When to use:** Worktree-isolated execution needing a large gitignored input. Avoids duplicating
351 MB per worktree; removing the worktree drops only the link.
**Source:** 03.2-02-SUMMARY.md (deviation 2), 03.2-03-SUMMARY.md (deviation 2)

### Bypass the package-manager wrapper, not the tool
Invoke `node node_modules/<pkg>/dist/cli.mjs` directly when `pnpm run` fails its dependency-state
check.

**When to use:** When a native postinstall fails but the shipped prebuild works at runtime. The
failing step is install-time only; the capability is genuinely present.
**Source:** 03.2-02-SUMMARY.md (deviation 1), reused by 03.2-03/04/05/06

### Annotate-don't-rewrite for execution records, proven additive-only
Append dated superseded-by notes; prove nothing was removed with `git diff -U0` showing zero
deleted content lines.

**When to use:** Correcting the record where some documents are *live* (replace) and others are
*historical* (annotate). The mechanical proof is what makes the claim checkable — 9 files,
45 insertions, 0 deletions.
**Source:** 03.2-06-SUMMARY.md, 03.2-VERIFICATION.md, 03.2-SECURITY.md (T-03.2-28)

### Record the disagreement rather than resolve it silently
Plan 03.2-06's independent re-sweep could not confirm one of the inventory's ten annotate rows.
It was left un-annotated with the discrepancy written down in place.

**When to use:** Whenever a verification pass disagrees with an earlier artifact. Forcing agreement
in either direction destroys the signal; the phase verifier later confirmed the re-sweep was right.
**Source:** 03.2-06-SUMMARY.md, 03.2-FIGURE-INVENTORY.md, 03.2-VERIFICATION.md

## Surprises

### The full re-run was ~30x faster than budgeted
8m10s against a ~3.5h estimate.

**Impact:** Removed the phase's dominant scheduling constraint mid-flight. Waves 4-6 could be run
back-to-back instead of being paced around a multi-hour job, and plan 03.2-04 could regenerate a
deleted run directory in 9 minutes rather than halting as its own precondition instructed.
**Source:** 03.2-03-SUMMARY.md, 03.2-04-SUMMARY.md

### Event-scoped OPR is worse than a coin flip early in an event, while still picking winners better than chance
Brier by completed quals: 0.2480 (0), 0.2599 (1-6), 0.2801 (7-12), **0.2937 (13-24)**, 0.2039
(25-48), 0.1718 (49+). A constant 50/50 predictor scores 0.25. Winner accuracy rises monotonically
throughout (0.5737 to 0.7670).

**Impact:** Identified the failure as **calibration, not discrimination** — the rank-deficient fit
produces extreme ratings and therefore overconfident probabilities, which Brier punishes even while
the pick is more often right. The rank checkpoints confirm the mechanism: rank/columns 0.37 at 6
quals, 0.65 at 12, 0.97 at 24, 1.00 at 48 — the accuracy inflection lands exactly where full column
rank arrives.
**Source:** 03.2-04-SUMMARY.md, data/diagnostics/opr-event-scope-2026-08.json

### The phase deliberately shipped a materially weaker baseline
Holdout Brier 0.212 (2025) / 0.221 (2026) against the retired 0.167 / 0.177.

**Impact:** Forced the honesty requirement to be load-bearing rather than decorative — Sigma1's
margin widened because its opponent got weaker, and `docs/models/opr-baseline-change.md` states
that outright ("Event-scoped OPR is the weaker opponent"). Correctness of definition was chosen
over favourability of result.
**Source:** 03.2-03-SUMMARY.md, 03.2-05-SUMMARY.md, 03.2-CONTEXT.md (D-15)

### A schema tightened in a prior phase made older published data unreadable
`HarnessArtifactSchema.parse()` rejected the surviving `reports/tuned-v3/` artifact — the run behind
every published figure — because phase 03.1 made `exclusionCounts.quarantined` required.

**Impact:** The provenance of the published record was briefly unreadable by its own codebase.
Resolved with a narrow passthrough input schema covering only the fields the generator reads,
rather than loosening the production schema.
**Source:** 03.2-01-SUMMARY.md (deviation 2)

### A pre-existing test would have failed against its own plan's required commit
`baselineFingerprint.test.ts` iterated every file in `data/baselines/` asserting the OPR version was
`2.0.0+baseline` — guaranteed to break the moment the event-scoped fingerprint (`3.0.0+baseline`)
was committed.

**Impact:** Caught before the commit rather than after. A test written to assert a universal
property over a directory becomes a tripwire the moment that directory legitimately gains a new
kind of member.
**Source:** 03.2-03-SUMMARY.md (deviation 4)

### Prediction sidecars came out incomplete once and never again
The retired final run wrote `predictions-2024.jsonl` at 0 bytes and never wrote
`predictions-2025.jsonl`, while the metrics artifact was complete and exact for all five seasons.
The event-scoped run wrote all five completely (75-156 MB each).

**Impact:** Diagnosed as a transient I/O fault rather than a systematic defect, which the later
clean run corroborated. It cost the bitwise half of D-13's control on two seasons, and directly
motivated IN-03's hardening — a truncated line must re-throw with context, never be skipped,
because skipping would change the fingerprinted population silently.
**Source:** 03.2-01-SUMMARY.md, 03.2-03-SUMMARY.md, 03.2-REVIEW-FIX.md
