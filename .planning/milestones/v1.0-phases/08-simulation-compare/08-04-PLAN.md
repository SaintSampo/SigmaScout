**The minimum band width is a provable floor, not an observation.** Over 200,000 randomly generated
1000-draw histograms across roster sizes 2 to 41, the minimum `p90 - p10` observed was exactly
`0.800000`, and its argmin was a histogram with all 1000 draws on a single rank. The value falls out
of the estimator directly: when both quantiles land in one bin of mass `m`, the width is `800/m`,
which is minimized at `m = 1000`.

**Raw band extents overflow the plot box at every real event measured.** Using `PLOT_W = 470` and
`x(rank) = ((rank - 1)/(N - 1)) * PLOT_W`:

| Event | N | Rows with p10 below 1 | Rows with p90 above N | Min raw left | Max raw right | Narrowest band |
|---|---|---|---|---|---|---|
| `2023nhgrs` | 39 | 1 | 1 | `-4.94px` | `474.88px` | `9.93px` |
| `2025flta` | 42 | 1 | 1 | `-4.55px` | `474.59px` | `9.17px` |
| `2022ispr` | 17 | 2 | 2 | `-10.58px` | `480.70px` | `44.34px` |

The overflow is `PLOT_W * 0.5 / (N - 1)` per side, so it grows as the roster shrinks: `3.05px` at the
78-team maximum, `6.18px` at 39 teams, `14.69px` at 17 teams and `235px` at a two-team event.

**Axis pitch versus slot width.** Rank pitch is `PLOT_W / (N - 1)` and the histogram slot is
`PLOT_W / N` — the sketch's own two denominators. At 78 teams that is `6.10px` and `6.03px`
respectively, matching UI-SPEC's `~6px per rank position` note; at 39 teams, `12.37px` and `12.05px`.

**The minimum-width floor is not currently binding, and that is stated rather than implied.** Since
the narrowest possible band is `0.8` rank units, its pixel width is `0.8 * PLOT_W / (N - 1)`, which
is `4.88px` at 78 teams — above the ported `2px` floor. After clamping, the tightest reachable case
(a fully locked team whose band is clipped at the left edge) is `2.44px` at 78 teams. `BAND_MIN_W`
therefore becomes binding only above roughly 94 teams, beyond the largest roster the corpus carries.
It is ported anyway, because it costs one comparison and the alternative is a silent deviation from
the validated reference.

## Decisions this plan makes (Claude's Discretion, recorded not assumed)

1. **`simAxis.ts` RE-EXPORTS `PLOT_W` from `apps/web/src/components/team/matchAxis.ts` rather than
   restating `470`, accepting an unusual `lib` -> `components` import direction to do it.** UI-SPEC
   says the value is *reused verbatim from `matchAxis.ts`*, and this repo has already settled what
   that means for this exact constant: `matchAxis.ts`'s own doc comment records that
   `EventMatchTable.tsx` imports it rather than restating it. Restating the digits here would
   recreate precisely the two-numbers-that-must-agree shape this plan exists to eliminate. The
   direction is safe: `matchAxis.ts` is explicitly a pure module with no React import, and its only
   cross-package import is a type-only one that `verbatimModuleSyntax` erases.
   — <reversibility rating="reversible">If the layering is later judged wrong, moving `PLOT_W` into `apps/web/src/lib/` and re-pointing three import specifiers is a pure refactor with both geometry test files already in place to prove it behaviour-preserving.</reversibility>

2. **The mapping function is named `x`, matching UI-SPEC's locked contract character-for-character,
   despite a one-letter module export being poor style in isolation.** UI-SPEC and the outline both
   call it *the single `x(rank, teamCount)` mapping function every rendered position must derive
   from*. A rename would make the contract un-greppable at exactly the moment a reviewer wants to
   check that every mark reads it, and a second exported alias would be two names for one function —
   the same drift shape in a different costume.
   — <reversibility rating="reversible">One export name and its call sites, all inside this plan and 08-14.</reversibility>

3. **`simAxis.ts` exports three derived-position functions (`rankBandExtent`, `medianTickLeft`,
   `histBarExtent`) rather than only `x()` and the constants.** The outline's own 08-14 row demands
   that *every position derives from 08-04's single `x()` function — no second hand-tuned position
   computed anywhere*; leaving the derivations to the render layer would put hand-tuned geometry in
   a component, which is the failure `chart-craft.md` records and which `matchAxis.ts`'s
