produces a **frozen** (honest from-here) prediction set alongside the **stored** (walk-forward

any unplayed qualification match). The cost of that choice is overconfidence, and this plan is where
that cost stops being an adjective and becomes a number.

`docs/models/rewind-overconfidence-gap.md` carrying method, event sample, per-event results,

## Decisions this plan makes (Claude's Discretion, recorded not assumed)

1. **Three start points per event, at qual fractions `0`, `1/3` and `2/3` — not one.** D-01's caption
   fires the moment *any* already-played row is selected, so a single measurement taken at the
   extreme (start at qual 1, the full rewind) would either overstate the typical case if reported as
   "the" number or understate the worst case if reported as a mean. Three points across five events
   gives 15 paired measurements, a mean, and a range — and the marginal cost is near zero because all
   three start points share the one season replay that dominates the runtime.
   — <reversibility rating="reversible">`START_POINT_FRACTIONS` is one exported constant with its own unit test; changing it re-runs the script and rewrites one block.</reversibility>

2. **The frozen predictions are produced INSIDE `onMatchComplete`, at the instant the boundary match
   completes — the captured state is never retained across a later fold-in.** The obvious
   alternative is to stash the state and use it after the run, which would depend on VPR's state
   being deeply immutable. It reads as immutable, but nothing in this repo currently retains a
   *mid-stream* state across further folds — `runSeasons` and `publishSeasons` only ever carry
   *end-of-season* states, and `publish.ts`'s own `onMatchComplete` consumes the state immediately
   into plain numbers. Producing predictions at the callback keeps this script inside the proven
   pattern and makes the mutation question structurally moot rather than answered by inspection.
   — <reversibility rating="reversible">A callback body versus a stashed reference; the surrounding recipe is unchanged either way.</reversibility>

3. **A noise-floor control arm: the STORED set is simulated a second time under a different seed.**
   Without it, `classifyVerdict` would need an invented threshold, and any small measured gap would
   be indistinguishable from Monte Carlo scatter with no way for a reader to tell. Re-running
   identical predictions under a different seed measures exactly that scatter, through the identical
   code path, for the cost of one more 1000-draw simulation per job.
   — <reversibility rating="reversible">One extra simulation call and one extra recorded field.</reversibility>

4. **The doc's ```json rewind-gap``` block is the number's single source of truth, and
   `apps/web/src/lib/rewindGap.ts` is a hand-written mirror guarded by a test rather than a generated
   file.** `docs/publish-budget.md` plus `payloadBudget.test.ts` is this repo's established shape for
   "a committed number that code depends on," and it works because a parser test makes drift loud.
   Generating a `.ts` file from a script would be a new mechanism in this repo for the same
   guarantee. The mirror exists at all because 08-11 renders the figure in the browser and cannot
   parse a markdown doc at runtime — and because the outline's own note is explicit that the caption
   *"must never ship with the placeholder literally visible"* and *"must never ship an invented
   number."*
   — <reversibility rating="reversible">Five constants and one test block; switching to generation later changes how the file is produced, not what it contains.</reversibility>

5. **The script is not given an environment-file flag, and does not read the environment at all.**
   It needs the corpus and the committed promoted-VPR version file, nothing else. `applyPromotedOverrides`
   is imported from `packages/harness/cli.ts` (which carries an entry-point guard and whose own doc
   comment already blesses being imported for a single export) rather than `resolvePublishAlgorithms`
   from `packages/harness/publish.ts`, precisely because the latter's module graph reaches the R2
   client. The `package.json` entry sits with `tune`, `promote`, `fingerprint` and `identifiability`.
   This is a stronger guarantee than a discipline note: a script with no credential in scope cannot
   leak one.
   — <reversibility rating="reversible">An import specifier and a script line.</reversibility>

6. **Only the seasons from the cold-start season through the newest target season are replayed, and
   the final season's stream is truncated immediately after the last target match.** Earlier seasons
   are needed in full for the `carrySeason` boundary thread; nothing after the last target match
   affects any measurement and no further carry is consumed, so the truncation is exact rather than
   an approximation. It is what makes a single-event smoke run (`--events 2022tuis3 --draws 50`)
   finish in seconds instead of minutes, which is the difference between an executor who tests the
   driver and one who only runs it once for real.
   — <reversibility rating="reversible">One `slice` guarded by a season comparison.</reversibility>

7. **Baselines are derived from the corpus's own `redRpEarned`/`blueRpEarned`, not from TBA's
   Ranking Score.** This is deliberately *not* D-12's precedence rule, and the difference is
   recorded rather than glossed: D-12 governs 08-11's browser-side assembly from the published event
