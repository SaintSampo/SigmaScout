<objective>
Build the app's first Web Worker: the message contract, the worker entry module, the Vite bundling
seam, local TypeScript typing that does not touch the shared `lib` array, and the hand-rolled mock
`Worker` every later test in this phase depends on.

**D-07 binding:** the 1000 draws run in a browser Web Worker with live progress during the run and
total elapsed time on completion. CONTEXT states plainly that `apps/web` has no Web Worker today,
so the Vite worker-bundling setup is real work rather than an import. This plan treats it that way.

The worker file itself is deliberately near-empty: `onmessage` -> `runSimulationJob` ->
`postMessage`. All math stays in 08-03's `packages/core/algorithms/simulation/rankSimulation.ts`.
Everything with logic in it — request validation, the chunked progress loop, histogram merging,
error translation — lives in a plain module (`simulationProtocol.ts`) that plain Vitest can call
directly, because jsdom implements no `Worker` API at all and a worker entry file is therefore
close to untestable by construction.

Purpose: this is the Simulation stack's genuine architectural unknown, and it is retired here —
wave 2, two waves before 08-09/08-11/08-13/08-14 build four plans of tab UI on top of it. Its
verification is deliberately tracer-shaped even though 08-01 is the phase tracer: one real
end-to-end round trip, main thread through the `Worker` API through the real protocol through the
real 08-03 core, ordered progress messages, one final result carrying a valid per-team histogram.

Output: six new files under `apps/web/src/workers/` and `apps/web/src/test/`, no new dependency, no

actually emits a worker chunk for this seam.

<planner_decisions>

- **PD-01 — Progress is emitted by calling `simulateRanks` once per chunk of draws with a SHARED
  rng, and summing the returned histograms.** 08-03's signature is
  `simulateRanks(remainingMatches, baselines, draws, rng)` with no progress callback, and the brief
  is explicit that its API is not to be re-decided. Chunking is the only way to satisfy D-07's live
  progress against that signature, and it is exact rather than approximate: each draw resets the
  accumulators from the baselines and consumes the same number of rng values, so 20 calls of 50
  draws sharing one `mulberry32` instance consume the identical rng stream that one call of 1000
  draws would, and per-rank draw counts are additive across chunks by definition. Task 1's
  equivalence test asserts this against the core directly rather than assuming it.
  **If that test fails, do NOT "fix" it by reseeding per chunk or by loosening the assertion** —
  a failure means `simulateRanks` consumes randomness outside its per-draw loop, which is a finding
  about 08-03 that must be reported. The documented fallback is a single `simulateRanks` call with
  two progress messages (`0` and `draws`), and 08-13 told that its bar is coarse.
  **Reversibility: reversible** (an internal loop shape behind a fixed message contract).

- **PD-02 — The logic lives in `simulationProtocol.ts`; `simulation.worker.ts` is a three-statement
  shim.** jsdom implements no `Worker`, so anything inside the worker entry file is unreachable by
  this repo's test environment. RESEARCH's recommendation is to keep the worker file thin enough to
  be untestable-by-design; this plan makes "thin" precise by moving every branch, every bound check
  and the whole progress loop into a plain module that Vitest calls directly, leaving the entry file
  with a `self` cast, an `onmessage` assignment and a `postMessage` forward. The drift risk this
  creates — the entry file wiring the wrong thing — is closed by the type system (the shim's local
  interface is parameterized by `SimulationOutboundMessage`) plus a grep criterion that the file
  contains exactly one `runSimulationJob` call and imports no `simulateRanks`.
  **Reversibility: reversible.**

- **PD-03 — The rng crosses the boundary as a numeric `seed`, not as a function.** `postMessage`
  serializes with the structured clone algorithm, which cannot clone a function; a request carrying
  `rng` would throw `DataCloneError` at runtime in a real browser while typechecking cleanly and
  passing any test whose double forwards by reference. This is precisely the class of bug a mock can
  hide, which is why the mock in this plan clones. The worker constructs `mulberry32(request.seed)`
  itself. **Reversibility: reversible.**

- **PD-04 — `DEFAULT_SIMULATION_SEED` is a fixed constant (`20260830`), and the value is
  arbitrary while its fixity is not.** The same event and the same start match must produce the
  same rank distribution on every run, so that a number a visitor sees change is a change in the
  data rather than an artifact of the draw. This is the client-side half of the same claim 08-03's
  own determinism prohibition makes about the core. 08-13 owns the call site and may not vary the
  seed per run without recording why. **Reversibility: reversible.**

- **PD-05 — The result message carries `computeMs`, and its doc comment forbids it from becoming a
  second user-facing number.** D-07 wants total elapsed time shown on completion, and the figure the
  user should read is the one 08-13 measures on the main thread from Run press to result arrival —
  that is what they actually waited through, including worker construction and message latency.
  `computeMs` is the worker's own `performance.now()` delta around the draw loop, and it exists so
  SC-2's representative measurement in 08-13's SUMMARY can be split into construction-plus-transfer
  versus compute. Publishing both to the user would invite the "which one is real" question this
  project cannot afford to answer with a shrug. **Reversibility: reversible.**

- **PD-06 — Cancellation is `worker.terminate()`; there is no `cancel` message in the protocol.**
  A cancel message would never be read: the draw loop runs synchronously inside the worker thread
  and does not return to its own message queue until it has already finished. `terminate()` kills
  the thread outright and is the only mechanism that works mid-run, so it is the only one offered.
  This makes `terminate()` semantically load-bearing rather than mere hygiene, which is why the mock
  models it and Task 3 asserts it. **Reversibility: reversible.**

- **PD-07 — The mock is installed per test from `src/test/mockWorker.ts`; nothing is added to
  `src/test/setup.ts`.** A global stub would give every `apps/web` test a `Worker` for free, which
  would quietly destroy the enforcement value of Pitfall 1's lazy-construction rule: a component
  that wrongly constructs a Worker on mount would keep passing. Leaving jsdom without a `Worker`
  means such a component fails loudly with `ReferenceError: Worker is not defined`. The
  save-and-restore shape follows this repo's existing `const originalFetch = global.fetch` /
  `global.fetch = originalFetch` convention (`AlgorithmSelect.test.tsx`, `Ribbon.test.tsx`).
  **Reversibility: reversible.**

- **PD-08 — The worker URL uses the `.ts` source extension, which is a deliberate exception to this
  repo's `.js`-extension import convention.** Every local import in `apps/web` is written with a
  `.js` extension (`./routeTree.gen.js`, `../../../../packages/core/.../constants.js`), but
  `new URL("./simulation.worker.ts", import.meta.url)` is a URL literal resolved by Vite against the
  source tree, not a module specifier resolved by TypeScript. Writing `.js` there resolves to a file
  that does not exist. The exception is documented at the call site so a later consistency pass does
  not "fix" it into a broken build. **Reversibility: reversible.**

- **PD-09 — The Vite seam is proven by a hand-run, reverted build probe rather than by a permanent
  CI assertion, and that limitation is stated rather than hidden.** Rollup only bundles modules
  reachable from an entry, and this plan's only consumer (08-13's Run handler) does not exist until
  wave 5 — so at this commit `createSimulationWorker.ts` is not in the module graph and no build can
  emit a worker chunk from it. Task 2 therefore temporarily adds a non-tree-shakeable reference in
  `main.tsx`, builds, confirms `dist/assets/simulation.worker-*.js` appears, reverts, rebuilds and
  confirms it disappears — both outputs quoted in the SUMMARY. This is the same hand-verified
  non-vacuity discipline 08-03 uses for its browser-safety guard. The permanent proof arrives free
  at 08-13, when a real call site enters the graph. **Reversibility: reversible** (the probe is
  reverted; a criterion asserts `main.tsx` is clean at task end).

- **PD-10 — No `checkpoint:decision` in this plan.** `REVERSIBILITY_GATES` is on and only a
  `one-way` rating earns a gate. Every task here creates new files in a directory that does not yet
  exist, adds no dependency, publishes nothing, writes no R2 object, changes no schema and edits no
  existing source file. `git revert` undoes the whole plan completely.

- **PD-11 — This plan is wave 2 and does not wait on 08-05's republish.** UI-SPEC's Data
  Dependencies gate exists so no surface reads `redRpPmf`/`blueRpPmf` off an artifact that does not
  carry them yet. Nothing here fetches an artifact: the worker receives pmf arrays inside a message
  payload the caller assembled, and the tests build their own. The outline records this reading in
  full under "Reading of the Data Dependencies gate (stated, not assumed)"; everything that
  genuinely touches a fetched artifact sits at wave 3 or later.

<threat_model>
ASVS level 1; block on `high`. Kept proportionate: this plan ships client-side plumbing that moves
already-public FRC numbers between two threads in the visitor's own browser. There is no server, no
credential, no storage, no network call and no rendered surface in its path. The surfaces genuinely
worth modelling are untrusted-payload handling at the thread boundary, client resource exhaustion,
and the drift risks that a test double and a near-untestable entry file introduce.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Published R2 artifact → main thread → worker thread | The pmf arrays that reach `simulateRanks` originate as plain JSON fetched from the artifact origin and are **not** re-parsed through a Zod schema in the browser. Their validity rests on 08-02's `.refine(isValidPmf, ...)` at the publish boundary. `runSimulationJob` is the last code that inspects the payload's shape before the draw loop consumes it. |
| Main thread ↔ worker thread (structured clone) | Everything crossing this boundary is cloned, not shared. A non-cloneable value throws `DataCloneError` at runtime with nothing at compile time to catch it, and a test double that forwards by reference would hide exactly that. |
| Visitor's CPU | A single request governs how much work the worker thread performs. An unbounded `draws` or `matches` value is a self-inflicted denial of service on the visitor's own machine. |
| Test double → production Worker | The mock proves the message contract and nothing about concurrency. Treating a green mock test as proof of a runtime property is a claim about something nothing measured. |
