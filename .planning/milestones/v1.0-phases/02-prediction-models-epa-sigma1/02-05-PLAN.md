<objective>
Persist what the run actually produced: every match's prediction from every algorithm with its full component vectors, and every involved team's metrics after every match.

Purpose: SC-4 requires every match in the corpus to have a predicted winner, win probability, and predicted alliance scores for each algorithm, with Sigma1's carrying variance — a claim that only exists if the records exist. D-28's metric snapshots are nearly free inside a loop already running, and they are precisely what Phase 6's metric-history plot and Phase 7's Breakdown tab need. Producing this data is Phase 2; rendering it is Phases 6-7.
Output: The JSONL prediction sidecar, the metric-history sidecar, and Sigma1's three link-mode variants registered in the harness.
</objective>

- Each line parses as JSON and validates against the record schema.
- A record carries `matchKey`, `season`, `eventKey`, `compLevel`, `algorithmId`, `algorithmVersion`, `predictedWinner`, `pRedWin`, `predictedRedScore`, `predictedBlueScore`, `redComponents`, `blueComponents`, `actualWinner`, `actualRedScore`, `actualBlueScore`.

- Lines for one match are contiguous and ordered by the run's algorithm order.
- A writer closed after 5 of 10 intended records leaves a file whose 5 lines all parse — the interrupted-run property.

- The file path is `{outDir}/predictions-{season}.jsonl`.
  </behavior>

  <action>
Create `packages/harness/predictions.ts` following `artifact.ts`'s validate-before-persist discipline exactly. Export `PredictionRecordSchema` (a Zod object per the behavior block) and `PREDICTIONS_SCHEMA_VERSION = 1` with the same "bumped whenever a consumer must know" comment `ARTIFACT_SCHEMA_VERSION` carries.

The writer is streaming, not buffered: export `openPredictionsWriter(outDir, season, secretToScrub?)` returning a handle, `writePredictionLine(handle, record)` which parses the record through the schema, serializes it to a single line, runs the secret-scrub check, and appends it, and `closePredictionsWriter(handle)`. Appending per record rather than serializing a whole season at the end is what makes D-25's interrupted-run property real — a partial file must be partial-but-readable, which a single end-of-run write cannot deliver. Use `mkdirSync(outDir, { recursive: true })` and `join(outDir, ...)` matching `writeArtifact`'s path handling.

Component vectors are the point of this file, not an extra: D-24 chose totals-plus-components over totals-only knowing it costs roughly ten times the size, because a quietly-wrong component is invisible behind a plausible total, and because Phase 7's Breakdown tab eventually renders exactly this. Do not add a totals-only mode.

Variance is optional in the schema and must be *absent* for algorithms that carry none, never present-and-zero. A zero variance is a claim of perfect certainty; an absent one is the truthful statement that this algorithm does not model uncertainty at all.

Run the secret-scrub check on the serialized line before it reaches disk, mirroring `writeArtifact`'s check. RESEARCH.md notes this writer never touches TBA credentials — it reads only the already-ingested read-only corpus — but the discipline applies to every new write path this phase adds, defensively.

Write `predictions.test.ts` covering every behavior bullet, including a round-trip that reads the file back, splits on newlines, and re-validates each line through the schema.

  <behavior>
- After each match, exactly the 6 teams named on that match's two alliances are snapshotted — not every team in state.
- One snapshot set is produced per algorithm per match, so a 3-algorithm run produces 18 rows per match.
- A row carries `matchKey`, `season`, `eventKey`, `algorithmId`, `teamKey`, `matchIndex`, and the team's metrics as component name to `{ value, spread? }`.
- Snapshots are taken after `update`, so a row reflects the state including that match.
- A surrogate on the match is still snapshotted — it appeared in the match, and its metric is a fact about the state even though the match did not update its rating.
- The snapshot call happens inside the existing replay loop; no second pass over the corpus occurs.
- Rows validate against their schema and stream to `{outDir}/metrics-{season}.jsonl`.
  </behavior>
