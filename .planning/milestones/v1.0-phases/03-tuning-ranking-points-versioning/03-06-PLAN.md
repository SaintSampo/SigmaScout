**`packages/harness/fixtures/extract-digest-slice.ts` (new).** A one-shot, committed extraction
script following the same `parseArgs` plus entry-point-guard shape as `identifiability.ts`. It
reads the promoted version's recorded `digest.sliceEventKeys`, pulls those events' played
matches from the local corpus in the season's own chronological order, and writes
`packages/harness/fixtures/digest-slice.json`: an object carrying `{ sliceSeason, sliceEventKeys,
extractedAt, corpusIdentity, matches: [...] }` where each match holds exactly the
`MatchResult` fields the replay needs, `score_breakdown_raw` included verbatim. Nothing is
rounded, reordered, or normalized — the fixture must replay to the identical prediction stream
the corpus produces, and any transformation here is a place that guarantee can silently break.

Keep the fixture bounded: aim for roughly 100-300 matches (2-3 events), which lands in the low
hundreds of kilobytes. State the resulting file size in the script's header comment. This is a
test fixture, not a generated artifact — the failure log's repo-hygiene rule targets outputs
that get regenerated on every run, and this file is regenerated only when a version is promoted
against a new slice. Say that distinction explicitly in the header so a later reader does not
delete it on hygiene grounds.

**`packages/harness/digest.test.ts`.** Restructure the source of matches: if
`data/corpus.sqlite` exists, replay from it (the strongest check — it proves the fixture and
the corpus agree); otherwise, if `packages/harness/fixtures/digest-slice.json` exists and its
`sliceEventKeys` and `sliceSeason` match the version's, replay from the fixture. Only if
NEITHER exists may the test skip, and then with an explicit message naming both. Add an
assertion that runs whenever both sources are present: the corpus-derived match list and the
fixture-derived one are deeply equal, so a stale fixture fails loudly instead of quietly
certifying a slice that no longer matches the corpus.

**`packages/harness/promote.ts`.** After writing a version file, print a reminder line naming
the exact `extract-digest-slice` command for that version's slice, so a promotion that changes
the slice cannot silently leave a stale fixture behind.

**`.github/workflows/test.yml` (new).** Triggers: `push` on any branch and `pull_request` — a
gate that only runs on `main` lets a regression through review, which is where it is cheapest

runtime) and `cache: pnpm`; `pnpm install --frozen-lockfile`; then `pnpm typecheck` and
