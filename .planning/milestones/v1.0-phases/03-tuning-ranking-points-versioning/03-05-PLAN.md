Run D-03's two-stage search for real: a one-at-a-time sensitivity screen that answers "which
knobs are actually live", then a joint search over only the survivors — twice, once with
adaptation on and once with it off, at identical budgets — and promote the winner as a named,
committed version.

Purpose: this is ALGO-04's substance. Plan 03-01 proved the pipeline on one knob; this plan

search logs; one promoted version file in `data/algorithm-versions/`.

cost is roughly 0.9-1.3 ms, so a full 2022-2024 replay of one configuration is on the order of

drives many modules over one shared stream — and run the search with `rpMonteCarloDraws: 0`,
which plan 03-03 proved leaves win probability and predicted scores exactly unchanged.

**`--stage joint`.** Flags: `--seasons` (default `2022-2024`), `--evals <N>` (default 60),
`--seed <N>` (default 42), `--batch <K>` (default 8), `--survivors <path>` (default
`reports/sensitivity-screen.json`), `--adaptation on|off` (default `off`).

Read the survivors from the screen artifact. Generate `--evals` candidate parameter sets with
`mulberry32(seed)`, sampling each surviving parameter uniformly on its declared scale
(uniform in log space for `log`-scaled parameters, so the search does not spend most of its
budget in the top decade) and holding every non-survivor at its default. Reject and resample
candidates failing `isValidParamSet`, counting rejections. Always include the default parameter
set as candidate zero, so the search cannot report a "winner" that never beat doing nothing.
Follow with a coordinate-descent refinement pass over the survivors around the best candidate
(one axis at a time, three points per axis, one sweep), which recovers local structure a
uniform random sample misses at a bounded extra cost.

Set `rpMonteCarloDraws: 0` on every candidate during the search and state why in a comment:
plan 03-03 proved by test that win probability and predicted scores are numerically identical
with draws on or off, so the objective cannot be biased by disabling them, and the promoted set
restores the versioned draw count.

**Objective (D-01).** Mean `brierScore` across the tune seasons for the `combined`
`compLevelView`, minimized. Winner accuracy is computed and recorded for every candidate and
never enters the ranking. State in the header the known risk D-01 accepts: a Brier-steered
search can buy calibration without closing the winner-accuracy gap, and the per-candidate
accuracy column is there so that outcome is visible rather than discovered later.

**Structural holdout blindness (Claude's Discretion, resolved: structural).** Three independent
gates, because one gate is a convention: (1) abort before any work if a requested season is in
`HOLDOUT_SEASONS`; (2) abort if `seasonSplit` labels any requested season anything but `tune`;
(3) after scoring, abort if ANY produced slice has `headlineEligible !== false`. Following
`toLeakProofUpcoming`'s precedent, the optimizer must be UNABLE to read 2025/2026, not merely
expected not to.

**Deterministic tie-break (ALGO-04 adjacency).** Candidates are evaluated in generation order
and compared by objective; on an exact tie the earlier-generated candidate wins. Record every
tie in the log with both candidates' full parameter sets, so an objective that cannot separate
two materially different configurations is visible rather than silently resolved. Re-running the
same search with the same seed must select the same winner — assert it.

**Boundary reporting (ALGO-04 boundary).** For each surviving parameter, flag `atBound: true`
when the winner's value equals its search bound. A winner sitting on a bound means the bound
was wrong, not that the search converged; the log and the SUMMARY must say so rather than
quietly accepting it.

**Empty/singleton survivor handling (ALGO-04 empty).** Zero survivors: skip the joint stage,
record `skipped: "no survivors"`, and report the defaults as the winner. Exactly one survivor:
run a one-dimensional sweep rather than failing or silently widening the space.

**Overfitting guard (Claude's Discretion, resolved: leave-one-season-out over the tune
seasons).** After the pooled winner is chosen on 2022-2024, run three LOSO selections — select
the best candidate from the SAME already-evaluated candidate set using only two tune seasons,
then evaluate that selection on the held-out third TUNE season. Record all three, plus whether
the pooled winner is also the LOSO winner in each fold, plus the per-season Brier spread of the
pooled winner. This costs no new replays (the per-season scores for every candidate are already
in hand) and it directly measures whether the winner is an artifact of one season's noise.
Holdout seasons are never involved: LOSO happens entirely inside 2022-2024.

Write `reports/tune-joint-{adaptation}.json` with every evaluation's parameter set, per-season
Brier and accuracy, objective, rejection count, tie records, `atBound` flags, and the LOSO
block. Every evaluation is logged for the record and NONE of them is a version (D-14).

**`packages/harness/tune.test.ts` (new).** Pure unit tests over the search's own logic, no
corpus: candidate generation with a fixed seed is reproducible and every candidate satisfies
`isValidParamSet`; the default set is always candidate zero; the tie-break selects the
earlier-generated candidate and records the tie; a synthetic survivor list of length 0 produces
the skip path and of length 1 produces a one-dimensional sweep; the objective ignores accuracy
(two synthetic slice sets with identical Brier and different accuracy rank equally); a slice set
containing a holdout-labelled slice makes the guard throw.
  </action>
