## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `event_rankings.team_key` FK failed against real 2024 data — synthetic second-robot team keys have no corpus `teams` row**
- **Found during:** Task 1, running the plan's own required live command `pnpm ingest:rankings --year 2024`
- **Issue:** Some 2024 remote-league events (`2024azrl1`..`5`) report TBA rankings for synthetic second-robot team keys (`frc1165B`, `frc7755B`, `frc1165C`, ...). Confirmed live: `/team/frc1165B` 404s — TBA has no team-detail record for these entities at all, so this corpus's `teams` table (populated only from the real `/teams/{year}/{page}` list) never has a row for them. The plan's literal schema (`team_key TEXT NOT NULL REFERENCES teams(team_key)`) then failed the whole event's upsert with `FOREIGN KEY constraint failed` on the first affected event.
- **Fix:** `ingestSeasonRankingsOnly` now loads the corpus's known team-key set once per season and skips (rather than upserts) a ranking row for any team key not in it, tallying the skip count separately (`unknownTeamCount`) rather than silently dropping it or fabricating a `teams` row — mirrors `ingestSeasonMediaOnly`'s existing 404/"unregistered slot" precedent in the same file. Every OTHER team's `totalTeams` for that event is unaffected (`response.rankings.length`, the true reported pool size, not a count of rows this corpus chose to store).
- **Files modified:** `packages/ingest/cli.ts`
- **Verification:** Full `pnpm ingest:rankings --year 2024` run completed (exit 0): 280/324 events populated, 87 rows skipped for an unregistered team key, 0 corpus rows with `rank < 1 OR total_teams < 1`. Confirmed live via `/team/frc1165B` returning 404 before writing the fix.
- **Committed in:** `9a274711` (Task 1 commit)
