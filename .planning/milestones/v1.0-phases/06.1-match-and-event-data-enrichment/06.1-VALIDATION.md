## Sampling Rate

- **After every task commit:** the extended/new unit test file that task touches (see map below).
- **After every plan wave:** `pnpm test` (full suite), **plus** an explicit
  `pnpm vitest run packages/harness/digest.test.ts` that is confirmed to have *run*, not skipped.
- **Before `/gsd-verify-work`:** full suite green, `digest.test.ts` passing (not skipped), and a
  real `pnpm publish:seasons` run whose output is byte-identical everywhere except the fields this
  phase intentionally adds. Mirrors Phase 6's `docs/publish-budget.md` verification pattern
  ("object count landed exactly on the prior run's ... confirming the new fields changed bytes,
  not object count").
- **Max feedback latency:** quick run must stay under 30s; if it drifts past that, split it.

### Success-criterion → proof mapping

| Success criterion | Proof |
|---|---|
| **1.** No dot stays `unknown` for a played match in a registered-RP season | Component test asserts every `qm` match in a registered season (2022–2026), not `usedFallback`/offseason, yields a fully-resolved `states[]` with zero `unknown` entries |
| **2.** "Rank N of M" from real ranking data | `publish.test.ts` asserts `rank`/`totalTeams` on a `TeamSeasonEventSchema` record trace to the `event_rankings` corpus table for an event with known real TBA rankings |
| **3.** Per-event metric line tiered from a published percentile | `percentiles.test.ts` invariant: a team's **last** history row percentile equals that team's published **season-final** percentile for the same metric |
| **4.** D-15 digest reproducibility holds | `digest.test.ts` passes *unmodified* — it is the proof, not a new test. Research confirmed `computePredictionStreamDigest` hashes only `[matchKey, pRedWin, redScore, blueScore]`, so this phase's additions are outside the digest's input |
