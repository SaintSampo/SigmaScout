## Accomplishments

- `percentileAgainstSortedPool(sortedValues, value)` ranks an arbitrary query value (a mid-season history-row value) against a pre-built season-final sorted pool, via lower-bound binary search plus a forward equal-run scan, reusing `percentileRanks`'s exact `(countStrictlyBelow + 0.5*countEqual)/n*100` formula and `roundTo(..., ROUNDING_RULE.percentile)` call — so a pool member's own percentile agrees EXACTLY (strict `toBe`, not `toBeCloseTo`) with what `percentileRanks` assigns it. Throws `EmptyPoolError` (a named class) for an empty pool rather than returning 0.
- `sortedPoolsByMetric(metricsByTeam, teamKeys)` builds, once per `(algorithm, season)`, an ascending sorted-values array per metric name any team in `teamKeys` has a value for — scoped strictly to `teamKeys` (never `Object.keys(metricsByTeam)`), omitting a metric name entirely when no team in the pool has it (PD-07), never mutating its input.
- `HISTORY_PERCENTILE_METRIC_KEYS` — the three `COMPONENT_GROUP_METRIC_KEYS` values plus `TOTAL_METRIC_KEY`, imported from `packages/core/algorithms/breakdown/index.js` and `packages/core/algorithms/types.js`, never written as string literals — carries PD-06's full measured payload-budget doc comment (304,862-byte artifact, 375,000-byte ceiling, 70,138-byte headroom, ~89,000-byte all-metrics cost vs ~21,000-byte four-name cost).
- `MetricValueSchema.percentile: z.number().min(0).max(100).optional()` added to `metricHistorySchema.ts` — a pre-phase published artifact with no `percentile` key still parses unchanged; an out-of-range value now fails loudly at build time instead of silently dropping a tier box at render time downstream (`tierForPercentile`).
- Confirmed by reading (not modifying) `publish.ts` lines 118-150 that `roundTeamMetricRecord`/`roundMetricHistoryRow` already pass a `percentile` field through unchanged (Phase 6 D-04 work) — no change needed there; that file remains untouched by this plan (`git diff --stat packages/harness/publish.ts` is empty).
- Extended `browserSafeSchemas.test.ts` with a named assertion scoping the Node-builtin import scan to `metricHistorySchema.ts` specifically, so a future Node-only import added there fails at this file's own test rather than surfacing as a confusing browser-bundle failure far from its cause.
