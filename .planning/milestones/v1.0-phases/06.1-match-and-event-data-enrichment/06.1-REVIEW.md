Plan 06.1-08 closes G-06.1-26 (playoff rows rendering bonus-RP dots for a ranking point FRC

file the plan touched, diffed each against `f987d25b`, traced the four call sites the plan claims

trusting the SUMMARY's narration.

**The gate holds on every path I could find.** `isBonusRpCompLevel` (`packages/core/algorithms/sigma1/rp/constants.ts:274-276`)
is the single exported predicate, and all four claimed call sites genuinely call it:

- **Predicted** — `distribution.ts:367`, `rpPmfForMatch`'s non-qualification short-circuit now
  reads `if (!isBonusRpCompLevel(compLevel))`. `grep -rn 'compLevel !== "qm"' packages/core/algorithms/sigma1/rp/distribution.ts`
  returns nothing, confirming the literal was actually replaced, not merely commented around.
- **Actual** — `publish.ts:436`, `actualBonusFlagsForSeason`'s loop body opens with
  `if (!isBonusRpCompLevel(match.compLevel)) continue;`, genuinely the first statement, genuinely
  above the `isRpEligibleEventType`/`hasScoreBreakdown` check at line 437 — PD-17's ABSENCE-not-`null`
  ordering is correct. A playoff match at an offseason event hits this `continue` and never reaches
  the `null`-producing branch.
- **Artifact assembly (the executor's documented Rule-2 deviation)** — `publish.ts:578-582` (predicted
  spread) and `publish.ts:613-614` (actual spread) both gate on `isBonusRpCompLevel(match.compLevel)`
  in addition to their existing presence checks, so `buildTeamSeasonArtifact` itself refuses to
  publish either kind of per-bonus data for a playoff row even when fed a caller-supplied
  `Prediction`/flags map that carries populated values — exactly the shape the new
  `publish.test.ts` invariant (line ~789) deliberately constructs and asserts against with
  `not.toHaveProperty` (not `toBeUndefined`) on all four keys.
- **Client** — `MatchTable.tsx` imports `isBonusRpCompLevel` directly from core (a legitimate
  deep relative import — I resolved it programmatically and it lands on the correct file; the
  precedent `metricKeys.ts` sets for reaching into `packages/core` from `apps/web` holds), threads
  `match.compLevel` into both `PredictedScoreLine` and `ActualScoreLine`, and passes
  `applicable={isBonusRpCompLevel(compLevel)}` to both `BonusRpDots` call sites (`grep -c applicable`
  confirms exactly two). `BonusRpDots.tsx`'s `applicable` prop is `required` in the TypeScript
  interface (no `?`), so a forgetful future call site fails `pnpm typecheck`, not silently.

A repo-wide grep for `compLevel === "qm"` / `compLevel !== "qm"` turns up exactly the two
