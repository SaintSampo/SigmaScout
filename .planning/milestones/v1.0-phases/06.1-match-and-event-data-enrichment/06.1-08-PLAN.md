<assumption_delta_decision>
**Primary noun, before:** `match`. `actualBonusFlagsForSeason` treated per-bonus RP as a property of
any match, deriving flags from each match's raw `score_breakdown` — where the bonus fields exist
structurally on playoff matches but carry no ranking-point meaning.

**Primary noun, after:** `qualification match`. Per-bonus RP is a property of a qualification match
and of nothing else. This was ALREADY the predicted side's model (`rpPmfForMatch` short-circuits on
`compLevel !== "qm"`, and `06.1-RESEARCH.md` line 281 documents the predicted arrays as "omitted
entirely ... when `compLevel !== 'qm'`"). The two sides disagreeing about the noun IS the defect.

**Decision: `promote`.** The narrower noun becomes primary everywhere, expressed as one exported
predicate `isBonusRpCompLevel` that the predicted gate, the actual gate, and the client guard all
call. No `add-alongside`: there is no surviving reader for whom bonus RP is a property of a general
match.

**Why the earlier accept was wrong, recorded so it is not repeated.** Plan 06.1-06's threat register
carries `T-06.1-26 | Repudiation | elimination-match dots | low | accept`, justified as "those dots
stay unknown — today's behaviour, unchanged (PD-13)". The premise was false: plan 06.1-05 had
already made the pipeline publish actual arrays on playoff rows, so "today's behaviour" on the
actual side was earned/missed, not unknown. The disposition was correct given its premise and wrong
given the facts. This plan re-dispositions it to `mitigate`.

**Generalized invariant that prevents silent reintroduction** (Task 3, `publish.test.ts`): over ONE
mixed stream containing a `qm` match and all four playoff comp levels (`ef`/`qf`/`sf`/`f`),
`actualBonusFlagsForSeason(...).has(matchKey)` is true if and only if `compLevel === "qm"`, and the
built artifact's playoff rows carry neither a predicted nor an actual per-bonus key. Written over
the comp-level set rather than over a single `sf` fixture, so adding a comp level or reintroducing
the ungated form fails loudly.
</assumption_delta_decision>
