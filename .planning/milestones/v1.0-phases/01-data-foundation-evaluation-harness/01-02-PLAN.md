<objective>
Prove the entire Phase 1 architecture end-to-end on one real event, through every layer, in one commit:
TBA fetch with conditional requests, Zod validation, quirk-aware normalization, SQLite corpus,
chronological replay with structurally-enforced predict-before-update, OPR producing real predictions,
Brier and winner accuracy, and both output artifacts.

Purpose: This is the tracer. Every remaining plan in this phase expands one layer of this slice
horizontally — more seasons, more quirks, more metrics, more chart types. Proving the spine works before
any of that expansion happens means an architectural dead end surfaces after one commit rather than
after ten. The single most load-bearing piece is the leak guard: the project's failure log names outcome
leakage as a prior failure, and RESEARCH.md Pattern 1 makes it a runtime fact rather than a type-level
convention because a TypeScript type can be bypassed with a cast and a Proxy trap cannot.

This is production code, not a prototype. Everything written here stays. The narrowness is in the
*path* — one event, one algorithm, the happy path plus real error handling on that path — never in the
quality of what sits on it.

Output: A working `pnpm harness --event <key> --algorithm opr` producing a JSON artifact and a
self-contained HTML report, with the leakage guard proven by test.
</objective>

packages/core/algorithms/types.ts defines:
- `UpcomingMatch` — matchKey, eventKey, compLevel ('qm'|'ef'|'qf'|'sf'|'f'), setNumber, matchNumber,
  redTeams (string[]), blueTeams (string[]), redSurrogates (string[]), blueSurrogates (string[]).
  Deliberately carries no score, winner, or ranking-point field at all.
- `MatchResult` — extends UpcomingMatch with winner ('red'|'blue'|'tie'), redScore, blueScore,
  redRpEarned (number|null), blueRpEarned (number|null), hasScoreBreakdown (boolean).
- `Prediction` — winner ('red'|'blue'), pRedWin (number in [0,1]), redScore (number),
  blueScore (number), and an optional variance channel left unpopulated by OPR.
- `AlgorithmModule<S>` — { id: string; version: string; initState(teams: string[]): S;
  predict(state: S, match: UpcomingMatch): Prediction; update(state: S, result: MatchResult): S }.
  Both predict and update are pure: they must not mutate their state argument, because Phase 4 runs this
  same module inside a Cloudflare Worker where state is rehydrated per invocation.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TBA API → ingestion | Untrusted third-party JSON crosses into the corpus |
| `.env` → pipeline process → output artifacts | The API key crosses into memory and must not cross into any written file |
| Corpus / TBA text → generated HTML | Third-party strings cross into a document rendered by a browser |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `packages/ingest/schemas.ts` fetch boundary | medium | mitigate | Every TBA response is parsed through a Zod schema before entering normalization; a parse failure throws and halts rather than coercing defaults into the corpus |
| T-01-02 | Information Disclosure | `packages/harness/report.ts` artifact and report writers | high | mitigate | The API key is a function parameter read from `process.env` in `cli.ts` only, never placed on any object that reaches the writers; an automated assertion checks the serialized artifact does not contain the key value |
| T-01-03 | Tampering | `renderHtmlReport` interpolating TBA-sourced event and team text | low | mitigate | Every interpolated value routes through `escapeHtml`; the report references no off-disk script or stylesheet, so injected markup has no external code to load |
| T-01-04 | Denial of Service | TBA request volume from `tbaClient.ts` | medium | mitigate | Conditional requests via `If-None-Match` mean a repeat run costs a 304, not a payload; the tracer fetches exactly one event. Throttling and full-backfill request accounting land in Plan 03, where bulk volume actually occurs |
| T-01-06 | Repudiation | Harness artifact with no provenance | medium | mitigate | The artifact records schema version, algorithm id and version, event key, and run timestamp, so a published number can be traced back to what produced it |
</threat_model>
