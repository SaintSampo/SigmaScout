<objective>
Close 01-REVIEW WR-05: `pRedWin` is never validated before scoring or binning, so a `NaN` yields a `NaN` Brier score, a negative value crashes `calibrationBins` with a bare `TypeError`, and `winnerAccuracy`'s comparison silently resolves `NaN` to blue.

Purpose: ROADMAP success criterion 3 — "A malformed prediction cannot reach a published number." Per D-05 the check lives where `predict()` returns, not at `scoreSet`/`calibrationBins` entry: Phase 2 writes per-match prediction JSONL sidecars, so a scoring-boundary-only check lets a malformed value reach an artifact on disk before anything notices, and an emission-time error can name the algorithm and match key rather than reporting only that a final score is `NaN`. Per D-06 the harness additionally quarantines and counts, and per D-07 that quarantine is bounded.

Note the deliberate asymmetry recorded in D-09, which this plan must preserve: a single bad `pRedWin` is a per-prediction anomaly and quarantines; a `denom <= 0` in the OPR solver (plan 03.1-03) means shared model state is unrecoverable and aborts the run. Two failure classes, two responses — do not normalize them into one policy.

Output: a dependency-free validity leaf in `packages/core/scoring/`, called from all three `predict()` return sites, plus a fourth counted exclusion branch and a bounded throw in `packages/harness/score.ts`.
</objective>

**Planner discretion exercised in this plan** (CONTEXT.md grants the D-07 threshold value explicitly):
- **Quarantine bound = both an absolute count and a share, with a population floor on the share.** `QUARANTINE_ABSOLUTE_LIMIT = 25`, `QUARANTINE_SHARE_LIMIT = 0.005`, `QUARANTINE_SHARE_MIN_POPULATION = 200`. The run throws when the quarantined count reaches 25, or when the candidate population is at least 200 and the quarantined share exceeds 0.5%. Rationale: D-07's stated risk is a corrupt team state cascading across that team's remaining matches and hollowing out a season, so both an absolute floor and a proportional bound are needed. The absolute limit tolerates a handful of genuine one-off anomalies without failing a season. The share bound catches a cascade inside a small slice (an elimination-only view can be a few hundred matches, where 25 would be most of the population) but is only applied above 200 candidates, because below that a single anomaly is not evidence of a cascade and the absolute limit should govern. The measured population of malformed predictions today is zero, so no currently-published figure is affected.
- **Where the helper lives:** a new dependency-free `packages/core/scoring/predictionValidity.ts`, following exactly the hoisting precedent set by `packages/core/algorithms/breakdown/constants.ts`'s `assertFiniteComponents` (Phase 2's WR-01 resolution) — one implementation shared by every algorithm, rather than three copies that can drift.
