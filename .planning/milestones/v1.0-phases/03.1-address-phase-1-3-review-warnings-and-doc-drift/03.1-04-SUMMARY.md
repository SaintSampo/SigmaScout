## Regression Proofs (success criterion 1)

Each of the three warnings' fix was temporarily reverted, observed to go red, then restored, per the plan's explicit acceptance criteria. None of these reverts were committed — only the pre-fix red output is recorded here.

**WR-01 (D-11):** Commented out the body of `Sigma1ParamsSchema`'s `.check(...)` (`if (true) return;` at its top). Result: all 8 new cross-parameter-invariant test cases in `params.test.ts` and `searchSpace.test.ts` went red — `expect(result.success).toBe(false)` failed with `expected true to be false`, i.e. the schema silently accepted an object it should have rejected. Restored; full suite green again.

Separately, temporarily widened `SIGMA1_SEARCH_SPACE.adaptationMaxFactor`'s bound to `{ min: 0.1, ... }` (below the default `adaptationMinFactor` of 0.25) **and** reverted `planJointCandidates`'s singleton branch to its pre-fix bare-cast form (no `isValidParamSet` filter). Result: the new per-key singleton test for `adaptationMaxFactor` went red (`expect(isValidParamSet(candidate.params)).toBe(true)` → received `false`), and the "reports a real rejected-candidate count" test also went red (`rejectedCandidates` stayed `0`). This proves the per-key coverage test is genuinely load-bearing, not vacuously passing. Both reverts restored; full suite green again.

**WR-02 (D-10):** Removed `selectBestScreenRow`'s empty-list guard, restoring the bare `let bestRow = rows[0]!;`. Observed pre-fix behavior: with an empty `rows` array, `rows[0]!` evaluates to `undefined` at runtime (the `!` is a compile-time-only assertion) and the subsequent `for...of` loop is a no-op, so the function **returns `undefined` without throwing at all** — worse than a bare `TypeError`, a silent wrong value. (In the pre-extraction real code path, this `undefined` would have propagated to `bestRow.value`/`bestRow.brierScore` a few lines later in `runScreenStage`, producing exactly the unhelpful `TypeError: Cannot read properties of undefined (reading 'value')` WR-02 describes.) The new test `throws — rather than returning undefined — on an empty row list` went red (`expected [Function] to throw an error`, received `undefined`). Restored; full suite green again.

**WR-03 (D-12):** Wrote a real (temporary, uncommitted) `sigma1@2.0.0+regression-test-newer.json` into `data/algorithm-versions/` with `provenance.promotedAt: "2099-01-01T00:00:00.000Z"` (genuinely newer than the pinned file's `2026-08-16T20:44:31.101Z`). With the `warnIfNewerPromotedSigma1(...)` call present in `applyPromotedOverrides`, a scratch script confirmed the warning fires (`WARNING [warnIfNewerPromotedSigma1]: a newer promoted "sigma1" version exists — pinned=sigma1@2.0.0+tuned-2026-08.json ... newest=sigma1@2.0.0+regression-test-newer.json ...`). With the call temporarily removed, the same script confirmed the warning **does not** fire (`wiring warning fired: false`) despite the genuinely newer file existing on disk — the red state WR-03 exists to eliminate. Restored the call; deleted the temporary version file (`git status` confirmed `data/algorithm-versions/` was left byte-identical to before this plan, matching D-13's zero-digest-drift requirement).
