### `packages/corpus/db.ts` — `acquireWriteLock` (WR-03 atomic `wx`)

**Current state (lines 48-60, already read in full):**
```typescript
function acquireWriteLock(lockPath: string): void {
  if (existsSync(lockPath)) {
    const ownerPid = Number(readFileSync(lockPath, "utf8").trim());
    if (Number.isFinite(ownerPid) && isProcessAlive(ownerPid)) {
      throw new Error(
        `Corpus is already open for writing by process ${ownerPid} (lock file: ${lockPath}). ` +
          `Wait for it to finish, or delete the lock file if you are certain that process is gone.`
      );
    }
    // Stale lock from a process that no longer exists — reclaim it.
  }
  writeFileSync(lockPath, String(process.pid), "utf8");
}
```
**Pattern to follow (per 01-REVIEW.md's own prescribed fix, verbatim):** Replace the trailing `writeFileSync(lockPath, String(process.pid), "utf8")` with an atomic exclusive-create attempt first (`writeFileSync(lockPath, String(process.pid), { flag: "wx" })` wrapped in `try/catch`), catching `EEXIST` and falling into the existing `existsSync`-based stale-lock-detection branch above. Keep `isProcessAlive`'s alive-check logic unchanged; only the initial existence-then-write race needs to become a single atomic syscall attempt with a catch-and-fallback.
