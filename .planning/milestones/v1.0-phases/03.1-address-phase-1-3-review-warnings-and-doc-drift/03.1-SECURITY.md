# Phase 03.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

Register origin: **authored at plan time** — all five plans (03.1-01 … 03.1-05) carry a parseable
`<threat_model>` block. Verification was therefore mitigation-verification, not retroactive STRIDE.

Scope note, carried forward from Phase 3: this remains an **offline pipeline** — no network-facing
surface, no authentication, no user input, and one secret (`TBA_API_KEY`) read only by the ingest
path. This phase added no new external surface at all: it is a remediation phase that closed nine
pre-existing code-review warnings and reconciled stale planning artifacts. The threats that
genuinely apply are integrity-of-record and availability-of-pipeline threats, not a transplanted
web-application register.

**Register shape:** 27 numbered threats (T-03.1-01 … T-03.1-27) plus one supply-chain threat
(`T-03.1-SC`) declared independently by each of the five plans — 32 register rows across 28
distinct threat IDs. Severity distribution of the numbered threats: 7 high, 11 medium, 9 low.
Dispositions: 19 mitigate, 8 accept (plus `T-03.1-SC`, accept).

## Findings — mitigations narrower than declared

**Three of this phase's own plan-time mitigations were initially implemented more narrowly than
the threat register declared.** All three were caught by the phase's code-review gate — not by the
plans, and not by the 664-test suite, which was green in every case. All three are now complete.
This is recorded rather than smoothed over, because "a guard that looks like it enforces something
but does not actually fire" is a named failure mode for this project.

| Threat | Declared mitigation | What was actually implemented | Closed by |
|--------|--------------------|-------------------------------|-----------|
| T-03.1-11 | "A non-finite residual **or a non-positive `denom`** throws before the ratings loop runs" | The guard tested `denom <= 0`, which is `false` for both `NaN` and `Infinity`. A non-finite `denom` bypassed the throw entirely and corrupted every entry of the ratings vector, aborting one match later and misattributing the failure to an unrelated observation. No test referenced `denom` at all. | `d73d5aba` |
| T-03.1-03 | "Atomic exclusive-create removes the check-then-write window" | True only for the no-lock-file fast path. The stale-lock reclaim path still used a plain non-exclusive `writeFileSync`, so two processes both finding the same crashed-owner lock could both claim it. | `280b1e7e` |
| T-03.1-16 | "every construction path already parses through" the schema | `makeSigma1` — the runtime factory turning a `Sigma1Params` into a live `AlgorithmModule` — never parsed `options.params`. Every current call site happened to validate upstream, so no live path produced a wrong number, but the "unconstructible" guarantee did not hold at that boundary. | `11087dd8` |

Each fix carries a regression test proven red against the pre-fix source.

### Residual risk, recorded not mitigated

**T-03.1-26 is closed but its mitigation is narrow, and the gap is load-bearing.**
`scripts/reviewFrontmatterLint.ts` checks a review file's frontmatter counts against **its own
body**. It never checks a review file's prose against **the code that file describes**. The
declared mitigation — an honest doc comment plus a deferred-ideas entry — is genuinely present, so
the threat is closed on its own terms.

But this phase then demonstrated the gap empirically: plan 03.1-05 wrote resolution records, the
code-review gate subsequently changed three of the same code paths, and the resulting stale prose
was invisible to the linter. It took **three verification rounds** to find it all, each round
surfacing drift the previous round missed. The linter built to prevent doc drift is structurally
incapable of detecting the doc drift this phase committed.

No further mitigation is claimed here. A full cross-artifact checker remains deferred in
`03.1-CONTEXT.md`'s Deferred Ideas.
