<objective>
Close all three open Phase-3 review warnings: WR-01 (`isValidParamSet` is not enforced at every candidate-generation and promotion boundary), WR-02 (`runScreenStage` can crash with an unhelpful `TypeError` if a parameter's entire grid is rejected), and WR-03 (`cli.ts`'s promoted-version path is a hardcoded filename with no staleness signal).

Purpose: ROADMAP success criterion 4's second half — "`isValidParamSet` is enforced at every Sigma1 candidate-generation and promotion boundary." Per D-11 the fix is structural, not a patch of the three known-missing call sites: a `Sigma1Params` violating the cross-parameter invariants must not be constructible in the first place, because patching known sites leaves enforcement a convention a fourth boundary can forget — which is exactly how this gap arose. This mirrors the project's own reasoning for the leak-proof Proxy: a runtime fact, not a convention a cast can bypass. The framing recorded during discussion was moving from "remember to call the check" to "can't not check."

Per D-12 the promoted-version path stays explicitly pinned to a named file and gains a loud warning when a newer version file exists. Globbing for the newest version was rejected because Phase 3's D-13 makes version identity load-bearing for Phase 4 artifacts, the Phase 5 dropdown and the Phase 8 Compare page, so an explicit pin is a reproducibility feature rather than an oversight. Hard-failing on a newer file was also rejected, since deliberately scoring an older version to compare it against a new one is legitimate work.

Per D-13, a committed digest is never hand-edited. Current risk is low — the two known-reachable inputs are already valid — but if anything here legitimately alters a prediction stream, the result is a new promoted version with its own digest and provenance, never an edit to an existing one.

Output: cross-field validation folded into the schema every construction path already parses through, an aborting screen stage with a named error, and a staleness warning on the promoted-version load path.
</objective>
