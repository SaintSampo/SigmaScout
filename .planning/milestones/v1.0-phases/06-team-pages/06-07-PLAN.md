<objective>
Build the season header TEAM-02 and TEAM-03 describe, and the rarity-tier system D-17 puts there.

Purpose: the sketch sessions concluded tiers are redundant on a sorted column — adjacent rows share
a tier by construction — but valuable on component columns, where a single team's components
genuinely span tiers. Their own worked example is a team that is Rare overall but Epic in one
component. A one-team view is where that signal is visible and a sorted table is where it is not,
which is why the tier boxes land here and not on the Teams table.

This plan also makes the global year dropdown page-dependent for the first time (D-18), a
deliberate, scoped exception to Phase 5's rule that its option set never changes per page.

Output: an Overview tab whose header is complete, with tier tokens defined once and applied through
a pure function.

This plan and 06-08 share a wave: plan 06-01 froze the `SeasonHeader` and `EventSectionList` prop
contracts so neither plan touches the other's files or `OverviewTab.tsx`.
</objective>
