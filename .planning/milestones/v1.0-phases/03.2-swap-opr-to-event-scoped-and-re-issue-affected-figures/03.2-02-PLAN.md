<objective>
Rewrite `packages/core/algorithms/opr.ts` so OPR means what TBA means by it: a fit over one event's
qualification matches, solved as a plain minimum-norm pseudo-inverse with no ridge term.

Purpose: this is the one code change in Phase 3.2. Everything downstream — the re-run, the SC-5
diagnostic, the re-issued figures, the SC-3 restatement — is measuring the consequences of this
file. 03.2-RESEARCH.md verified against TBA's own production source
(`src/backend/common/helpers/matchstats_helper.py`) that both locked decisions match reality
exactly: `if match.comp_level != "qm": continue` appears twice, and the solve is a bare
`np.linalg.pinv(M)` with no regularization anywhere in the file.

Output: an event-scoped, quals-only, no-ridge `opr.ts` roughly 250 lines shorter than the current
514, with its surrogate/disqualification policy and its loud-failure discipline intact, proven
end-to-end through the real WalkForwardSimulator path and through one real single-season harness
run before the multi-hour re-run in plan 03.2-03 is attempted.

The rewrite is **subtractive, not a from-scratch numerical implementation**. `ml-matrix`'s
`SingularValueDecomposition.solve()` — already called by the current code — already zeroes singular
values below its own relative threshold before inverting, which is the same convention
`np.linalg.pinv` uses. Do not hand-roll a singular-value cutoff and do not port an epsilon from
another language.
</objective>

  <action>
Rewrite `packages/core/algorithms/opr.ts` as an event-scoped, quals-only, unregularized module.

**State shape (D-01).** Replace the flat `OprState` with a two-level immutable structure:
`OprState = { perEvent: ReadonlyMap<string, PerEventOprState>, lastEventByTeam: ReadonlyMap<string, string> }`, where `PerEventOprState = { observations: readonly OprObservation[], ratings: ReadonlyMap<string, number> }`. Keep `PerEventOprState` module-private; keep `OprState` and `OprObservation` exported. Do NOT reset state when the eventKey changes — `buildSeasonStream` interleaves concurrent regionals in one chronological stream, so a single "current event" pointer would corrupt every simultaneously-running event. Follow epa.ts's immutable-map-swap idiom for BOTH map levels: every update builds a new outer Map with one entry swapped and returns a new `OprState`, never mutating the incoming state.

**Delete (D-03).** Remove the `IncrementalInverse` class, `IncrementalRidgeSolve`, `emptyIncrementalSolve`, `ratingsVectorToMap`, `applyObservation`, and `nextPowerOfTwo` — roughly lines 245-435 of the current file. That machinery exists solely because season pooling at n≈3,700 made a fresh solve cost ~110-420ms; at the corpus-measured ~39 teams per event a direct solve is microseconds. Also remove the `OPR_RIDGE_LAMBDA` export and its doc comment.

**Solve (D-06).** Rename `solveRidgeOpr` to `solveEventOpr` and drop its `lambda` parameter entirely. Inside, the current line that forms the Gram matrix with an added scaled identity becomes a bare `M.transpose().mmul(M)`; the following two lines (`M.transpose().mmul(s)` and `new SingularValueDecomposition(MtM).solve(Mts)`) stay exactly as they are — that call is already the minimum-norm least-squares solution. Keep solving via the normal equations on `M^T M`, NOT via an SVD of the raw design matrix: TBA's `build_Minv_matrix` builds the Gram matrix directly and pseudo-inverts that, and matching it is the whole point. Record in the function's doc comment that this squares the effective condition number and that the squaring is a deliberate fidelity choice, not a defect to be optimized away.

**Update (D-05).** `update(state, result)` returns `state` unchanged — a genuine no-op, the same idiom the current code uses for a degenerate observation — whenever `result.compLevel !== "qm"`. For a qm match: look up (or create) the `PerEventOprState` for `result.eventKey`, build the red and blue observations via the surviving `allianceObservation`, append them to that event's observations, re-solve that event from scratch with `solveEventOpr` over the whole accumulated observation list, and swap the result into a new outer map. Full per-event re-solve on every qm match is the intended implementation — at ~39 teams even hundreds of re-solves per event cost low milliseconds. Do not reintroduce incremental machinery without first measuring that this is a bottleneck.

**Surrogate mean-share scope (planner-resolved design point — implement exactly this).** `currentLeagueMeanPerTeamShare` currently reads season-wide `state.observations`. Feed it **only the observations already accumulated at `result.eventKey`**, with the existing `(result.redScore + result.blueScore) / 2` fallback when that event has none yet. Reading across events here would put cross-event information back into the fit for surrogate-affected alliances, which is exactly what D-02 excludes. The surrogate and disqualification policies themselves are unchanged — `ratingEligibleTeams`, `allianceObservation` and their doc comments (which carry the D-07 and Open-Question-3 reasoning) are preserved verbatim.

**Most-recent-event tracking (D-04).** Maintain `lastEventByTeam` explicitly: on every qm update, set `lastEventByTeam[team] = result.eventKey` for every rating-eligible team on both alliances. Do NOT infer "most recent event" from `perEvent` map insertion order — insertion order records first-seen order, so a team that plays event B (inserted first) and later plays event A (inserted second, but seen earlier in the stream) would resolve to the wrong event. `teamMetrics(state, teams?)` then resolves each requested team through `lastEventByTeam` to its event's ratings map, preserving the existing output shape `result[team] = { [TOTAL_METRIC_KEY]: { value: rating } }` and the existing skip-if-unknown behavior. When `teams` is omitted, return every team in `lastEventByTeam`.

**Predict (D-02, D-05).** `predict()` keeps its current shape — `ratingEligibleTeams` for both alliances, sum of ratings, `logisticWinProbability` on the margin, `assertValidPRedWin` before returning — with one change: each team's rating is looked up from `state.perEvent.get(match.eventKey)?.ratings.get(team) ?? 0`. No comp-level branch is added; playoffs are still predicted and still scored. The `?? 0` is D-02's literal-zero cold start, and the consequence is deliberate: the first qualification match of every event yields a 0-0 predicted score and pRedWin exactly 0.500.

**Finiteness guard (D-03's survival requirement).** After every `solveEventOpr` call and before the result enters state, assert every value in the returned map satisfies `Number.isFinite`. On failure throw with a message naming the eventKey, the offending team, and the observation count, citing 01-REVIEW WR-01 in the adjacent comment the same way the current guard does. Follow the existing loud-throw-never-degrade discipline; do not clamp, substitute, or skip.

**Version (03-CONTEXT D-13's identity scheme).** Bump the module's `version` from `2.0.0+baseline` to `3.0.0+baseline`, keeping the existing comment explaining why `buildArtifact` requires the `{codeVersion}+{paramSetName}` shape and adding one line stating what the major bump signals. A reader of any published artifact must never see one code version standing for two structurally different algorithms.
