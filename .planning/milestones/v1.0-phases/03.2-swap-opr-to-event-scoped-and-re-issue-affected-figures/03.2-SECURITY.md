# Phase 03.2 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

Verified at HEAD `d7109c4e` by `gsd-security-auditor` (ASVS L1, block_on: high). The register
was authored at plan time across all six PLAN files; the audit verified that those mitigations
actually landed, rather than scanning for new threats.

**Phase character.** This is a numerics-and-documentation phase. It introduces no HTTP
endpoints, no user input, no secret handling, and no new packages. The threat surface is
therefore dominated by **integrity and provenance** of committed data artifacts (Tampering,
Repudiation) rather than conventional web threats. The two new scripts are read-only and
guarded at their entry points (`baselineFingerprint.ts:448`, `eventScopeDiagnostic.ts:783`),
so importing either has no I/O side effect.

## Advisories (non-blocking — no threat left open)

**A-01 — T-03.2-13 residual: the silent fallback is unchanged in code.**
The declared mitigation is process-and-artifact based and it is satisfied — the committed
artifact carries `sigma1-adapt @ 2.0.0+tune-joint-on-winner`, not the fallback. But the
underlying mechanism still degrades silently: `packages/harness/cli.ts:263` resolves
`loadSearchWinnerSigma1(...) ?? algorithm` when the gitignored `reports/tune-joint-on.json` is
absent, and the committed test asserts the five algorithm **ids** and the **version** of `opr`
but not that of `sigma1-adapt` (`packages/harness/baselineFingerprint.test.ts:175-191`). A
future re-run in a fresh worktree can regress identically. Cheap hardening:

```ts
expect(parsed.algorithms.find(a => a.id === "sigma1-adapt")?.version)
  .toBe("2.0.0+tune-joint-on-winner");
```

**A-02 — provenance-timestamp divergence, benign but readable-as-wrong.**
`data/diagnostics/opr-event-scope-2026-08.json` names `artifactRunTimestamp:
2026-08-21T18:29:11.904Z` while `data/baselines/opr-event-scoped-2026-08.json` names
`runTimestamp: 2026-08-21T17:48:49.076Z` — both for `reports/event-scoped-v1`. Cause: plan
03.2-04 regenerated the cleaned run directory (documented, `03.2-04-SUMMARY.md:139-144`). All
five seasons' brier/accuracy/scoredCount were confirmed **bit-identical** between the two
artifacts, so the population is genuinely the same and the diagnostic honestly names the
artifact it read. No action required; recorded because a reader comparing the two files could
mistake it for a mismatch.
