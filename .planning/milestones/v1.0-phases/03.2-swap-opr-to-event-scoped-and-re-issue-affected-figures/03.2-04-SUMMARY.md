## Accomplishments

- **Quantified D-02's literal-zero cold start in the project's own units.** Bucket 0 (a team's first qualification match of an event): Brier 0.2480 (n=1105, pooled across 2022-2026) — at the theoretical 0.25 ceiling for an uninformative 0.5 prediction — and `winnerAccuracy: null`, because every single bucket-0 prediction is an exact 0.5 no-call (0 vs 0 rating margin), leaving the accuracy denominator genuinely empty. This is a stronger, more precise finding than "near the base rate": there is no decisive prediction to score at all in bucket 0.
- **Traced the recovery curve through all six buckets:** 0.2480 → 0.2599 (1-6) → 0.2801 (7-12) → 0.2937 (13-24) → 0.2039 (25-48) → 0.1718 (49+), pooled across all five seasons. The curve is not monotonic in the middle buckets (7-12 and 13-24 are noisier/worse than 1-6) — reported as measured, not smoothed.
- **Built the rank-vs-team-count mechanism half** reusing `identifiability.ts`'s own `computeDesignMatrix` (SVD-derived rank/condition number) at checkpoints 0/6/12/24/48/event-end: mean rank rises from 0.0/0.0 (checkpoint 0, 0% full column rank) through 23.7/39.2 (checkpoint 12, 3.6% full rank) to full column rank in 100% of events by checkpoint 48, pooled across 955 non-offseason 2022-2026 events.
- **Documented the normal-equations condition-squaring tradeoff (D-06/Pitfall 2) in the report's own methodology block**, not just a code comment — OPR solves `M^T M` (matching TBA's `build_Minv_matrix`), which squares the effective condition number relative to the raw design matrix, so some of the measured early-event degradation is attributable to that fidelity-preserving numerical choice, not only to true rank deficiency.
- **Built D-09's warm-only cut**, partitioning the pooled headline exactly: `allMatches` (Brier 0.2111, accuracy 0.7294, n=84003 — identical to the reconciliation-proven pooled headline) = `warmOnly` (Brier 0.2024, accuracy 0.7385, n=72427) + `coldOnly` (Brier 0.2651, accuracy 0.6123, n=11576), with the partition-sum invariant asserted in code (`assertWarmCutPartition`), not merely hoped true.
- **Reconciled the bucketed accuracy curve against the artifact's own headline to full floating-point precision**, per season — all five seasons' `matches: true` — proving the six buckets partition exactly the population the headline figures were computed over, not a subtly different one (T-03.2-18).
- **Introduced no cold-start mitigation of any kind** (D-08): `git diff --stat packages/core/` is empty for this plan's entire commit.

## Decisions Made

- **Tasks 1-3 combined into one commit.** All three build the exact same script incrementally, and Task 2's Zod schema (defined once) already requires Task 3's `warmCut` field to validate — a literal per-task commit split would have required temporarily weakening the schema to fake an earlier commit's shape, which is less honest than one commit reflecting how the script was actually built and validated (against the real corpus and run directory, as a whole).
- **`assertWarmCutPartition`'s cold/warm split reads the raw `completedBefore` tag, not bucket-label membership.** Bucket `"7-12"` spans `completedBefore` 7..12 inclusive (half-open per the fixed boundaries), so a record at exactly 12 would be misclassified as cold if the warm cut were derived from bucket membership instead of D-09's literal "at least 12" threshold. Keeping `completedBefore` alongside the bucket tag through the pipeline, rather than discarding it after bucketing, avoided this off-by-one.
- **`poolSlices`/`poolPredictions` pool multiple seasons' already-computed `ScoreSlice`s via weighted-average reconstruction of `scoreSet`'s own formulas** (`squaredErrorSum/count` for Brier, `accuracyCorrect/accuracyDenominator` for winner accuracy), rather than re-running `scoreSet` over a synthetic multi-season population. This is mathematically exact (a standard weighted-mean-of-group-means identity), reuses `aggregateScores`/`scoreSet` for all actual scoring/exclusion logic, and never reimplements the Brier or accuracy formulas.
