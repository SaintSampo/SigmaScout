## Added by quick 261009-r9x (the awards flag and the winner records)

Item 18 is closed. What is left, none of it able to show a team Locked on a slot an award can still take unless stated:

- (a) **Awards listed in several batches after the first judged award with points.** The reservation is released at that first batch (a judged award listed and award points for the event in the rankings). Winners listed later are merged on the tick the list changes, because a changed list passes the gate. Between the first batch and a later Impact listing the flag reads true while Impact is not yet recorded. This is the one remaining window in which a held slot is released early, and it needs TBA to list a judged award WITH its points before it lists Impact at the same event. Not observable in the corpus (ingested after the fact).
- (b) **The live window closing before the ceremony.** The flag stays false and the reservations stay held until the offline republish.
- (c) **No real live district event has exercised any of this.** First observation due at the first 2027 district event.
- (d) **An event with no awards cursor row whose district is quiet may not be asked again while it stays quiet.** Events with a row are asked before the gate on every tick; an event with no row is asked only on a tick that already passed the gate. For an event whose flag still waits and whose playoffs are done, every path through the pass leaves a row (the ETag of a merged list, or a null ETag retry marker after a failed ask), so the one remaining way to get there is a D1 cursor write failing on the same tick an awards ask failed (or on the tick its first list was merged) while the rankings answered 304. The flag stays false in that case, so the reservations stay held. Separately, an event whose flag the offline publisher set true has no row until the first tick that passes the gate, so an award listed for it before then is recorded on that tick and not earlier.
- (e) **Awards or award points that land AFTER the live window of the event closes** wait for the next offline republish, or are never asked for again by the Worker (the existing freshness limit, now covering points too). The flag stays false. Candidate fix: whenever a district passes the gate, also ask awards for artifact events with `playoffsDone` true and `awardsPosted` false that are outside the window, capped per tick.
- (f) **An offline republish from a corpus older than the Worker's live writes overwrites the live flag and the live winner records.** The republish rebuilds `qualifyingAwards` and the state block from the corpus, so a flag the Worker raised and a winner it recorded are lost until the corpus catches up. With the flag back to false the reservations are held again.
- (g) **While the flag waits on points, the published verdicts both consume the slot of a recorded winner and still reserve one for the event.** Conservative: it never publishes a Locked that is not true. Measured by the executor on the synthetic three team district (`packages/harness/districtRankingsMerge.test.ts`, the lock regression describe): the top team reads `locked` after the Winner and Finalist list, `contending` once the Impact winner is recorded with the flag still waiting, and `locked` again when the points arrive. So the PUBLISHED `districtLock` can take a Locked back for that window. No page renders the published `districtLock` or `champLock` status (the Locks tabs compute their own and gate each award on its own event's stage, so they do not flip), which is why this is recorded and not fixed. Candidate fix if the published verdict is ever displayed: an event with a recorded consuming winner at the district tier reserves nothing for it (one Impact per district event), with the champ tier needing its own count against the judged ceilings.
