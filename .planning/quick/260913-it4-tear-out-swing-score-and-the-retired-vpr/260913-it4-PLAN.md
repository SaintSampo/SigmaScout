- Offseason is INCLUDED, as publish:seasons runs it. The season is replayed from a cold start (no warmup).
- It mirrors scripts/measureMatchBandCoverage.ts's main loop exactly:
  - stream = buildSeasonStream(db, season, { includeOffseason: true })
  - [algorithm] = resolvePublishAlgorithms(id)
  - teams = unique roster keys of the stream
  - when usesSigmaScore(id), an onMatchComplete callback records each involved team's TOTAL_METRIC_KEY value into
    a per-matchKey talent map
  - records = new WalkForwardSimulator(stream, corpusColdStartIndex(db)).runAll([algorithm], teams, undefined, onMatchComplete)
  - layer = new SigmaScoutLayer(RP_RULE_MODULES[season], id)
- For each record, in stream order:
  - FIRST call upcoming = layer.enrichUpcoming(record.match, record.prediction). It only reads; it prices the
    match as a not-yet-played match from history so far.
  - THEN call folded = layer.foldPlayed(record.match, record.prediction, talent.get(matchKey)).
- It writes JSONL streams to SCRATCH/label/id.stream.jsonl, one line per match:
  - winner: [matchKey, pRedWin, redScore, blueScore] from record.prediction
  - played-core and upcoming-core: the same four values from folded.prediction and upcoming.prediction
  - played-rp and upcoming-rp: [matchKey, rp]. `rp` is an object holding whichever of the nine fields are present,
    inserted in this fixed order: redRpPmf, blueRpPmf, matchOutcomePmf, redOutcomeRp, blueOutcomeRp,
    redBonusRpPmf, blueBonusRpPmf, redBonusRp, blueBonusRp. It is null when none is present.
  - played-band and upcoming-band: [matchKey, matchBand or null]
- After the loop it writes the presim-rp stream:
  - finalState = records.finalStates.get(id)
  - group the played qualification (compLevel qm) records by eventKey. Iterate event keys in ascending order;
    within an event, keep stream order.
  - roster = the sorted unique team keys across that event's qm matches
  - filler = makeRankingPointFiller(layer.rpAccumulator, RP_RULE_MODULES[season], layer.consistencyByTeam(), roster)
  - if filler is undefined, write [eventKey, null]
  - otherwise, for each of the event's first 12 qm matches, write
    [eventKey, matchKey, rp of filler(match, algorithm.predict(finalState, match))]
- It writes the seed stream as exactly four lines, each a [name, value] pair: consistencyByTeam, sigmaBeliefs,
  sigmaPopulation (null when undefined) and rpVariableBeliefs.
- All JSON goes through one replacer: a Map becomes its key-sorted entry array, a Set becomes a sorted array, a
  typed array becomes a plain array. Floats are written by JSON.stringify unrounded; equal doubles serialize
  identically.
- It writes SCRATCH/label/id.summary.json containing:
  - label, algorithm id and version, season, includeOffseason: true
  - gitHead, from execFileSync git rev-parse HEAD
  - dirtyPackagesPaths: the output of git status --porcelain --untracked-files=no -- packages scripts
  - corpusBytes, from statSync of data/corpus.sqlite
  - playedMatches, elapsedMs
  - seedCounts: the entry count of each seed map
  - per stream: line count, sha256 of the file bytes, and rpBearingLines (lines whose rp or filler object is
    non-null)
- It ends by printing `CAPTURE COMPLETE label=<label> algorithm=<id> matches=<n> elapsedMs=<ms>`.

Subcommand `compare --before <label> --after <label> --expect <identical|rp-off-for-non-sigma> [--algorithms <csv>]`:
- `--algorithms` defaults to opr,epa,spr. Every gate in this plan uses the default except the spr-only
  determinism check.
- It requires a summary for every listed algorithm under both labels.
- It prints INCOMPARABLE and exits 2 when season, includeOffseason, algorithm version or winner line count differ
  between the labels. A changed winner line count means the corpus changed; it is not a regression.
- It prints a WARNING, without failing, for any non-empty dirtyPackagesPaths.
- It hardcodes the Sigma set as {spr}. It does not import repo code, so the compare cannot be bent by the change
  under test.
- For `identical`, every stream's sha256 must match for all three algorithms.
- For `rp-off-for-non-sigma`:
  - all three algorithms: winner, played-core, upcoming-core, played-band and upcoming-band match by sha256
  - spr: additionally played-rp, upcoming-rp, presim-rp and seed match by sha256
  - opr and epa: before rpBearingLines for played-rp and upcoming-rp are both greater than 0; after rpBearingLines
    for played-rp, upcoming-rp and presim-rp are all 0; line counts match; after seedCounts for consistencyByTeam
    and rpVariableBeliefs are 0
- On any sha mismatch it prints the stream name, the first differing line number, and both lines truncated to 300
  characters.
- It prints one PASS or FAIL line per check, then a final `EQUIVALENCE: PASS` or `EQUIVALENCE: FAIL`, and exits 1
  on FAIL.
