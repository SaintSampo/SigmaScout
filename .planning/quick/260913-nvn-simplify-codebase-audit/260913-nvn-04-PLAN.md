## Comment policy (applies to all three tasks)

The question for every comment: would a competent maintainer reading only the current code make a mistake, or lose real time, without this sentence? No: delete it. Yes: keep the smallest form that prevents the mistake, usually one line.

DELETE
- D1 Provenance narration: quick-task ids ("Quick task 260913-jkp:"), phase/plan/task refs ("Phase 4", "plan 09-07 Task 2", "05-05-PLAN.md", "05-RESEARCH.md Pattern 3", "UI-SPEC"), decision/finding ids ("D-15", "F-12", "SC-2", "PD-05") and dates ("(2026-09-09)") when they only record where something came from. If an id is the ONLY pointer to a still-relevant decision, compress to one line that states the reason itself, with at most one pointer (prefer a docs/ path over a planning id).
- D2 History: "used to", "was renamed from", "before X we", "this bullet used to claim", finished cutovers, migrations, renames, fixed-bug war stories, what an earlier version did. Keep only the resulting live constraint, in present tense.
- D3 Deleted features: Sigma1, VPR, BPR as an algorithm, Swing / Swing Score / Swing Factor, spread, GBR, PCM, tune/promote tooling, Rule A tooling, scripts deleted by plan 01. Exception: the name is load-bearing for live code (a frozen artifact field or baseline alias still read, a wire id or R2 prefix still parsed, a CSS token still declared such as `--compare-algo-vpr`); then one line.
- D4 Restating code: what the next line does, parameter names repeated as prose, "returns X" on `getX`, type information already in the signature, empty section banners.
- D5 Essays: a multi-paragraph "why" collapses to 1-3 lines. Measured figures that justify a live constant keep one figure plus one doc pointer; tables, derivations and before/after series go.
- D6 Commented-out code; TODOs about deleted features or finished work.
- D7 Line-number cross references (`publish.ts:3244`): they rot as soon as this task shifts lines. Replace with a symbol name if the pointer is worth keeping, else delete.
- D8 Verification and acceptance narration: "verified verbatim", "grep-proven", "this same task", "Task 1 acceptance", "(not asserted)".
