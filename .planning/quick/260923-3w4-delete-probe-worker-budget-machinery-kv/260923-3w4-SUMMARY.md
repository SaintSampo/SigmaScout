# Delete the probe Worker, the subrequest budget machinery, and KV

The account moved to Cloudflare Workers Paid on 2026-09-22 (30 s CPU per cron tick, 10,000
subrequests per invocation, 1M KV writes/month). Jacob decided on 2026-09-23, on the audit in
`.planning/quick/260923-1tu-workers-paid-rearchitecture-audit-find-c/260923-1tu-FINDINGS.md`
(section 2 items C2, C3, C4 and section 3), to delete everything that existed only to fit the
retired free-plan limits. This task did that, in five commits.

**Net: 32 files changed, 1,104 insertions, 8,512 deletions, about 7,400 lines removed.**

## What changed

### 1. The state-probe Worker is gone (`224d7d84`; the file deletions themselves landed in `94268898`, see the incident note)

`apps/worker/src/stateProbe.ts` (3,562 lines), `apps/worker/test/stateProbe.test.ts` (3,443) and
`apps/worker/wrangler.probe.toml` (47) deleted, along with the `deploy:probe` package script. The
instrument measured milliseconds against a 10 ms CPU budget that is now 30 s; its second job,
proving the deployed bundle can deserialize live D1 rows, is already covered on the live path by
`STATE_SNAPSHOT_SHAPE_VERSION`, the `state-generation-mismatch` suspension, and the
seed-first-deploy-second runbook order.

`docs/worker-operations.md`'s 286-line "Pre-event probe" section is replaced by a note saying the
budget it measured no longer exists and where the records live. Stale cross-references, the
troubleshooting row that told an operator to run it, and the shape-16 bullet instructing a
post-seed probe redeploy are repointed at the live-path checks. `docs/models/rp-layer-config-arms.md`'s
two "What shipped" call sites are relabelled historical.

`mergeTeamSeasonArtifact` and `artifactMerge.ts` are kept; their comments now point forward to the
successor task that reinstates the tick's per-team artifact write (findings item C5).

### 2. The subrequest budget and every deferral path are gone (`4671401d`)

Deleted: `SUBREQUEST_CAP`, `SUBREQUEST_RESERVE`, `usableCap`, `remaining`, the `tryConsume`/`consume`
split, `WriteArtifactResult.deferred`, `ArtifactReadBudgetExhaustedError`,
`estimateEventSubrequestCost`, the three fixed-cost constants, the `status: "deferred"` branches of
`EventOutcome` and `EventPreflightResult`, `TickResult.eventsDeferred`, and
`RunTickDeps.subrequestCap`/`subrequestReserve`.

Kept: `rotate` and `sortEventKeys`, and a plain counter for the tick log's `subrequestsUsed`.
`src/subrequestBudget.ts` is now `src/subrequestCounter.ts`, holding a `SubrequestCounter` whose
`spend()` cannot fail.

Three operations that previously ran only when a subrequest happened to be left over now simply
happen: the etag-only cursor write, the state-block completion read, and the live-roster write. So
does the Phase A claim revert, which previously sat behind `tryConsume` and so could leave
`event_cursor` claiming matches no state ever saw, a latent correctness bug the deletion removes.

### 3. Every open probe window is probed every tick (`68aa843d`)

`MAX_PROBES_PER_TICK` (6) and `PROBE_ROTATION_PERIOD_MS` deleted; `runProbes` no longer rotates.
The 40 windows of 2026-09-20's manifest cost 81 subrequests to probe in full. A newly started
event is discovered on the next cron minute rather than up to `ceil(n/6)` minutes later.
`runProbes` still runs before the algorithms-manifest read and the module build, with the
outage-derived comment intact.

### 4. `teams/{year}` rebuilds on every tick that touched a team (`e1ed9074`)

`GLOBAL_REBUILD_INTERVAL_MS`, the deps override and the `lastGlobalRebuildAtMs` tick-meta field are
gone; `runGlobalRebuild` runs unconditionally and its own `touchedTeamsByAlgorithm.size === 0` early
return keeps the cost at one R2 Class A write per algorithm-season per touched tick. The
event-completion trigger is subsumed. The Teams page is now at most one cron minute behind the
event page. `.planning/todos/pending/teams-list-live-delta-overlay.md` moved to `completed/`.

### 5. KV is gone (`480bfd3d`)

`[[kv_namespaces]]` removed from `wrangler.toml`, `Env.MANIFEST` removed, and `readManifestText` is
now one R2 `get`. Nothing in this repository ever wrote a value to that namespace. The Worker now
touches exactly two stores: D1 (Worker-internal state and cursors) and R2 (published artifacts).
The namespace still exists in the account, unbound; deleting it there is a dashboard action.

### 6. `selectChangedRows`'s justification corrected (in `480bfd3d`)

`apps/worker/src/stateStore.ts` justified the filter by D1's retired free allowance. The function
stays; its real reason is idempotency.

## Incident: a concurrent commit absorbed staged deletions

The executor ran `git rm` on the three probe files and `git add` on its PLAN.md before committing.
The orchestrator's summary commit for quick task 260923-3w9 (`94268898`) then committed the whole
index, sweeping those staged deletions in under the wrong message. No work was lost and the tree is
correct; `224d7d84`'s body names the incident. Rule going forward: in a shared checkout, commit by
pathspec (`git commit -- <paths>`), never by bare `git commit` after `git add`.
