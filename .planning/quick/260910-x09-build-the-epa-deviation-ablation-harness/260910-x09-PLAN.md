<objective>
Build a measurement-only harness that replays EPA under each of its documented divergences from
Statbotics, independently toggleable, and reports what each one costs or gains in winner accuracy
and Brier — per season, pooled, and (for the carryover defect) over each season's onset window.

Purpose: stage 1 of 4. Nobody has ever measured what any individual EPA deviation costs. This is
the backbone for stage 2 (land the carryover fix with evidence), stage 3 (audit whether the
component-map divergence is even real any more), and stage 4 (an interactive methodology surface
where a reader ticks a checkbox per deviation and sees its effect).

Output: `scripts/measureEpaDeviations.ts` + tests, a `measure:epa-deviations` pnpm script, a
stable-keyed `reports/epa-deviation-ablation.json` designed for stage 4's consumption, real
numbers in SUMMARY.md, and doc-only corrections to the stale prose in
`docs/models/epa-divergences.md`.

## Arms ride ONE shared stream, exactly like measureAllianceReconstruction

`WalkForwardSimulator.runAll(algorithms, teams, initialStates)` keys state by `algorithm.id` and
drives every supplied module over one chronological stream, handing each the identical
leak-proof match object. An "arm" is therefore just an `AlgorithmModule` with its own id. Four
arms on one pass per season = 9 stream builds, 36 (season, arm) replays, and any difference
between arms is provably the arm and not the data.

RUNTIME: the nine-season three-algorithm reference run took 476s. Four EPA arms over the same
nine seasons is the same shape; budget 10-25 minutes for the full run and do not add arms
without re-reading this line.

## The arms

| arm id | deviations enabled | shippable | note |
|--------|-------------------|-----------|------|
| `epa` | none | yes | the shipped module BY REFERENCE. The baseline. |
| `epa-carryover-fix` | `carryover-scale-anchor` | yes | lazy per-team rescale on first sight |
| `epa-winprob-season-sd` | `winprob-scale` | NO | season-final SD is outcome leakage |
| `epa-winprob-fixed-sd` | `winprob-scale` | yes | fixed `EPA_FALLBACK_SCORE_SD` denominator |

Every arm is built by spreading the shipped module and overriding named functions:
`{ ...epa, id, predict, update, carrySeason }`. Spreading carries `carryFrom:
"last-official-match"` forward, which is load-bearing — an arm that carried at season-final
would be measuring two changes at once.

## Arm: `epa-carryover-fix` (deviation 1, highest priority)

THE DEFECT. `carryover.ts`'s `epaCarryover` derives `{mean, sd}` from `input.teamTotals` — the
OUTGOING season — at line 228, then uses that same pair for BOTH `normalizedFromPoints` (line
232) and `normalizedToSeasonUnits` (line 242). Every team enters a new season carrying LAST
season's point units. `02-CONTEXT.md` D-16 and `02-RESEARCH.md` record Statbotics' `init.py`
verbatim as converting into the NEW season's point units, so this is a port defect against the
project's own recorded reference, not merely an undocumented placeholder.

THE ARM (do not re-derive the evidence; the harness reproduces it): wrapper state is
`{ inner: EpaState, pending: ReadonlySet<string>, seedMean: number, deferredRescales: number }`.

- `carrySeason(state, boundary)`: capture `seedMean = state.inner.allianceScoreStats.mean`
  BEFORE delegating, call the shipped `epa.carrySeason`, then set `pending` to
  `new Set(next.teamComponents.keys())`. That key set is exactly the carry-worthy teams — the
  shipped `carrySeason` builds a fresh map containing only `carryResult.teamPointTotals`.
- Live new-season scale, WITHOUT re-deriving the DQ fold rule: the shipped `carrySeason` reseeds
  `allianceScoreStats` via `reseedFromPrior(stats, EPA_SCORE_SD_SEED_COUNT)`, so the accumulator
  after a boundary is exactly `EPA_SCORE_SD_SEED_COUNT` pseudo-observations at `seedMean` plus
  the new season's own real folds. Recover the clean season mean by unwinding that seed:
  `(stats.mean * stats.count - seedMean * EPA_SCORE_SD_SEED_COUNT) / (stats.count -
  EPA_SCORE_SD_SEED_COUNT)`. This reads only exported values and never re-implements which
  alliance scores EPA chooses to fold.
- MATERIALIZATION, lazily, per team, on first sight in the new season: `ratio = cleanSeasonMean /
  seedMean`, and every component value for that team is multiplied by `ratio`. Guard with an
  exported `EPA_CARRY_RESCALE_MIN_OBS = 100` (alliance scores past the seed); below it use
  `ratio = 1` and increment `deferredRescales`, which the run prints and the artifact carries —
  the honest cost of being walk-forward-legal, reported rather than hidden.
- `predict` materializes TRANSIENTLY (build a temp inner state for this match's teams, delegate,
  discard); `update` materializes PERMANENTLY then delegates and drops those teams from
  `pending`. Both read the pre-update accumulator, so the two agree by construction.
- LABEL, in the artifact and in every printed line: `approximation:
  "closest-walk-forward-legal"`. Statbotics runs offline and simply knows the season scale; that
  is not walk-forward reachable. This arm is never described as identical to Statbotics.

## Arms: `epa-winprob-*` (deviation 4)

Both override `predict` only: delegate to the shipped `predict`, then recompute
`pRedWin = 1 / (1 + exp(-(redScore - blueScore) / scale))` with a different `scale`, and
re-derive `winner` with the same `pRedWin >= 0.5` convention `epa.predict` uses. `scale` is
`sd / (-EPA_K * Math.LN10)` in both, differing only in `sd`:

- `epa-winprob-season-sd`: the season's population SD of every alliance score in that season's
  stream, computed in a cheap pre-pass over `buildSeasonStream`'s output before `runAll`. This
  is Statbotics' literal `year_obj.score_sd` and it is OUTCOME LEAKAGE — it is a reference bound,
  `shippable: false`, and the printed line says so.
- `epa-winprob-fixed-sd`: `EPA_FALLBACK_SCORE_SD` always.

PRE-REGISTERED INVARIANT: a scale on the logistic cannot change `sign(margin)`, so both arms'
winner accuracy MUST equal baseline's to full precision in every season. The run ASSERTS this and
throws naming the season if it fails — a wrapper that changed something it should not have is the
only way this can break, so the assertion is the arm's own self-test. Brier is expected to move,
which is exactly the thing stage 4's UI teaches: accuracy is blind to calibration.

## Artifact design — the stage-4 contract

Path `reports/epa-deviation-ablation.json`, one stable path, overwritten per run.

DECISION, stated because the task asked for it: stage 1 measures INDIVIDUAL deviations only —
arms of size 0 and 1. The SCHEMA supports arms of any size (`arm.deviations` is an array), so a
later stage can add combination arms without a schema change, and stage 4's UI answers a ticked
set by looking for an arm whose `deviations` match exactly and rendering "this combination has
not been measured" when none does. It must never SUM individual effects: the deviations are not
additive (the carryover fix changes the ratings the win-probability scale then divides), so
`notes.additive` is `false` and `notes.combinationsMeasured` is `[]`. Combinatorial cost, for the
record: all-subsets of k deviations is 2^k arms — 4 measurable deviations is 16 arms and roughly
4x this run's wall clock, 6 would be 64 arms and an overnight job.

Top-level shape (stable keys):

    schemaVersion, generatedAt, generator, corpusPath, seasons, streamPopulation,
    scorer: { module, tiesCountedInBrier: true, compLevelView },
    deviations: [ { id, title, class, status, shippable, predictionAffecting, docSection,
                    summary, reason, approximation, priorMeasurement } ],
    arms:       [ { id, label, deviations: [], isBaseline, shippable, unshippableReason } ],
    rows:       [ { armId, scope, season, winnerAccuracy, brier, scoredCount, tieCount,
                    noCallCount, candidateCount, eventCount } ],
    contrasts:  [ { armId, baselineArmId, scope, season, metric, pointEstimate, standardError,
                    percentile: { lower, upper }, eventCount, matchCount, verdict } ],
    notes:      { additive, combinationsMeasured, combinatorialCost, deferredRescales },
    census:     { ... }

`scope` is `"season" | "pooled" | "onset"`. Sign conventions, documented in the file's own
`notes` AND in the script header: for `metric: "brier"` a NEGATIVE `pointEstimate` means the arm
is BETTER; for `metric: "winnerAccuracy"` a POSITIVE `pointEstimate` means the arm is BETTER.

## Scoring — the published scorer, pinned to the local pairing filter

Headline per-(arm, season) numbers come from `aggregateScores` (packages/harness/score.ts) with
`selectedOnSeasons: ELIGIBILITY_NOT_CLAIMED` and `corpusSeasons: seasons`, reading the
`combined` compLevelView slice. That is the PUBLISHED scorer and its Brier population INCLUDES
TIES — a hand-rolled Brier here would invent a regression of roughly the size the real effect is.

Paired contrasts need per-match rows, which `aggregateScores` does not return, so the script
mirrors its exclusion ladder in one local predicate — offseason, then surrogate-affected, then
cold start, then missing result, then invalid `pRedWin`, IN THAT ORDER — and then ASSERTS that
the local predicate's per-(arm, season) survivor count equals `aggregateScores`' own
`scoredCount` for the combined view, throwing if they ever disagree. That assertion is what stops
the two populations drifting apart silently.

Per-match terms reuse `outcomeTarget` and `accuracyCall` from `packages/core/scoring/brier.ts` —
never a second transcription of the tie convention. Paired unit per match:
`{ eventKey, matchKey, diff }` where `diff` is `brier_arm - brier_baseline`, or
`accuracyCall_arm - accuracyCall_baseline` as 0/1 with ties (`accuracyCall` returning null)
dropped from the accuracy pairing entirely. Intervals via `eventBlockedBootstrap(units, mean)`,
with `eventCount` printed beside every one so a small-sample claim is visibly small-sample.

`onset` scope = the first `ONSET_MATCH_COUNT = 500` scorable matches of each season after a
boundary, pooled across boundaries. This is the window the already-measured carryover evidence
lives in (2018 to 2019's 0.19x scale collapse, +103 points per alliance over the first 500 base
matches of a 55-point game), so the harness reproduces that finding rather than only restating
it. Onset rows use `scoreSet` over the same scorable set the pinned local predicate produces.

## Stream and season set

`buildSeasonStream(db, season, { includeOffseason: true })`, matching production's
`--include-offseason`, with `isOffseason` derived from `selectEventMeta(db, season)` exactly as
`publish.ts` does around line 2199. Season-boundary threading copies
`measureAllianceReconstruction.ts`'s proven block verbatim: `seasonBoundaryFor(seasons, index)`
