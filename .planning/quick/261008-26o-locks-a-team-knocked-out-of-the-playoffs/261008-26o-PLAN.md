## The settled rule (decided by the planner, from CONTEXT's locked decisions)

`settledPlayoffPoints` is ONE exported pure function in districtLedgerRows.ts, called once per (team, event) in `buildTeam`, at the pass's own tier. Inputs: season, tier, teamKey, the position stage `final`, `elimFinalAtNow` (= `derived.final.elim`, the event's own state block), the artifact's `entry.earned`, the team's `AllianceBracketMilestone` from `playoffMilestoneByTeam`, and the event's `alliedTeams`. Returns `number | undefined`:

1. `final.elim` true: undefined (the shipped final path already prints TBA's number).
2. milestone kind `decided`: settled.
3. `final.alliance` true AND `alliedTeams` present AND the team not in it: settled (unpicked).
4. Otherwise undefined (finalists, `alive`, `topFour`, selection open, no real alliance list).

The settled VALUE is `entry.earned.elim` when `elimFinalAtNow` and `entry.earned` exists (TBA's published row with the playoffs final, which is every rewound stop over a finished event), otherwise `playoffPoints(season, tier, placement)` for case 2 and 0 for case 3. This is the one place a derived value may print, because a decided placement is a bracket fact, unlike a derived qualification rank; state that beside the existing qual comment and keep that comment.

Floor formula, both status modules, for a row or source carrying `settledElim` while its stage's `elim` is open: subtract the artifact's earned `elim` (0 where TBA has no row), add `settledElim`, add NO elim ceiling. One formula covers both cases CONTEXT asks to be explicit about: rewound over a finished event it nets to zero; live mid playoffs it adds points `pointTotal` may not carry yet.
