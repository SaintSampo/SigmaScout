# Quick task 260910-sz9 — `measureSwingSkill.ts`

Implements **R1** from `.planning/todos/pending/swing-score-audit.md`.

## Why

Audit finding **F1**: the only skill number anyone quotes for Swing Factor is `r ≈ 0.59`, and that is
a **ceiling** swept against the **pre-centring, about-zero** estimator (`sigma1/swing.ts`, quick task
260903-750). Centring, the two-observation rule, the demo/full-DQ exemptions and the collapse onto
West's incremental form all landed afterwards. The shipped estimator's own skill has never been
measured, and `scripts/` holds no harness that could measure it.

Swing is load-bearing for two surfaces (the team tile/column and every match band on the site), so
this is a published number with no evaluation harness — the failure the project's log names as its
original sin. R2–R5 of the audit are all unactionable until there is a baseline to beat.

## What gets built

One script plus one test file plus one package.json entry. **No production code changes** — this
measures the shipped estimator, it does not alter it.

## Method

Drive a `SwingFactorAccumulator` by hand over a chronological season stream, reading the estimate
**before** folding each match — the same predict-before-update discipline `SigmaScoutLayer.foldPlayed`
uses, which is what makes the pairing walk-forward rather than hindsight.

Per team, per match, when that team already has a Swing Factor (≥2 prior observations):

```
dev          = (actualAllianceScore − predictedAllianceScore) / rosterSize
runningMean   = belief.mean                     // recency-weighted, matches 1..N−1
centredDev    = dev − runningMean                // what Swing actually claims to predict
swing         = accumulator.swingFor(team)       // matches 1..N−1
```

Record `(swing, centredDev, dev)`, then `accumulator.foldMatch(match, prediction)`.

**Observation gating mirrors the estimator exactly.** The same `isFullyDemoAlliance` and
`isFullyDqZeroScoreAlliance` predicates `foldMatch` applies are applied to *recording* too, so the
measurement population is identical to the population the estimator learns from. Measuring on rows
the estimator never sees would be scoring it on data it was denied.

### Outputs, per (algorithm, season) and pooled

1. **Skill — correlation against the ceiling.**
   Pearson and Spearman r between `swing` and `|centredDev|`. Also Pearson against `|dev|`
   (uncentred) and against **signed** `dev`.
   The signed figure is a control: a spread estimator cannot predict direction, so a value near 0 is
   the expected, correct result and a large one would mean something is wrong with the pairing.
   The `r ≈ 0.59` ceiling's stated target ("a team's actual deviation") is **ambiguous** between
   signed and absolute; only the absolute reading is answerable by a spread estimator, so the script
   prints every variant rather than silently picking one and comparing it to a number that may have
   meant the other.

2. **Calibration by swing decile.** Per decile: n, mean swing, realized RMS `centredDev`, the ratio
   between them, and coverage (`P(|centredDev| ≤ swing)`). A flat ratio across deciles means the
   estimator ranks teams correctly; a ratio near 1.92 means the *scale* is right. Divergence at the
   ends is the shrinkage case R2 predicts.

3. **Coverage against the σ claim.** Pooled `P(|centredDev| ≤ swing)`, against the 68.3% that
   "one standard deviation" implies (audit finding F6), plus the scale that *would* make it 68.3% —
   per algorithm, which is the number R5 needs.

4. **Baseline and oracle bracket.** Gaussian negative log-likelihood of `centredDev` under
   `σ̂ = swing / SWING_FACTOR_SCALE`, lower better, against two reference points:
   - **population-constant baseline** — `σ̂` = walk-forward pooled RMS of every centred deviation seen
     so far, one number carrying no per-team information. This is the "better than nothing" bar.
   - **per-team hindsight oracle** — `σ̂` = that team's own full-season RMS centred deviation.
     Uses the future, so it is **a bound, not a candidate**, and is labelled as such in the output.

   Reported as a skill score (`NLL_baseline − NLL_shipped`, positive = the estimator earns its
   complexity) and as the fraction of the baseline→oracle gap the estimator closes.

### Honesty notes the script must print, not bury

- **n is team-matches, not independent observations.** Even-split hands all three teammates the
  identical deviation (audit finding F2), so each match contributes up to 6 rows sharing 2 values.
  Confidence intervals from a naive n would be roughly √3 too tight, so the script prints the match
  count alongside the row count and states this rather than implying independence.
- Which seasons, which algorithm versions (`id@version`, post-promotion), and whether offseason was
  included — all echoed in the header so a pasted result is self-describing.

## CLI

```
npx tsx scripts/measureSwingSkill.ts [--seasons 2024-2026] [--algorithms opr,epa,bpr] [--include-offseason]
pnpm measure:swing-skill
```

Defaults:
- `--seasons 2024-2026` — deliberately the same span the `r ≈ 0.59` ceiling was swept over, so the
  headline comparison is apples-to-apples. Wider spans are available via the flag.
- `--algorithms` unset → `resolvePublishAlgorithms(undefined)`, i.e. all of `PUBLISHED_ALGORITHM_IDS`
  with promoted parameter overrides applied, so this measures what the site actually ships.
- offseason **excluded** by default, matching the site's official-only scoping.

Read-only corpus (`openCorpusReadOnly`), corpus-global cold-start index (`corpusColdStartIndex`) so
predictions match the published pipeline's. **No network.**

## Tasks

1. `scripts/measureSwingSkill.ts` — CLI parsing, the walk-forward measurement loop, the three
   estimators, and the report.
2. `scripts/measureSwingSkill.test.ts` — unit tests for the pure helpers: Pearson, Spearman
   (including a tied-rank case), Gaussian NLL, decile bucketing, and the running-RMS baseline.
3. `package.json` — add the `measure:swing-skill` script.
4. Run it and record the measured result in the SUMMARY, and add the achieved-skill numbers to the
   audit doc so F1 stops being an open gap.

## Verification

- `npx vitest run scripts/measureSwingSkill.test.ts` green (invoke vitest directly, never through
  `timeout … pnpm`, per the known false-green trap).
- The script runs end to end against the real corpus and prints non-degenerate n.
- The signed-deviation control correlation comes out near 0 — if it does not, the walk-forward
  pairing is wrong and the run is not to be believed.
- Root typecheck clean, plus the `apps/web` tsconfig (root `tsc --noEmit` alone does not cover it).
