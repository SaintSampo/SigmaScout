<objective>
Add one minimal progress bar to the Locks controls card, on both the District Locks and Champ Locks tabs, shown only while the tab is waiting on its per event simulation (Jacob, 2026-10-07: "add a minimal progress bar for when the simulation is running").

Purpose: today a Locks tab that is still simulating looks the same as one that has finished, so the visitor cannot tell whether the cutoff and the open cells are about to change. The bar says "working" and, while the run is in flight, how far along it is.

Output: a pure derivation module (`ledgerRunProgress.ts`), two copy entries, a `.locks-progress*` CSS block, a `progress` prop on `ControlsCard`, wiring in both tabs, and unit, component, CSS contract, copy and integration tests.

Every locked decision maps to a task: D-01 (where, both tabs, renders only while `artifacts.isLoading || data.runPending`) Tasks 1 and 2; D-02 (determinate vs indeterminate, pure type and function) Task 1, pinned in Task 2; D-03 (look: 4px, rounded, theme tokens, sweep keyframe, reduced motion, plain class strings) Task 1, CSS contract in Task 2; D-04 (accessibility) Task 1, pinned in Task 2; D-05 (tests a to d) Tasks 1 and 2; D-06 (out of scope) honoured by both tasks, which edit none of the excluded files.

The tracer (Task 1) touches six files, each a small additive edit (a ~40 line pure module, two copy entries, a ~45 line CSS block, one prop plus a small component, a one call wiring, one integration describe). Splitting it would leave a bar in the DOM with no styling or no caller, which is not production quality.
