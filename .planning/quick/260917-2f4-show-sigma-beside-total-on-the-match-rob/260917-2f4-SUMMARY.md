# 260917-2f4: Sigma displays anywhere Total does — the last two surfaces

## Outcome

Jacob: "for SPR, Sigma should be stored and displayed anywhere Total is." An audit found
**storage already complete** — every artifact family carries the `sigma` metric key, and the live
Worker carries it forward — and all but two display sites already rendering the joined
`TotalSigmaValue` pill (shipped 2026-09-13, 260913-jkp). Those two now render it:

1. **Match page robot grid** (`MatchRobotGrid.tsx`) — the per-robot Total cell.
2. **Team page event sections** (`EventSection.tsx`) — the end-of-event Total tile.

**No publisher, schema or Worker change, and no republish.** The change ships with the next web
deploy.

## Surfaces that needed nothing

Teams list, team-page header tile, event Insights, event Breakdown, event Alliances (picks, backup
and Combined Total), and the metric-history chart's Total ± Sigma band all already render it.

Qualifications, Playoffs, Simulation, compare, districts and home render **no per-team Total at
all** — their match rows carry the Match Band, which is the match-level quantity, not a per-team
Sigma. "Anywhere Total is" therefore excludes them.

## Decisions

- **Gated on data presence, never on algorithm id** — with no sigma key the render is byte-identical
  to the previous `MetricValue`, pinned by an `outerHTML` equality test on both surfaces.
- **The Sigma half renders untiered here.** A per-match sigma row carries no percentile by design
  (a per-match ranking pool has no meaning), and `TotalSigmaValue` already handles a tier-less sigma.
  `neutral: true` was rejected — it means a three-team band, which this is not.
- **Both surfaces read their own metricHistory row**, so the Total and the Sigma share one instant.
  Season-final Sigma from `seasonStats` was deliberately not used: it would pair an as-of-then value
  with a whole-season ±.
- `spread` is read nowhere; a test asserts the printed ± is the sigma even when a spread is present
  on the same fixture.

## Finding, flagged not fixed

other axis there, so both quantities are present, but there is no value cell to join — adding a ±
would be a chart-design question (error bars? opacity?), not this change.
