# Predicted cutoff replaces the line — plan

Both Locks tabs print a number at the top and draw a dashed rule on every grand
total histogram. Today those two are different quantities, and neither of them
sits between the In range and the Out of range teams. This replaces both with
**one** computed value: the midpoint of the boundary pair, carrying a likely
range taken from the simulated line the advancement run already has the material
for but currently throws away.

**Untouched, by instruction:** `packages/core/districts/locks.ts`, the tenets and
`measure:ledger-tenets`, and every status verdict. The cutoff is DERIVED from the
ranking the statuses already produce; it moves no chip.

**Worktrees are OFF** — work happens on the main tree, staged by explicit path.
Run vitest from the **repo root** (295 files; `apps/web` alone is far fewer and an
8 day red CI once hid in that gap). The root `tsc --noEmit` misses `apps/web`, so
all four typechecks run. The executor's sandbox has no network: the live e2e run
and the deploy are left for the orchestrator, and the SUMMARY text is **returned
to the orchestrator**, not written.

Read `.claude/skills/sketch-findings-sigmascout/SKILL.md` before touching any
rendered string: a percentile range is written "likely a–b" with the en dash and
never a plus minus.

Run against `data/fixtures/phase10/district-2026pnw.json` with the real
`buildDistrictLedgerRows`, `buildChampLedgerRows`, the two status modules and
`pointsRaceSlots`, at a position where all nine events are stamped all final. So

**Champ tab.** `cmpSlots` 21, 8 award qualifiers, `pointsSlots` **13**, pool 118.
Pool ranks 11 to 15 by median projection: 190, 186, **182**, **182**, 174. The
boundary pair is 182 and 182, so the midpoint is **182**, which is exactly
`insights.cmpCutLinePoints` and exactly the number the tab prints today. Jacob's
pin holds on this tab without qualification.

**District tab.** `dcmpSlots` 50, 8 award qualifiers, `reservedSlots` 0,
`pointsSlots` **42**, pool 118. Pool ranks 39 to 44 by median projection: 62, 61,
61, **60**, **57**, 56. The boundary pair is 60 and 57, so the midpoint is 58.5,
which rounds to **59**.

**The district pin of 82 is not reachable, and the reason is a tier mismatch
rather than a rule choice.** `insights.dcmpCutLinePoints` is 82 because it ranks
the artifact's all tier `pointTotal`, which includes each team's District
Championship points; in that ordering pool rank 42 is 82 and rank 43 is 65, so
even a midpoint taken there would be 74. The District Locks tab's grand total is
the **district tier only** total by construction (`districtTierEvents` drops every
dcmp tier row, and that is the tab's whole subject), and in that ordering the
published 82 has no counterpart at all. The tab does not print 82 today either:
its current stat line reads **56**, the 50th highest unnarrowed earned district
total, and its own In range cut line is 60.

So this plan pins the district tab's all final cutoff at **59** and pins, in the
same test, that it is deliberately NOT `insights.dcmpCutLinePoints`, with the
tier mismatch recorded as the reason. The champ tab keeps the 182 pin against
`insights.cmpCutLinePoints`. **This is the one departure from the locked
decisions and the orchestrator must surface it before execution starts.**

## The rule, stated once

Let the pool be `pointsRaceSlots(<the tab's own sorted team keys>, capacity,
{awardQualified, prequalified}, reservedSlots).poolKeys` — the same narrowing the
verdicts beside it used — and let `n` be that call's `pointsSlots`, the slots left
for points once the award qualifiers have taken theirs.

- Capacity is null → **capacity unknown**, and the wording stays "Capacity not
  published".
- `n` is 0, or the pool holds `n` teams or fewer → **absent**. There is no first
  team Out of range, so there is nothing between two groups to sit between.
- Otherwise the boundary pair is the median predicted grand total of pool rank
  `n` (the last team In range) and of pool rank `n + 1` (the first team Out of
  range), and the cutoff is their midpoint, rounded to a whole number.
- Every pool team has no open category → **final**: the same arithmetic, printed
  without the tilde and without a range.

The strict between property follows and is what the test pins: every In range
team's median is at or above the cutoff and every Out of range team's is at or
below it, strictly between whenever the pair differs and equal to both when it
ties. It holds under BOTH tabs' In range rules — the district tab's `>=` cut line
and the champ tab's pool rank — because the tab's sorted order is by median
projection, so rank order and value order are the same order.
