# Quick Task 261007-3g2: Locks page rewind, per-round playoff stops - Context

**Gathered:** 2026-10-07
**Status:** Ready for planning

<domain>
## Task Boundary

The Locks milestone picker (District Locks and Champ Locks tabs) offers eight stops per event:
Schedule, Quals 1/4, 1/2, 3/4, Quals done, Alliances done, Playoffs done, Awards done. Inside
the playoffs there is nothing between "Alliances done" and "Playoffs done", so a reader cannot
see how each alliance's playoff points locked in through the double-elimination bracket.

Replace the single Playoffs stop with six: Round 1, Round 2, Round 3, Round 4, Round 5, Finals.
A rewound view at a round stop prices the bracket from the sets already played at that stop
(real results for played sets, simulated for the rest) and shows the ledger's locked ranges
as they stood then.

</domain>

<decisions>
## Implementation Decisions (Jacob, 2026-10-07)

### The stops
- Six playoff stops, named with FIRST's own round names: Round 1, Round 2, Round 3, Round 4,
  Round 5, Finals. Thirteen stops per event in total.
- Round 1 is included even though it moves no lock (a list starting at Round 2 reads like a gap,
  and Round 1 is the first stop priced against a real bracket rather than seeds).
- Finals means the END OF THE SERIES (whichever of game 2 or game 3 clinched it). It is the
  existing Playoffs stop renamed: same `playoffsDone` fact, same `<eventKey>:playoffs` at id, so
  every shared link keeps working.
- Round to TBA set mapping (`comp_level = sf`, `set_number`): Round 1 = sets 1 to 4,
  Round 2 = sets 5 to 8, Round 3 = sets 9 and 10, Round 4 = sets 11 and 12, Round 5 = set 13.
  Finals = `comp_level = f`. This is `BRACKET_SETS` in `packages/core/districts/bracket.ts`.

### What each stop locks (for comments and copy, derived from the 30/20/13/7/0 placement table)
- Round 2: sf5/sf6 losers locked at 0; sf7/sf8 winners floor 13.
- Round 3: sf9/sf10 losers locked at 0; winners floor 7.
- Round 4: sf12 loser locked at 7; sf11 winner floor 20; sf12 winner floor 13.
- Round 5: sf13 loser locked at 13; winner floor 20.
- Finals: 30 and 20 locked.
- Round 1 and a non-clinching finals game move no lock, only the predicted ledger.

### Claude's Discretion
- Sub-words under the dots, the group label geometry, and how the thirteen-column track
  behaves at phone width. Verify at 375px with a screenshot; the sub-word under the last stop
  may need to be shorter than "Finals" to fit, but the accessible name and title say "Finals".
- Whether round stops of a divisioned district championship parent (2 or 4 alliance bracket,
  never eight) simply never "happen" (disabled dots) or are hidden. Never fabricate a bracket.

</decisions>

<specifics>
## Findings from the code (verified 2026-10-07, before planning)

**Timeline has no playoff match steps.** `districtTimeline.ts` builds match steps from
qualification rows only (`buildQualRows`); the Playoffs and Awards stage steps anchor on the
event's LAST played playoff row. `remainingQualRowsAtPosition` filters `step.kind === "match"`,
so playoff matches must NOT be added as `match` steps or they would count as remaining
qualification rows. Add a new step kind (for example `round` with a round number 1 to 5) that
sits between `alliance` and `playoffs` in `DISTRICT_STEP_KINDS`, decides no category
(`CATEGORY_BY_STEP_KIND` stays as is), and anchors on the last played row among that round's
sets (by `sortTime`, like the Playoffs anchor). A round with no played row yet gets no step
position (or sorts like an unplayed Playoffs step); its milestone is not `happened`.

**The as-of INDEX records every fold, playoff matches included.** `packages/harness/asOfState.ts`
line 509 marks the last `qm` fold separately (`index.lq`), which only makes sense because
non-qm folds are in `m`. So `asOfCutAtMatch(index, <sf match key>)` resolves and a round stop
has an exact instant to rebuild at. `resolveStopCut` walks back to the nearest anchored
position otherwise.

**The simulation already conditions a bracket on played sets.** `DistrictLedgerEventInput.playedElimMatches`
(`packages/core/districts/ledgerSimulation.ts` around line 505) routes every played set with its
real winner and prices the rest. `districtLedgerRows.ts:852` only passes it when
`conditionOnPlayedElims === true`, which `districtRunAssembly.ts` sets for the live position
(line 194) and explicitly `false` for a rewound stop (line 285). A round stop needs the
rewound assembly to pass the played playoff matches AT OR BEFORE THE CUT: filter
`playedBracketMatchesFor(eventArtifact)` to rows whose INDEX position is at or before the cut
(`asOfAtOrBefore`, the ONE order the as-of module insists on), or by `sortTime <= anchor`
if the planner judges that equivalent; say which and why in a comment. At a round stop
`stage.alliance` is final and `stage.elim` is open, so `knownAlliances` is supplied and
the per-team bracket milestones are computed.

**Happened for a round stop.** `DistrictMilestoneEventInput` carries only the state block
(`DistrictEventStateFacts`: qualMatchesPlayed, qualMatchesTotal, alliancesPicked,
playoffsDone, awardsPosted). At "now" on a finished district no event artifact is fetched,
yet every stop of a finished event must be solid and clickable (decision 2 in
`districtMilestones.ts`). So: a round has happened when `playoffsDone` is true, OR the event's
loaded artifact has a played row for every set of that round. Pass the loaded event artifacts
(or a precomputed per-event "rounds played" count) into the milestone model; do not add a new
state block field (that would need a Worker deploy and republish).

**At id for a round stop.** Use `<eventKey>:round:<n>` (matches the new step id) so a stale
link resolves to now like any unknown id. Keep `<eventKey>:playoffs` for Finals.

**Picker geometry is hard-coded to eight.** `theme.css` 1567 to 1598: `repeat(8, ...)`, the
line inset `calc(100% / 16)`; `LocksMilestonePicker.tsx`: `fillStop / 7` and
`calc(n * 100% / 8)`. Derive all of these from `DISTRICT_MILESTONE_KEYS.length` (13) or a
CSS custom property set from it. `DISTRICT_LEDGER_MILESTONE_GROUPS` (districtLedgerCopy.ts:170)
becomes Schedule 1/2, Qualification 2/6, Alliances 6/7, Playoffs 7/13, Awards 13/14.

**Tests and specs that pin eight.** `districtMilestones.test.ts`, `LocksMilestonePicker.test.tsx`
(lines 105 to 120, 216 to 266: "eight column stepper", "/ 8" style, CSS contract regexes),
`districtLedgerCopy.test.ts:154`, `DistrictLedger.test.tsx`, `ChampLocksLedger.test.tsx`,
`districtTimeline.test.ts` (any test iterating `DISTRICT_STEP_KINDS` must get the new kind:
iteration-list trap), and the live-only Playwright spec `apps/web/e2e/districts-ledger.spec.ts:301`
(`toHaveCount(8)` becomes 13; it runs against sigmascout.org only, so it is updated in the
repo and re-run after deploy, not in CI).

**Headers to update.** The "eight milestones / Sketch 024 Q has nine; its Playoffs half stop is
not modelled yet" sentences in `districtMilestones.ts`, `LocksMilestonePicker.tsx` and
`districtLedgerCopy.ts:167` are now wrong. The methodology page copy
(`apps/web/src/components/methodology/districtLedgerContent.ts`) should be checked for a stop
list and updated in the flat third-person voice with no dash characters.

**Round placement when only part of a round is played.** The round step anchors on the last
played row of the round, but the stop is `happened` only when every set of the round is
played. Between those two states (a live bracket mid-round) the Live position already
conditions on everything played, so nothing is lost.

</specifics>
