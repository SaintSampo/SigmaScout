# Quick task 261006-2mg: count the events whose simulation roster carries playoff-only demo robots, propose a fix

One 2026 event's pre-schedule simulation (2026txmca) ranks nine demo robots (frc9991 to frc9999)
that appeared only in its playoff matches. The todo `presim-roster-demo-robots` records the
defect and says nobody has counted how many events share it.

## Task 1: count from the corpus

Walk every event's matches in `data/corpus.sqlite`. For each event take the match-derived roster
the publisher uses (every team in every played or scheduled match at every comp level) and the
qualification roster (teams in `qm` rows). Count events where the difference holds a demo key
(frc9970 to frc9999). Break out by season, by official versus offseason, and separately count
demo keys that played qualification matches and real teams that appear only in playoffs.

## Task 2: confirm against production and the code

Fetch the live `v1/presim/{event}/spr@10.0.0+baseline.json` and `epa@14.0.0+baseline.json`
sidecars for every candidate event and count demo keys in `roster`. Read the sidecar gates in
`packages/harness/publish.ts` (offseason events get no sidecar) so the count matches what is
published, not just what the corpus holds. Read `apps/web/src/components/districts/asOfRewind.ts`
to answer whether the per-match rewind builds the same roster.

## Task 3: propose and record

Write the counts and the proposal into the SUMMARY and into the todo's "Not known" section.
Check TBA's own `event_rankings` for demo keys so the proposed roster rule follows the convention
TBA already publishes.
