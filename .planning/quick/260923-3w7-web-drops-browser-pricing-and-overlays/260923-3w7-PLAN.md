# The web drops browser pricing and every live overlay

The web half of `260923-1tu-FINDINGS.md` items C1 and C5. Quick task 260923-3w6 put upcoming
pricing, per-team artifact writes and the priced-row shape back inside the Worker tick, and stopped
emitting the event `state` block, the ephemeral `live` block and `v1/live-roster/{eventKey}.json`.
Every browser-side derivation that existed to compensate for the retired 10 ms CPU budget is
therefore dead code. This task deletes it and re-points the web at the artifacts the tick writes.

Nothing may change how the site LOOKS, with one intended exception: live data now arrives from the
Worker's own artifacts instead of browser derivation.

## Tasks

1. **The Worker counts live event standings itself.** `mergeEventArtifact` preserves
   `teams[].rank`/`record`/`rp` as last published, so the browser copy in
   `apps/web/src/lib/liveStandings.ts` is load-bearing and cannot simply be deleted. Move the
   derivation into the Worker merge (`apps/worker/src/liveStandings.ts`), with its test, and apply
   it in `mergeEventArtifact`. The `artifact.live !== undefined` trigger is replaced by "the tick
   holds played qualification rows", which is the same set of writes.

2. **Derived live standings leave the browser.** Delete `lib/liveStandings.ts` (+ test),
   `withStandingsSafely`, `EventPageArtifact.standings`, `LiveStandingsMarker`, and
   `InsightsTab.tsx`'s reading of the marker.

3. **The robot and match pages read their own artifacts.** Delete `lib/liveTeamSeason.ts` (+ test),
   `components/team/useLiveTeamSeason.ts`, `components/team/teamUpcomingOverlay.ts` (+ test),
   `lib/liveDiscovery.ts` (+ test), `lib/api/liveRoster.ts`,
   `apps/worker/test/liveTeamSeason.parity.test.ts`, `packages/harness/liveEventRows.ts` (+ test)
   and `packages/harness/liveRoster.ts` (+ test). Unwire the team route and the match route, drop
   the now-unfed live override props, and move the 60 s poll onto the team artifact (the query the
   tick's writes now reach).

4. **The `live` block leaves the read schema.** Delete `EventLiveBlockSchema`,
   `EventLiveRowSchema`, both `EVENT_LIVE_BLOCK_TRIM_*` constants, the `live` key on
   `LiveEventArtifactSchema`, and `artifactShapeCheck.ts`'s `isLiveBlock` with its test group.

5. **Browser pricing and the `state` block are gone.** Delete `lib/eventPricing.ts`,
   `eventPricing.lazy.ts`, `eventPricing.parity.test.ts`, `eventPricing.bundleGuard.test.ts`;
   `api/event.ts` parses and hands the artifact straight through. Drop `state` from
   `EventArtifactSchema`, delete `EventStateBlockSchema`/`EventStateBlockRowSchema`,
   `EventScheduledMatchSchema` and the `upcoming` union, and collapse `LiveEventArtifactSchema` into
   `EventArtifactSchema`. Move `stateBlockScopeKeys` and the rule-module season guard out of
   `packages/harness/eventStatePricing.ts`, convert its parity suite to the in-memory-model arm in
   `upcomingPricing.test.ts`, then delete the file, its browser-safety test and
   `fixtures/eventStateArtifactFixture.ts`. Remove `isPricedUpcomingRow` and the schedule-only row
   branch in `eventMatchAxis.ts`. Add a test that an artifact carrying a stale `state` block still
   parses and drops the block.

6. **Docs and the pending todo.** Retire the remaining state-block / live-roster / browser-pricing
   wording in `docs/`, and record in `.planning/todos/pending/live-merges-drop-percentiles.md` both
   that the `live` block is gone and the one visible regression this task accepts.
