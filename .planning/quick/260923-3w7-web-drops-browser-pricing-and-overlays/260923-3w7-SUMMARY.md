# The web drops browser pricing and every live overlay

The web half of `260923-1tu-FINDINGS.md` items C1 and C5, following quick task 260923-3w6's Worker
half. The tick prices its own upcoming matches, writes per-team artifacts and counts its own
standings again; every browser-side derivation that existed to compensate for the retired 10 ms CPU
budget is deleted, and the web now reads exactly what the Worker writes.

**Net: 83 files changed, 1,779 insertions, 5,287 deletions, about 3,500 lines removed.**

**Published numbers did not change.** A live artifact's `teams[].rank`/`record`/`rp` move from
browser-computed to tick-computed with the same arithmetic (the module was moved, not rewritten),
and every upcoming row was already priced by the tick. No algorithm version bump.

## What changed

### 1. The tick counts live event standings itself (`f0da5088`)

`mergeEventArtifact` preserved `teams[].rank`/`record`/`rp` as last published, so
`apps/web/src/lib/liveStandings.ts` was load-bearing, not dead. The derivation moved into the tick
as `apps/worker/src/liveStandings.ts`, arithmetic unchanged, with its test as
`apps/worker/test/liveStandings.test.ts`. It runs only from a merge, which runs only when the tick
folded something, so the old `artifact.live !== undefined` trigger needed no replacement.

### 2. Derived live standings leave the browser (`3b5290b3`)

`lib/liveStandings.ts` (+ test), `withStandingsSafely` and `EventPageArtifact.standings` deleted.
The marker was promoted, not deleted: `EventArtifactSchema` gains an optional
`standings: { source: "tick-counted", ranked }`, written by `mergeEventArtifact` only when it
actually counted, so the Insights tab's "counted from the results posted so far" notice keeps
rendering. That is one new published key on live-written event artifacts.

### 3. The robot and match pages read their own artifacts (`0389726b`)

Deleted: `lib/liveTeamSeason.ts`, `components/team/useLiveTeamSeason.ts`,
`components/team/teamUpcomingOverlay.ts`, `lib/liveDiscovery.ts`, `lib/api/liveRoster.ts`,
`packages/harness/liveEventRows.ts`, `packages/harness/liveRoster.ts`, their tests, and
`apps/worker/test/liveTeamSeason.parity.test.ts`. The robot page reads one file; the match page reads
`teamArtifact.metricHistory` directly. The 60 s poll moved with the data: `teamQueryOptions` gains a
`refetchInterval` gated on `shouldPollTeamArtifact`. The route-level override props on
`OverviewTab`, `EventSectionList`, `SeasonHeader` and `MetricHistoryTab` are removed.

### 4. The live block leaves the read schema (`566a0189`)

`EventLiveBlockSchema`, `EventLiveRowSchema`, both `EVENT_LIVE_BLOCK_TRIM_*` constants, the `live`
key and `artifactShapeCheck.ts`'s `isLiveBlock` deleted. A compatibility test pins that an artifact
an earlier tick wrote, still carrying a `live` block in R2, parses and drops the key.

### 5. Browser pricing and the state block are gone (`334a60f6`)

Deleted: `lib/eventPricing.ts`, `eventPricing.lazy.ts` and both tests,
`packages/harness/eventStatePricing.ts`, `fixtures/eventStateArtifactFixture.ts`. `api/event.ts`
parses and hands through. One event schema where there were two: `EventArtifactSchema.state`,
`EventStateBlockSchema`, the strict `EventScheduledMatchSchema` and `LiveEventArtifactSchema`'s
two-shape `upcoming` union deleted; `LiveEventArtifactSchema` collapsed into `EventArtifactSchema`.
A schedule-only upcoming row is now rejected, so the tick's pricing is a schema invariant.

The equivalence proof was re-pointed, not lost: `eventStatePricing.parity.test.ts` became
`packages/harness/upcomingPricing.test.ts` with every arm rebuilt on the in-memory
`UpcomingPricingModel`, still compared against the publisher with no tolerance. `stateBlockScopeKeys`
moved to `stateSnapshot.ts` as `stateScopeKeys`. `pageArtifacts.test.ts` pins that a stale `state` or
`live` block parses and is dropped, and that no schema in the file is `.strict()`.

### 6. Docs and the pending todo (`af19bd74`); four dead imports (`efeff5b8`)

## Decisions

- Item 3 of the brief: the standings derivation moved into the Worker because the merge did not
  update the counted columns.
- `packages/core/rankingPoints/rulesLoader.ts` kept (has its own test and a test consumer).
- The "No prediction" rendering in `MatchTable.tsx` and `EventMatchTable.tsx` kept as a
  presentational guard; the derivations that produced such rows are deleted.

## One visible regression, intentional and recorded

A live-folded row's snapshot tiles on the robot page render untiered until that event's next
republish, because `EventSection`'s `tierCuts` came from the live event artifact the page no longer
fetches. Event-page surfaces and published rows are unaffected. The fix is to publish `tierCuts` on
the team-season artifact (a `TeamSeasonArtifactSchema` key plus a `scheduled.ts` carry-forward);
recorded in `.planning/todos/pending/live-merges-drop-percentiles.md` and assigned to quick task
260923-3x0 by the orchestrator.

## Operator-visible changes

- No republish or re-seed is owed for this task alone; stale blocks parse and are dropped.
- **The Worker must be deployed before this web change goes live**: the new event schema rejects
  the schedule-only upcoming rows the pre-260923-3w6 Worker writes during a fold, so a live event
  page would fail to parse under the old Worker.
- An event page no longer downloads a lazy pricer chunk; a robot page makes one artifact fetch and
  polls its own file every 60 s while its event is live.
