  <name>Task 1: Decide how the Teams table participates</name>
  <decision>Should the Teams table render the Common outline now, and if so, on what evidence?</decision>
  <context>
Every surface except the Teams table works out the tier in the browser from a published
percentile, so it knows exactly when a value is Common. The Teams table is different: to keep
that file small the pipeline strips the percentile and ships a short tier label instead — and
it leaves the label off entirely for Common, because Common used to need no box. So on the
Teams table "no label" currently means either "this is Common" or "nobody ranked this metric",
and the browser cannot tell which.

In practice those two are the same thing on any season that has been fully published: the
publish pass ranks every metric that has a value, so the only cells with no label are the
Common ones. The gap opens during a live event — the Worker that updates rows mid-event
computes no percentiles at all, so a genuinely Legendary team's row can arrive with no label
until the next full publish. Today that cell renders bare. Under option A it would render a
Common outline instead, which is a small, temporary, wrong claim rather than no claim.
  </context>

      <name>Outline the Teams table too — treat a missing label as Common</name>
      <pros>One line. Common looks identical everywhere on the site the moment this ships, which is what the task asked for. Exactly correct on every fully-published season, which is what almost every page view reads.</pros>
      <cons>During a live event a top team's cell can briefly wear a Common ring instead of the ring it deserves. That is a wrong claim where today there is no claim.</cons>
