## Two corrections to the review's own proposed fixes, established during planning

Both were verified against HEAD; the review's literal text is wrong in each case and the plan
below supersedes it.

1. **WR-03's season assert cannot be written as the review wrote it.** The review proposes
   `s.season === artifact.season`. `CompareArtifactSchema` (`packages/harness/pageArtifacts.ts:1262`)
   is `PagePreambleSchema.extend({ algorithms, slices })`, and `PagePreambleSchema` carries only
   `schemaVersion`, `generation` and `computedAt`. **There is no `artifact.season`** — that
   expression is a TypeScript error. `season` lives on each SLICE. The caller is therefore the only
   party that knows which year an artifact was fetched for, so the season must be threaded in.
   Task 2 does that. (`CalibrationSection.tsx:176` gets away with `s.season === year` for exactly
   this reason: `year` is its own local selection, not a field it read off the artifact.)

2. **IN-01's `metricsOverride !== undefined` is not a reliable signal today.**
   `team.$teamNumber.tsx:83-86` computes `officialSnapshotMetrics(...) ?? data.seasonStats.metrics`
   — so when no official match exists, `metricsOverride` is present and is SEASON-FINAL. Labelling
   that "As of last official match" would ship a new false claim in the act of fixing a missing
   one. Task 1 removes the route's fallback first; `SeasonHeader` already falls back identically on
   its own line 64, so this is behaviour-preserving and is what makes the label truthful.
