# Quick task 261006-2t0: simulation baselines from qualification rows only

## What changed

`simulatedTeams(artifact)` in `apps/web/src/lib/simulationInputs.ts` returns the `teams[]` rows
whose team is on at least one qualification row (played or upcoming, from `buildQualRows`), or
the whole list when the artifact holds no qualification row. It is read at the three places a
browser simulation roster was built from `artifact.teams`:

| Site | What it feeds |
|---|---|
| `buildSimulationInputs` (simulationInputs.ts) | Simulation tab per-match run, live Locks ledger mid-event |
| `asOfQualSplit` and `finalRankingBaselines` (asOfRewind.ts) | Rewound Locks view and rewound Simulation tab |
| `finishedQualBaselines` (districtLedgerRows.ts) | Live Locks ledger for a finished event |

`fieldSize` in `buildDistrictEventSimulationInput` is the baseline count, so at the thirteen
affected events it is now the qualification field (2026txmca: 18, was 27). District
qualification points read rank against field size, so the rewound Locks view for 2026mefal,
2026txfor and 2026txmca priced every team's qualification points against an inflated field
before this change.

The event page's own `teams` rows are untouched: the carve-out in `apps/web/src/lib/teamKey.ts`
stands (event pages show whoever actually played).

## Verification
