<objective>
Fix seven EPA-mode table defects the user reported, in their own words. The
seven map to D-1..D-7 and this plan cites them by that id throughout:

- **D-1** "EPA Teams list table horizontal spacing is bad."
- **D-2** "make EPA table show limited components by default, like VPR with Auto, Teleop, Endgame, and total. have the button expand the table."
- **D-3** "EPA team page is missing breakdown as Auto Teleop Endgame"
- **D-4** "EPA event page insights is missing auto endgame teleop data"
- **D-5** "epa breakdown page total column needs to be moved just to the right of the nickname column."
- **D-6** "change NICKNAME to TEAM NAME"
- **D-7** "EPA events page Alliances horizontal spacing is bad. EPA is too close to team number. lots of horizontal space is wasted"

D-2, D-3 and D-4 are one root cause with three faces. VPR's pipeline publishes
`phaseAuto`/`phaseTeleop`/`phaseEndgame` as first-class metrics carrying their
own value, spread and percentile; EPA's does not, so every surface that reads
those three keys renders blank for EPA. `lib/metricGroups.ts`'s header records
why the client stopped summing components itself: a summed group cannot produce
an honest SPREAD (that needs unpublished inter-component covariances) or an
honest PERCENTILE (a sum's rank is not a function of its parts' ranks). That
argument is about spread and percentile, and it still stands — but EPA
publishes no spread at all (`packages/core/algorithms/epa.ts`'s `teamMetrics`:
"EPA carries a mean only, exactly as Statbotics' `EPARating`"), so for EPA there
is no spread to get wrong. A client-side sum of published EPA component VALUES
is exact arithmetic over published numbers, fabricating nothing.

That is the decided approach: derive the group VALUE client-side, publish no
spread and no tier on it, and never let a derived entry displace a published
one. No pipeline change, no republish, nothing outside `apps/web`.

Purpose: EPA is a headline algorithm on this site and its tables are currently
both harder to read than VPR's and missing data VPR shows.
Output: three commits, before/after screenshots, and a derivation the whole
site shares.
</objective>
