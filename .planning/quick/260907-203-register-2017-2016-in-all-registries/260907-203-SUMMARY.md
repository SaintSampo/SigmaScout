# Quick task 260907-203: Register seasons 2017 and 2016 — Summary

`componentMapForSeason` and `rpRuleModuleForSeason` now resolve for **2016 through 2026**
contiguously. Both seasons were ingested, measured, registered across every registry, and
verified — and **`FIRST_SEASON` remains 2019**, so none of 2016/2017/2018 is visible on the
site. Publish-then-reveal is intact; no artifacts for these seasons exist in R2.

## Ingest

`pnpm ingest --years 2016-2017`, then `ingest:rankings`, then `ingest:districts` — 492 + 460 +
373 = **1,325 requests, all clean**. 2016: 203 events, 11,079 official quals with breakdown
(22,158 sides). 2017: 256 events, 12,693 quals (25,386 sides). The 31/57 rows skipped for an
unregistered team key are mid-range and normal (every season shows 21-87).

## The headline finding: 2018 is a one-off, not a pre-2019 pattern

The whole reason 2018 was done first was that it violates the additivity assumption underneath
OPR, EPA and Sigma1. The open question was whether that was a property of the older game era.
It is not:

| season | corr(red, blue) totalPoints | reconciliation |
|---|---|---|
| 2016 | **+0.3416** | 0 / 22,158 qual sides |
| 2017 | **+0.3293** | 0 / 25,386 qual sides |
| 2018 | **-0.4567** | 196 / 28,312 |

Both new seasons sit squarely in the normal +0.24..+0.52 band and reconcile perfectly on quals.
**2018 remains the only anti-additive season in the corpus**, which downgrades its open modelling
question from "an era we are extending into" to "one strange game".

## RP rules — 2017 is the cleanest season in the project

| season | bonus | rule | agreement, all 3 tiers |
|---|---|---|---|
| 2017 | kPa | `autoFuelPoints + teleopFuelPoints >= 40` | 100.000%, 0 FP, 0 FN |
| 2017 | rotor | `autoRotorPoints/60 + teleopRotorPoints/40 >= 4` | 100.000%, 0 FP, 0 FN |
| 2016 | breach | >= 4 of 5 `position{i}crossings` at >= 2 | 100.000%, 0 FP, 0 FN |
| 2016 | capture | `attackedTowerEndStrength <= 0 && challenge/5 + scale/15 >= 3` | 0 FN; 1 FP total |

2017 is the **first season where both bonuses are simultaneously exact and fully numeric**, so
`predictThresholds` is identical to `parse` — no boolean, no fallback, no conservative branch, no
tolerance. 2018 needed a fallback for `autoQuest`; 2019 needed a hard-coded-false branch for
`completeRocket`.

Three traps caught by measurement rather than by reading the game manual:

- **2017 rotor.** `autoRotorPoints + teleopRotorPoints >= 160` is the obvious rule and it is
  wrong — 14 false positives, every one at `120 + 40`: two auto rotors (60 each) plus one teleop
  rotor (40) is 160 points but only THREE rotors. A point sum cannot recover a count when the two
  sources are worth different amounts.
- **2016 breach.** "All five defenses damaged" gives **12,248 false negatives**. The rule is four
  of five, with perfect separation: damaged-count 0-3 always false (6,651 sides), 4-5 always true
  (15,507).
- **2016 capture.** `towerEndStrength` on a side is *that side's own* tower — the one the opponent
  attacks. Reading your own gives 212 FP / 1,304 FN. It is exposed as an own-alliance threshold
  variable `attackedTowerEndStrength` sourced from the opponent side, which keeps
  `predictThresholds` symmetric; the value genuinely *is* this alliance's offensive output.

2016 carries one false positive in 22,158 sides (`2016melew_qm24`), tolerated at
`{ season: 2016, bonus: "capture", eventTypes: [1], rate: 0.0005 }` — event_type 1 only, so every
other tier stays bound to exactly 0.

## Four brief corrections the run produced

The orchestrator's brief was wrong on four points. Each was disproved by measurement and verified
before being acted on — recorded here because three of them would have shipped a silent defect.

1. **The breakdown reconciliation is NOT qual-scoped.** `sampleBreakdowns` has no `comp_level`
   filter and `ORDER BY match_key ASC` sorts `f` < `qf` < `qm` < `sf`, so its 2,000-row window is
   playoff-inclusive. The brief's claim that playoff-only fields were merely a latent risk was
   wrong — they are load-bearing for a green suite.
2. **2016 therefore DOES need a breakdown tolerance**, contrary to the brief: 3 exceptions in
   26,604 (`2016capl_f1m1` +25, `2016milsu_qf4m1` +25, `2016mndu2_f1m2` -25), all eliminations,
   and one sits inside the sampled window. Signs are **mixed**, so `direction` is omitted —
   measuring only the window would have wrongly encoded `"positive"`. All three also fail TBA's
   own `totalPoints` identity while both our halves reconcile, so the tolerance is earned.
3. **The eight-name 2016 `diagnosticKeys` list must not ship.** Its only consumer
   (`identifiability.ts:253`) treats every listed name as a *foul* field via
   `hasFoul = ...some(key => val > 0)`, so `towerEndStrength` and the five crossings counts would
   have reported a near-100% 2016 foul rate. Both seasons ship `["foulCount","techFoulCount"]`.
4. **TBA reports elimination RP as `NULL`, not `0`, for 2016 and 2017** — 2,223/2,223 and
   2,747/2,747 played elimination sides, against explicit 0 from 2018 onward. Quals are
   unaffected. The invariant now asserts the substantive rule (no non-zero RP in elimination play)
   for every season, with the representation pinned per season by a documented
   `NULL_ELIMINATION_RP_SEASONS` constant — strictly stronger than what it replaced.

## The trap, fourth and fifth sightings

`rules.test.ts` carried four season literals; **two fail silently** (a `toThrow` substring regex
and a `for...of` list) and two are loud pins. All four were edited for each season and all four
were proven to fail by name. A fifth iteration list — `rp/reconciliation.test.ts`'s `CHECKS` — was
found and **correctly left alone**: its shape requires one variable against a tiered scalar, and
all four new bonuses are multi-variable.

Two new silent gaps were surfaced and are recorded rather than fixed:

- **`statbotics.test.ts` cannot catch an absent season.** Its only registry-wide check iterates
  `Object.entries(STATBOTICS_REFERENCE_FALLBACK)`, so a missing season removes its own case. There
  is no equality pin on the registered set the way `pointModel`/`rules`/`groups` have.
- **`npx vitest run apps/web/src/lib/<file>` finds zero test files and exits 0.** The web
  project's `include` is relative to `apps/web`, so a repo-root path filter into it silently
  matches nothing and reports success — the same false-green family as the `timeout+pnpm` trap.
