### The 09-09 NO-SHIP is CONFIRMED, not overturned

The todo's concern was legitimate and is now settled against rung 1. Raising the count from 20 to
4,000 moved the **floor** 27.0% → 98.4% (71 points) while moving the **candidate** only
32.8% → 41.4% (8.6 points). At 20 schedules clause 1 was unreachable by any method including the
one that ships; at 4,000 it is comfortably reachable and rung 1 does not reach it.

The candidate's worst team fell **7.59 → 3.33** ranks, which confirms most of the old worst-team
figure genuinely *was* noise. But 3.33 ranks is still more than three times the criterion's hard
per-team bound of 1.0, against a floor whose own worst team moves 0.71.

**The failure is structural and scales with roster size, not with resolution** — per event,

## What changed in the code

**`--schedules`** (`resolveScheduleSplit`, `DEFAULT_SCHEDULE_COUNT = 20`). `--draws` stays the
total; draws-per-schedule stays derived. The derivation is the expression that was inline in
`measureEvent`, **copied rather than rewritten**, so the default path cannot drift. `MeasureOptions`
gained an *optional* count, so existing callers keep today's behaviour by the type rather than by
remembering. Zero, negative, fractional, `NaN`, `Infinity` and a raw string all throw naming the
script and the value; none clamps.

**The binding floors.** `measureResamplingFloor`, `measureEdgeNoiseFloor`, `REPLICATE_SUFFIX` and
`DRAWS_PER_SCHEDULE` are **imported** from `measureGeneratedSchedules.ts`, never re-implemented.
`measureEvent` builds a second artifact differing in exactly one field — `algorithmVersion` plus
`REPLICATE_SUFFIX`, which `buildPreScheduleArtifact` uses only for seed hashing — through the same
bound `predict` closure, hoisted to one `const` so the two cannot diverge in pricing. A guard throws
if this run's draws-per-schedule is not the imported `DRAWS_PER_SCHEDULE`, because the floor derives
its own draw count from that constant and would otherwise be read at a different count than the
candidate.

**The draw-only diagnostic survives.** `measureSeedNoiseFloor` is still called, still carried on the
record, still printed, and still carries its original doc comment — now explicitly labelled as not
binding. The floors were added beside it, not in place of it. A test asserts it is still exported.

**The module cycle.** `measureGeneratedSchedules.ts` already imported this module; importing back
closes a cycle that resolves only because neither module reads an imported binding during top-level
evaluation. That condition is documented at the import site and **asserted by test** rather than
trusted, so a later edit that breaks it fails in a second instead of ten minutes into a run.

**`renderDoc` is self-labelling at every count.** It reads the schedule count from the measurements
(and throws on a sample that disagrees with itself) and threads it through the title, the headline,
the JSON block, the verdict table, the per-event table, the diagnostics table and the caveats. The
artifact-size section carries a caption stating the figures are at 4,000 schedules — *not* the
shipped count — and that the baked column is therefore ~200× the artifact that ships. The superseded
n=20 headline can no longer be read as current.

**[Rule 3 — Blocking] `printEvent` prints the floors; the side-by-side pairing lives in the pooled
summary.** The plan asked for the candidate's clause-1 rate and the binding floor to appear side by
side in `printEvent`. `printEvent` is called per event *during* the measurement loop, before
`evaluateRungOneCriterion` has run — and that function requires the whole six-event sample, so no
authoritative clause rate exists at that moment. Computing one early would have meant a second copy
of the rate calculation, which the "one scorer" constraint forbids. The pairing is therefore done in
the per-event summary loop, which reads `verdict.perEvent` from the single scorer; `printEvent` prints
the floors alongside the event's own diagnostics. The requirement — candidate and binding floor read
together at the same count — is met, and it is met from one scorer. Commented in the source.
