## Discretion calls made while planning (the executor implements them as written)

- **CD-01, deviation forced by the code.** `min` is OPTIONAL in the lattice declaration, not required as SD-01's shape implies. 2016 `attackedTowerEndStrength` has no rule floor: tower strength counts down by one per boulder and goes negative (observed down to -13). Its starting strength also depends on the event tier. So that one variable declares `step: 1` with no bounds and takes the discretized Gaussian. A rules.test.ts pin allows exactly that one variable to omit `min`.
- **CD-02 discretized Gaussian semantics.** The mass at lattice point x is `Phi((x + step/2 - mean)/sd) - Phi((x - step/2 - mean)/sd)`. Lattice points are anchored at `min` (or 0) modulo step. When `min` is declared, all mass below it is lumped onto `min`. Single-term tails use the closed form (`P(X >= x) = Phi(-(x - step/2 - mean)/sd)` for x above min, and 1 at or below min), so no pmf is built for them. A pmf is materialized only for convolution, over `[max(min, mean - 8sd), mean + 8sd]`, with both tails lumped onto the end points, so it sums to 1 by telescoping. The lattice path uses a double-precision normal CDF (the probe's Hart/West `phi`, under a new name). It never uses `standardNormalCdf`, whose Abramowitz-Stegun error (1.5e-7) would make far-tail masses negative. `standardNormalCdf` itself is not changed.
- **CD-03 family choice.** The bounded family is used whenever a max is declared, whatever the width, as SD-02 says. The probe instead used robust ranges from season data with a width <= 30 rule, so this arm's figures will not reproduce the probe's 70.9%. That is expected, not a defect.
- **CD-04 mean-shift population.** Exactly the probe's scored population: `isBonusRpCompLevel`, `isRpEligibleEventType`, a breakdown present, and BOTH sides parsing inside one try (any throw skips the whole match). A side counts only when every roster team `hasHistory` before this match's fold. The residual is taken against the UNSHIFTED `momentsFor` mean read before the fold. State is keyed by season, and a state whose season differs from the rule module's is discarded on resume.
- **CD-05 mean shift in pre-schedule pricing.** The settled decisions do not cover this. `makeRankingPointFiller` prices synthetic 3-team rosters of real teams and uses the same per-alliance fully-warm check. The field-averaged presim has no real roster, so it applies the shift only when every team in the event roster has complete history. That is all-or-nothing, decided once per event, following `buildFieldContributions`' existing convention. Jacob may veto this before Task 6.
- **CD-06 F10 fill clamp.** For any defined probability, the fill height is `round(p * innerPx)` clamped to `[1, innerPx - 1]`. This matches `predictionPercent`'s 1-99% "never certain" display policy.
