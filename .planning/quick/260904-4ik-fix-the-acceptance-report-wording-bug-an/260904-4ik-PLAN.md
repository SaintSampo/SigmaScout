<objective>
Two independent harness-side leftovers, ordered small-and-unblocked first.

**Task A** fixes a wording bug in `buildAcceptanceReport`: one shared sentence prefix, reused by
all three verdict branches, renders a SIGNED margin behind a directional verb, so a rejected
candidate's report reads as if it had won by a negative amount. The decision logic is correct and
stays untouched; only the sentence is wrong. A negative-margin regression test closes the gap that
let it ship.

**Task B** closes `.planning/todos/pending/remeasure-baseline-fingerprint-post-trz.md` by committing
a new baseline fingerprint measured under the current promoted versions. The expensive half is
already done — `reports/rolling-2026-09` is a complete 5-season run under exactly the three versions
the todo requires. The remaining work is a post-hoc read, gated on verifying that the five
`260904-cs1` commits which landed ~25 minutes AFTER the run did not move its predictions.

Purpose: an acceptance report that describes a loss as a win is the same hazard, pointing the other
way, that `acceptance.ts`'s header already warns about — it makes a rejected candidate read as a
near-miss that "only just" failed the bar. And a stale fingerprint means the project's own accuracy
record is measured under code that no longer exists.

Output: a sign-neutral verdict prefix with a regression test; a fifth committed fingerprint with an
honest `sourceNote`; and the todo closed.
</objective>
