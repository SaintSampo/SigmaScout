# Offseason scoping: official-only W-L-T display, official-only EPA priors

Two changes, both narrowing an offseason-inclusive population to official play
without hiding any offseason data from the surfaces that should still show it.

1. **Display.** `record` (W-L-T), `eventCount` and `matchCount` on the Teams
   list and the team page header are OFFICIAL-ONLY. The header row used to pair
   an official-scoped metric snapshot with a season-wide record; it now draws
   from one population.
2. **EPA priors.** At each season boundary `epa.carrySeason` receives the state
   as it stood after that season's last OFFICIAL match. An exhibition blowout in
   November can no longer seed a team's rating for the following February.
   EPA only — VPR, OPR and BPR are provably untouched.

Ships as `epa@6.0.0+baseline`.

## Design decision (resolved during planning, held through execution)

`MatchResult` already carries a required, non-outcome-bearing `eventType`, so
officialness is answerable inside `WalkForwardSimulator.runAll`'s existing
chronological loop with no event-meta join and no leak risk. The carry instant
therefore lives at the replay layer as a second returned map (`carryStates`),
selected per algorithm by an opt-in `carryFrom` field. Because the stream is
chronological, the last write wins by construction — no scan back, no second
pass. An all-official stream yields `carryStates` reference-identical to
`finalStates`, so an offseason-excluded run is unchanged.

Six season loops call `carrySeason`; putting the choice of instant in `runAll`'s
return means none of them can hold a different opinion about it.

## Deviations from plan

- **A plan claim was wrong and is corrected in code, comment and test.** The plan
  (and my first comment) said passing the all-play stats map to
  `deriveTeamRegions` was load-bearing because "a team whose only events are
  offseason ones still has a home region". False: `deriveTeamRegions` applies its
  own `isRegionEligibleEvent` official-type filter, so an offseason event never
  contributed a region either way. The comment now says that, and a test pins it,
  so a future reader does not "fix" a region input that was never broken.
- **`mergeTeamSeasonArtifact` is now exported** from `apps/worker/src/scheduled.ts`
  (it was module-private). Driving the record assertion through `runTick` would
  need the whole D1/R2/KV fake rig to prove a property of ten lines of pure merge
  logic. The export carries a comment saying why.
- **Two extra ribbon tests beyond the plan's list** (12.x, and an unparseable
  version string), because the new gate parses rather than prefix-matches and the
  failure direction needed pinning.
- **`packages/bpr/equivalence.ts` audited, no change** — it drives
  `bpr.carrySeason` from its own loop without `runAll`, and BPR declares no carry
  instant.
- **`baselineFingerprint.test.ts` needed no edit**, as the plan predicted: its
  `epa@5.0.0+baseline` strings are historical file-content records, not claims
  about today's `epa.version`. Confirmed by running it, not by reading it.
