<objective>
Narrow two EPA/display populations to official play, without hiding any offseason
data from the pages that should still show it.

1. **Display scope.** `record` (W-L-T), `eventCount` and `matchCount` on the
   Teams-list rows and on the team page header become OFFICIAL-ONLY, so the whole
   header row draws from a single population. The match table, event sections and
   metric-history chart stay offseason-inclusive.
2. **EPA cross-season priors.** At each season boundary, `epa.carrySeason` receives
   the state as it stood immediately after that season's last OFFICIAL match, not
   the season-final state that kept learning through offseason play. EPA only.

Purpose: a team's headline row currently mixes two populations — official-scoped
metric tiles beside an offseason-inclusive record — and next season's EPA prior is
currently seeded by exhibition play. Both are corrected here.

Output: an `epa@6.0.0+baseline` model, official-only display counts on both team
surfaces, one shared carry-instant mechanism every replay entry point reads, and
docs that describe what actually ships.
</objective>

<design_resolution>
Answers the plan's one open design question — WHERE the last-official-match
snapshot is taken — so no task has to rediscover it.

**The stream already knows.** `MatchResult` extends `UpcomingMatch`, which carries a
REQUIRED `eventType: number` (`packages/core/algorithms/types.ts:42`), populated for
every row `buildSeasonStream` produces. So `isOfficialEventType(result.eventType)` is
answerable inside the replay loop with no event-meta join, no corpus read, and no
new parameter — and `eventType` is deliberately NOT in `OUTCOME_KEYS`, so reading it
is leak-safe.

**The mechanism.** `WalkForwardSimulator.runAll` already threads state through one
chronological loop and returns `finalStates`. It gains a sibling, `carryStates`,
built in that SAME loop:

- A new optional `carryFrom?: "season-final" | "last-official-match"` on
  `AlgorithmModule` (default, and every algorithm that omits it, is `"season-final"`).
- Inside the existing per-match/per-algorithm inner loop, for any algorithm declaring
  `"last-official-match"`, the state returned by `update` is recorded as that
  algorithm's running official snapshot whenever the match's event type is official.
  Because the stream is chronological, the LAST such write is by construction the
  state immediately after the season's final official match — exactly D-CARRY.
- `carryStates` = `finalStates`, overridden per algorithm by its official snapshot
  when one exists.
- **Fallback:** a stream with zero official matches for that algorithm (an
  offseason-only season, a cold-start slice, a truncated diagnostic stream) records
  no snapshot, so `carryStates` falls back to the running/final state — identical to
  today's behavior, never `undefined`.
- **Identity claim, stated precisely:** when every replayed match is official,
  `carryStates` is reference-identical to `finalStates`, so an offseason-excluded run
  is byte-identical to today. Note the one real edge: `buildSeasonStream`'s
  `excludeOffseason` filters `is_offseason` (type 99) but NOT preseason Week-0
  (type 100), so a `--no-offseason` stream containing Week-0 matches will now exclude
  those from the carry instant. That is the correct behavior under the locked
  definition of official, and it must be named in the epa.ts bump comment rather than
  glossed as "no change".

**Why it lives at the replay layer.** Six separate season loops call `carrySeason`
today (publish.ts, cli.ts, tune.ts, epaVsStatbotics.ts, measureRewindGap.ts,
reparamEquivalence.ts). Putting the choice of instant in `runAll`'s return means each
one changes a single token at the point it stashes state for the next season — none
of them can hold a different opinion about which instant EPA carries.

**Why the flag lives on the algorithm.** D-13 requires an epa.ts version bump for
this change. Declaring `carryFrom` in `epa.ts` makes the bump comment describe a real
epa.ts edit rather than pointing at a harness change, and keeps VPR/OPR/BPR
provably untouched (they simply do not declare the field).

**Sites that must NOT switch to `carryStates`** — call these out, they are load-bearing:

- `publish.ts:2620` `finalSeasonStates` — the D-12 D1 seed the live Worker resumes
  from. The Worker continues the real, offseason-inclusive season; seeding it from a
  rewound snapshot would make live and offline disagree. Stays `finalStates`.
- `epaVsStatbotics.ts:164` `finalStatesBySeason` — the measured comparison value,
  documented as the offseason-inclusive production arm. Stays `finalStates`.
- `cli.ts:635` `reportBreakdownParseFailures` — a cumulative telemetry read that must
  see the whole season. Stays `finalStates`.

**Audited, no change needed:** `packages/bpr/equivalence.ts` calls `bpr.carrySeason`
directly from its own match loop without `runAll`; BPR does not declare `carryFrom`,
so its behavior is unchanged. Do not edit it — record it as audited in the SUMMARY.
</design_resolution>
