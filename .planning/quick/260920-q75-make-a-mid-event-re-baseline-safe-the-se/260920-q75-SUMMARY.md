# 260920-q75: make a mid-event re-baseline safe

**Code complete and tested. Nothing is live yet: the republish, the four-file seed and the Worker
deploy are owed, in that order.**

## The incident this closes

2026-09-20. `pnpm publish:seasons` (generation `e5cf1304`) finished at 20:12 UTC with four live
windows open. Tick `tick-1789935145177` (20:12:25 UTC) ran before the D1 seed, folded all four
events on the previous generation's state, advanced every `event_cursor`, and rewrote the event
artifacts with stale-state values. The seed then replaced `algorithm_state` and left the cursors
alone. `2026onsca1` ended 2 matches past what the seeded state holds and `2026tnkno` 1 past; those
matches are missing from live state until the next re-baseline. Had the seed landed first, the tick
would have folded all 70 `2026cc` quals a second time. Both directions are silent.

## What changed

- **The tick refuses stale state.** Each live algorithm has a state-baseline marker, a reserved
  `event_cursor` row holding a bare generation string. The tick reads the markers in the same
  statement as the tick-meta sentinel (`readEventCursors`, one `IN (...)` read), so no path gained
  a D1 round trip and `TICK_FIXED_SUBREQUEST_COST` stays 3. A missing or differing marker on any
  live algorithm suspends the whole tick: no fold, no cursor claim, no R2 put, one
  `state-generation-mismatch` warning, `TickResult.stateGenerationMismatch: true`. Probes still run.
- **The seed owns the cursor.** `publish:seasons` writes a fourth file, `seed-cursors.sql`, applied
  last. It sets each windowed event's cursor to the last match the offline replay folded (NULL for
  a zero-match window), with `tba_etag` NULL so the next tick re-polls and resumes after it. The
  markers live in the same file, guarded by `WHERE EXISTS` against that algorithm's own seeded
  state, so an out-of-order apply leaves the tick refusing rather than folding. The tick-meta
  sentinel is never written; the emitter throws on a reserved key.
- **One match order.** The Worker sorted by `sortTime` alone and fell back to TBA's array order on
  ties; the publisher breaks ties by event, comp level, set and match number. A tie straddling a
  seeded cursor would have dropped a match. Both sides now use `compareCorpusMatchOrder`
  (`packages/ingest/normalize.ts`). No offline number changes.
- `SEED-COMMANDS.txt` is generated per run with the four commands in order.
- `docs/worker-operations.md`: the new command order, the refusal log line, the bootstrap note
  (live D1 holds no marker, so seed before deploying this Worker), and the dated incident.

## Deviation

`SEED-COMMANDS.txt` is written by `writeSeedCommandsFile` in `seedSql.ts`, not inline in
`publish.ts`. `publish.test.ts` mocks `./seedSql.js`; an inline write would have put a real file in
the checkout on every test run.
