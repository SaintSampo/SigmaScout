<objective>
Scope the Teams-list metric snapshot to official play. Today a team's `teams/{year}` row carries
its SEASON-FINAL metrics, which keep learning through offseason (`event_type` 99) and preseason
Week-0 (`event_type` 100) matches — so an offseason result silently rewrites a team's position on
the season leaderboard. After this plan, the row carries the team's metrics as of its LAST OFFICIAL
match instead.

Purpose: the Teams list is the official-season leaderboard; an exhibition result must not move a
team on it. The team page header already does exactly this
(`apps/web/src/lib/officialSnapshot.ts`, 2026-09-01) — this plan brings the Teams list into
agreement with it and single-sources the predicate they share.

Output: a shared `isOfficialEventType` predicate in `packages/core`; an official-play snapshot in
the offline publisher; a gate on the Worker's live incremental merge; a republished
`teams/{year}` artifact; a transcribed publish-budget entry.
</objective>

  `metricHistoryForAlgo` — a `Map<teamKey, MetricHistoryRow[]>` built in the `onMatchComplete`
  hook, one row per match in chronological stream order, each row carrying `eventKey` and the
  team's `metrics` AFTER that match (D-28). This is exactly the per-match walk-forward series
  the fix needs; no second replay, no second corpus read.
- **Officialness classification:** `packages/corpus/schema.sql` derives `is_offseason` as
  `event_type == 99` ONLY. Preseason Week 0 (`event_type == 100`) is NOT flagged. The correct
  predicate is therefore `eventType !== 99 && eventType !== 100`, matching
  `apps/web/src/lib/officialSnapshot.ts`'s `!row.isOffseason && row.eventType !== 100` and
  `apps/web/src/components/events-list/filterModel.ts`'s `event.isOffseason || event.eventType === 100`.
  `publish.ts`'s `eventMeta` rows carry both `is_offseason` and `event_type`.
- **The second producer:** `apps/worker/src/scheduled.ts`. `runGlobalRebuild` (D-16) does a
  read-modify-write incremental merge of touched teams' live metrics into `teams/{year}`, fed by
  `touchedTeamsByAlgorithm`, which `runPhaseBAndReport` populates at its `seasonMap.set(teamKey, ...)`
  call. The live-windows manifest (`packages/harness/manifests.ts`) does NOT filter offseason, so a
  live offseason event reaches this path.
- **Downstream safety, already verified:** `apps/web/src/components/teams-table/rowModel.ts`
  documents that "a key the declared set contains but this row lacks is simply absent here, never
  defaulted", sorts rows missing the total key last without throwing, and `MetricValue.tsx` renders
  a single em-dash for an absent metric. `apps/web/src/lib/search-index.ts`'s `SearchTeamRow` reads
  only `teamKey`/`teamNumber`/`nickname` — so a row must KEEP existing even with no metrics, or
  offseason-only teams vanish from site search.
- **Percentile pool safety:** `packages/harness/percentiles.ts`'s `withPercentiles` skips any
