## Locked decisions (from the todo; do not revisit)

- **L-1 Unseen teams follow OFFLINE.** A roster team with no Sigma belief means no band and no RP, exactly as `SigmaScoutLayer.enrichUpcoming` (`allianceSigmaBandVariance` over `sigmaScoreByTeam()`, all-or-nothing). NOT the Worker's price-from-prior (`SigmaScoreAccumulator.bandVarianceFor`). Note the all-or-nothing unit is the ALLIANCE: the fully-seen alliance keeps its own band key, and RP needs both variances so the match gets none. Parity with `enrichUpcoming` is the contract.
- **L-2 State location.** Step 2 embeds a `state` block in the event artifact: the spr league row plus each roster team's row, with `sigmascoutSigma`/`sigmascoutRp` on team rows and the Sigma population and RP mean shift on the league row. Phase data is not needed by pricing but may be present.

## Decisions made in this plan (Claude's discretion)

- **D-A Rows stay verbatim `StateRow`s, `stateJson` kept as a string.** Block = `{ algorithmId, algorithmVersion, snapshotShapeVersion, rows }`, each row the seven `StateRowSchema` fields with its own `generation`/`computedAt`. Why: (1) a row is exactly a D1 `algorithm_state` record, so step 2's Worker splices the rows it just wrote with zero parse/re-stringify, and CPU on that tick is the entire reason for this direction; (2) the pricer passes `block.rows` straight into `deserializeState` and the four passenger readers, so no reader logic is duplicated; (3) per-row stamps survive, since touched rows carry the tick's stamp and untouched rows the seed's. Cost: escaped quotes plus repeated stamp strings, mostly absorbed by gzip/brotli. JSON number round-trip is exact for doubles, so either encoding preserves parity. The executor records the fixture block's raw and gzip bytes, beside a parsed-object variant, in the task summary.
- **D-B Extract row assembly, duplicate level-2 glue.** Row assembly (rounding, key-presence and comp-level gates) moves VERBATIM from `publish.ts` into browser-safe `publishedRows.ts`, called by the publisher and the pricer. No existing test scans that code as text, and the existing publish tests plus an independent rounding spot-check guard it. The level-2 read path (band + `#rpFieldsFor`) is MIRRORED in the pricer, not extracted: `sigmaScoutLayer.bandGuard.test.ts` pins `#rpFieldsFor`'s guard as source text inside `sigmaScoutLayer.ts`, so moving its body out needs a substantive edit to an existing test (forbidden). A delegating shim that keeps a redundant guard only to satisfy a text scan is worse than an honest mirror. The parity test and hand mutations guard the mirror. Every primitive is still the shared function: `spr.predict`, `allianceSigmaBandVariance`, `sigmaMatchBandVariance`, `RpMomentsAccumulator.fromBeliefs`/`momentsFor`, `RpMeanShiftAccumulator.fromState`/`apply`, `rosterIsFullyWarm`, `analyticRpPmf`, `rounding.ts`.
- **D-C Parity fixture = committed `packages/harness/fixtures/digest-slice.json`.** It is a 2022 slice: 3 regionals (eventType 0), 265 matches, every one with a score breakdown, including qf/sf/f. `sigmaScoutLayer.meanShift.test.ts` already shows every 2022 threshold variable passes mean-shift warmup on it. No corpus needed, so it works in a worktree.
- **D-D Invariants live in code, not the schema.** The zod schema is structural only, so a malformed block never fails the whole event-artifact parse in step 2. The builder enforces invariants at write time; the pricer re-checks at read time and throws a typed `EventStateBlockError` (step 3 falls back to published fields).
