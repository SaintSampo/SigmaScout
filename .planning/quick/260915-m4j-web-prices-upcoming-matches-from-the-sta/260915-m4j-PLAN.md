Step 3 of 4 of the browser-pricing direction (`.planning/todos/pending/rp-fold-exceeds-worker-cpu-budget.md`, "DIRECTION CHOSEN"). The web prices upcoming SPR matches from the event artifact's `state` block, team pages take upcoming rows from the event file, live event pages poll, and the orchestrator ships (republish, D1 seed, Worker deploy, web deploy) from the main context.

Locked decisions (Jacob, 2026-09-15; cited as LD-n in tasks):
- LD-1 Unseen teams follow the offline rule. It already lives inside `priceUpcomingFromState` (per-alliance band, no RP). The web adds no price-from-prior of its own.
- LD-2 Team pages fetch the event file for upcoming prices.
- LD-3 Polling is in scope (closes DATA-04 gap F.3).
- LD-4 Container is a series of quick tasks, not a phase.
- LD-5 Blocks exist only for events with a current schedule (7 days, `eventScheduleIsCurrent`). The web reuses exactly that function for its own "is this event live enough to fetch or poll" decisions.

WHERE PRICING RUNS, AND WHY: inside the TanStack Query `queryFn` of `eventQueryOptions`, right after the schema parse, through `resolveEventArtifact` (`apps/web/src/lib/eventPricing.ts`). A module-level memo sits on top, keyed by eventKey, algorithmId, algorithmVersion, generation, computedAt and the upcoming keys and rosters.
- A `select` cannot work. It must be synchronous, so it cannot await the lazy pricer chunk or `loadRpRuleModule`. It also runs separately in each observer: the event page, the match page and every team page.
- A derived second query was rejected. It adds a second pending state and paints unpriced rows for one frame before the priced ones.
- A render-path hook was rejected. It would run on the render path and be repeated by every consumer.
- The queryFn runs once per fetch per cache entry, off the render path. Its result is shared by every observer of the same key, and structural sharing keeps references stable when a poll returns identical prices.
- The memo stops a 60 s poll that returns the same generation from re-pricing.
- The resolved artifact has `state` removed, so no consumer can re-implement pricing.

UNPRICED-ROW DISPLAY DECISION (sketch-findings: "the row needs a deliberate empty treatment rather than a gap"; colour-and-tiers: a blank cell reads as missing data):
- The Confidence cell prints the muted words "No prediction" (`--color-text-muted`, `text-role-body`, testid `no-prediction-{matchKey}`).
- The Predicted RP cell renders nothing.
- The plot cell draws no tick, band or dot. No mark is drawn at a fabricated position, and the shared axis header still frames the row.
- The Call cell keeps the existing unplayed dash, and the scheduled time still shows in Actual RP.
- One-sided bands need no new treatment: `PredictedScoreLine` and `AllianceRow` already omit the plus-minus and the band per side when that side's variance is absent.

Output: the web data layer, lazy pricer chunk, unpriced rendering, team overlay with dedupe, polling, a web-layer parity test, a local visual fixture, and a verified build with chunk sizes recorded.
