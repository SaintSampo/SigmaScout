# OPR and EPA fold live alongside SPR

Jacob's decision 2026-09-23 on `260923-1tu-FINDINGS.md` item C6. `LIVE_ALGORITHM_IDS` was `"spr"`
because the free plan's 50-subrequest cap made a three-algorithm event defer every tick, and then
because its 10 ms CPU cap did; Workers Paid (2026-09-22) retired both and quick task 260923-3w4
deleted the cap and the deferral machinery.

**Net: 12 files changed, 496 insertions, 111 deletions, across three commits.**

**Published numbers change, and that is the point.** OPR and EPA ratings now advance within a cron
minute of a result being posted instead of standing still between manual re-baselines, so both ship
under a new major version. No prediction math moved, and SPR's version is unchanged.

## What changed

### 1. opr 6.0.0 and epa 13.0.0 (`610e4d9f`)

`opr.ts` `5.0.0+baseline` to `6.0.0+baseline`, `epa.ts` `12.0.0+baseline` to `13.0.0+baseline`, each
with a history entry naming the quick task, the date and why major. The two literal equality pins
moved with them (`opr.test.ts`, `epa.test.ts`).

`data/baselines/level1-digest-2026-09.json`: only the two `algorithmVersion` strings moved; the diff
is exactly two lines. All three `predictionStreamSha256` values are byte-unchanged and still
reproduce bitwise under `level1Digest.test.ts` against both `data/corpus.sqlite` and the committed
slice fixture. That is the proof the math did not move. The `bpr` entry resolves to `spr` through
the file's alias and records `7.0.0+baseline`, which equals `SPR_VERSION` today; left as is.

Left alone deliberately: historical prose in `spr.ts` and `docs/models/*`, frozen measurement
records under `data/baselines/` and `data/diagnostics/`, pasted census transcripts in
`docs/publish-budget.md`, and fixture version strings in `apps/web` tests and
`scripts/pruneR2Generations.test.ts`, none of which reads a module version or the real manifest.

### 2. The tier is opr, epa, spr (`fc062cc7`)

`wrangler.toml`: `LIVE_ALGORITHM_IDS = "opr,epa,spr"` in `PUBLISHED_ALGORITHM_IDS` display order, and
the 24-line comment above it replaced with one paragraph. Order is cosmetic: `buildAlgorithmModules`
turns the list into a `Set` and fold order comes from the algorithms manifest.

`DEFAULT_LIVE_ALGORITHM_IDS` now equals the tracked value (`[...PUBLISHED_ALGORITHM_IDS]`) so a
dropped `--var` cannot silently narrow the tier; the `live-tier-defaulted` warn line makes the
omission audible. `publishedAlgorithms.ts`'s comment now separates RP odds (SPR only) from live
folding (all three).

A finding, fixed here: 260923-3w4's commit `4671401d` deleted the describe block holding the
tracked-value equality pin along with the budget arithmetic, leaving the toml-reader helper unused,
so the deployed value was untested for part of 2026-09-23. `apps/worker/test/liveAlgorithmTier.test.ts`
now has three pins (raw tracked string, its parse equals `PUBLISHED_ALGORITHM_IDS`, the default equals
it), every fold assertion derives from the tracked value, and narrowing the value to `"spr"` was
shown to fail exactly those three. New tests: with the tracked tier every id writes league and team
state and exactly the `EVENT_SCOPED_ALGORITHM_IDS` members write an event row, and each id gets an
event artifact, a team artifact per played team and a `teams/{year}` rebuild; a promoted
never-published event bootstraps for every tracked id. The manifest fixture's opr and epa versions
now come off their modules.

No production code needed changing for the widening itself; the fold path was already
algorithm-agnostic.

### 3. Docs (`33445847`)

`docs/worker-operations.md`'s "Live folding tier" section now leads with the contract (all three
published algorithms fold live) and marks the old reasoning as history. 260913-ppk's reason (b),
the shared per-event cursor and TBA ETag, is now the argument for all three rather than one, with an
explicit "do not reintroduce a rotation". The shape-16 seed bullet and the stale-opr/epa
troubleshooting row are updated: a partial seed now leaves opr and epa unfoldable rather than
merely unread. `docs/publish-budget.md`'s live-Worker write table is now actual rather than
forward-looking, and its "Re-baseline cadence" command block gains the previously omitted
`seed-cursors.sql` (following the block as written would have left every tick refusing to fold).

## Seed and rebaseline readiness (verified, nothing changed)

`publish.ts` emits one `seed-{id}.sql` per resolved published algorithm at that module's own
version and passes the same id set to `emitCursorSeedSql`; `scripts/rebaseline.ts` names all four

`scripts/pruneR2Generations.ts` selects on exact generation equality, so `opr@5.0.0+baseline` and
`epa@12.0.0+baseline` become orphans once the manifest names the new versions and
`spr@7.0.0+baseline` is refused as live; `scripts/publishProbeStubs.ts` already loops every
algorithm the live manifest names.
