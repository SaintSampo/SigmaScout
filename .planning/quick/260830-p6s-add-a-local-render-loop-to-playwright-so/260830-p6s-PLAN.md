# Quick Task 260830-p6s — Add a local render loop to Playwright

<objective>
Give `apps/web`'s layout/visual e2e specs a **local** page origin to run against, so the
render-and-look loop closes during a phase instead of only after a deploy.

**Why (G-06-2, verbatim):** *"the loop that catches bad UI is rendering it and looking. In this
phase that loop was structurally broken, which is why 9 plans and 7 planning documents did not
catch a layout defect visible in one glance"* — because `apps/web/e2e` has no local `webServer`
and asserts only against the deployed origin, and the deploy workflow had been dead. So
`no-page-pan.spec.ts`, **a spec that already encoded that exact bug**, had never actually run.
Phase 7 then shipped 8 more visible layout defects (07-UAT G-3/G-4/G-5/G-6/G-7/G-9/G-12/G-13),
each of which became an e2e spec only AFTER a human found it by looking.

**The one hard problem this task must actually solve.** `playwright.config.ts`'s own header
explains why there is no local `webServer`: `https://data.sigmascout.org`'s R2 CORS policy
(Phase 5 D-18) allow-lists only the site's real origins — `localhost` is not among them — so a
local page's artifact fetches CORS-fail and every page renders empty. This is not a detail to
route around; it is the reason the loop was broken. Two facts already in the repo make it
solvable without touching R2's CORS policy or inventing a fixture corpus:

1. `src/lib/artifactOrigin.ts` already reads `import.meta.env.VITE_ARTIFACT_ORIGIN`, and its own
   comment says it exists so "a local fixture server can stand in during development/preview
   testing." It is the ONLY place an artifact host string appears in `apps/web`.
2. Vite's preview server can proxy. Point the built app's artifact origin at the preview server
   itself and proxy `/v1/*` through to R2 server-side: the browser then makes a **same-origin**
   request and CORS never enters the picture. The bytes are still the real published artifacts.

(Note: `scripts/fixture-server.mjs`, referenced by `table-layout-quality.spec.ts`'s header, does
not exist in the repo — it was a throwaway during 07's gap-closure work. Do not look for it.)

Purpose: infrastructure for Phase 8, which adds three brand-new visual surfaces.
Output: a `webServer` + two local Playwright projects + a `test:e2e:local` script, and a real,
output-based report of what the loop finds on first run.

**This task builds the loop. It does not repair what the loop finds.**
</objective>
