**D-3 revised (commit `4927ef08`).** The user revised D-3 the same day, before any of it was

on 2022–2026, and origins become 2024/2025/2026/2027.

The stated reason was year-round maintainability, and it holds on honesty grounds independently:
it deletes the live-params-versus-evaluation-params special case entirely, it is temporally
honest by construction, and it makes each season headline-eligible automatically once played.

## The one open sub-question this surfaced

**Which parameter set scores 2022 and 2023?** All five seasons are published on Compare today
and every 2022/2023/2024 slice carries `seasonLabel: "tune"`. Under the decided scheme neither
2022 nor 2023 has an origin, so neither has an honestly out-of-sample set — anything that scores
them was selected having already seen them. D-4 removes their headline claim but does not say
what produces the numbers still shown. Recorded as explicitly unanswered; must be decided before
the republish.

## The tradeoff D-3's revision accepts

The preseason set ships **ungated**. D-T7 compares a candidate against the incumbent *on the
origin season*, and the live season has no data yet, so there is nothing to run the gate
against. The accepted handling is retroactive: score the season when it completes, record
whether the set actually beat the incumbent, and let that inform the next preseason's search.

A consequence worth carrying forward: this makes `tune.ts`'s **gate 4** — winner written to disk
before any origin-season evaluation — load-bearing. For the back origins it is a belt-and-braces
check with the acceptance gate behind it; for a live season it is the *only* thing making the
eventual score honest. A refactor that relaxes gate 4 silently invalidates every future headline
season.
