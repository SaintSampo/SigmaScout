# Alliance selection readability — plan

Jacob queued this straight after 260925-uf8. The Alliance selection cell prints
`~80% picked / ~12 if picked`, where "picked" silently counts captains too, so the
cell answers a question no reader asked: it never says which route the team is
actually on.

**Untouched, by instruction:** Qualification, the status rule, the lock math, the
tenets, the reservation and the pooled lock. `measure:ledger-tenets` runs at the
end: both tenets zero, totals identical to 260925-pl6.

## Task 1 — the draw reports the ROUTE, not just the points

`packages/core/districts/ledgerSimulation.ts`. The joint draw already knows, per
run, which slot of which alliance every team filled — it is how `selection[teamI]`
gets its value. Today that fact is thrown away the moment the points land in the
histogram.

- new result field `selectionRoutes: ReadonlyMap<string, DistrictSelectionRoutes>`:
  per team, per TBA pick slot (0 captain, 1 first pick, 2 second pick, 3 backup
  robot), the draw count, the observed point range, the single alliance number
  every run agreed on where they agree, and the range that slot CAN pay at this
  event's alliance count from `districtSelectionPoints` — plus the not-selected
  count.
- new result field `rankingFixed: boolean`: the run had no remaining
  qualification matches, so every draw shared one finishing order and the draft it
  produced is a fact rather than a prediction.
- **No randomness is consumed.** The route is read off the draft, which is
  deterministic given the ranking; every seeded output is byte identical, and a
  test pins that.

## Task 2 — the route chances reach the cell

`districtSimulationProtocol.ts` forwards `DistrictLedgerResult` UNRESHAPED, so the
wiring is a structured-clone assertion rather than a new message field; a test pins
that the routes and `rankingFixed` survive the boundary in both directions.

`districtLedgerRows.ts`: `DistrictEventDistributions` gains
`selectionRoutesByTeam` and `rankingFixed`, `distributionsFromResult` passes both,
and the open Alliance selection cell carries them. `distributionsFromPreSim` has
only pmfs, so a BAKED event carries neither: that cell keeps today's wording and
the gap is disclosed as `eventsWithUnknownSelectionRoutes`.

**Commit:** `feat(260925-w4y): the route chances reach the alliance selection cell`

## Task 3 — the bold line names the likelier route

`districtLedgerOutcomes.ts` gains `districtSelectionHeadline` (captain against
first plus second pick) and `districtSelectionSettledRoute` (one route, one
alliance number, a fixed ranking). `districtLedgerCopy.ts` gains the route words
and `districtLedgerSelectionSettledLine`; every string is pinned.

| what the runs say | bold | small |
|---|---|---|
| captain is the likelier route | `captain ~70%` | `~12 if in` |
| picked is the likelier route | `picked ~44%` | `~12 if in` |
| above the 99.5% chance form threshold | `~12` | `likely 12.0–12.0` today, `captain, alliance 5` once the ranking is fixed |
| the routes are unknown (a baked event) | `~80% picked` | `~12 if picked`, byte for byte as today |

**Commit:** `feat(260925-w4y): the alliance selection cell names the likelier route`

## Task 4 — the outcome list in the drawer

`districtSelectionOutcomes` builds the rows: captain, first pick, second pick, not
selected, with the chance from the route counts and the points as the range the
runs produced (a single value where they pin it). A row the RANKING has ruled out
is omitted, on the same terms the playoff list omits a placement the bracket has
ruled out: with a fixed ranking the draft is deterministic, so a route no run took
cannot happen. With the ranking still open every row stays, so the list's length
does not move with the draws. The grand total plot stays beside it.

`DistrictOutcomeList` gains an optional `pointsHigh`, so the shipped playoff and
award rows render byte for byte.
