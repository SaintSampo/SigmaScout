# Quick Task 260904-6k1: Ribbon-Sigma Favicon Summary

SigmaScout now ships a font-independent SVG favicon — the ribbon's light-green sigma stroked on its dark-green tile — declared in `index.html` and locked to `theme.css`'s `--ribbon-bg`/`--ribbon-accent` tokens by a drift test.

## What Was Built

**`apps/web/public/favicon.svg`** — a standalone 32x32 SVG document with a `<title>SigmaScout</title>`, a full-bleed `#14532d` background rect (literal copy of `--ribbon-bg`), and the sigma drawn as a single open polyline (`M25 7 H8.5 L16.5 16 L8.5 25 H25`, `stroke-width="3.4"`, `stroke-linecap="butt"`, `stroke-linejoin="miter"`) stroked `#81c784` (literal copy of `--ribbon-accent`) with `fill="none"`. No script element, no `@font-face`, no remote reference — geometry and solid colors only.

**`apps/web/index.html`** — added `<link rel="icon" type="image/svg+xml" href="/favicon.svg" />` in the head, after the viewport meta and before `<title>`, following the same `/`-rooted `public/` convention `__root.tsx`'s `/alfredo-systems.png` already uses.

**`apps/web/src/favicon.test.ts`** — 9 tests across three groups:
- Color drift guard: regexes `--ribbon-bg` and `--ribbon-accent` out of `theme.css` at test time (throwing if either fails to match, so a renamed token fails loudly) and asserts `favicon.svg`'s text contains each captured value case-insensitively.
- Wiring: asserts `index.html` has an icon `<link>` with a `/`-rooted href, and that the corresponding file exists under `apps/web/public/`.
- Self-containment: asserts absence of a script element, `@font-face`, `xlink:href`, `href="http`, and any `<text>` element; asserts the SVG parses as well-formed XML via `DOMParser`.

All file paths are resolved via `fileURLToPath(new URL(..., import.meta.url))` relative to the test module, not the process cwd, per this repo's recorded test-scope trap (a bare `vitest run` at the repo root sees a different file set than `apps/web` alone).

## Visual Verification

Wrote a scratchpad-only preview HTML page (never committed) that inlined the favicon markup at 16px/32px/64px on both white and dark strips, screenshotted it with `npx playwright screenshot`, and read the resulting PNG. The sigma reads clearly and unambiguously at all three sizes, including 16px — arms stay distinct from the diagonals and the glyph sits optically centered. No stroke-width or path adjustment was needed after the first render.

### Auto-fixed Issues

**1. [Rule 1 - Bug] Malformed XML comment in favicon.svg**
- **Found during:** Task 2, running the new well-formedness test
- **Issue:** The first-drafted SVG comment (Task 1) contained double-hyphen sequences (`--ribbon-bg`, ` -- the same pairing`), which is illegal inside an XML/HTML comment (`--` may not appear except as the closing `-->`). `DOMParser` reported `malformed comment` and the file failed to parse as well-formed XML.
- **Fix:** Reworded the comment to avoid any `--` sequence (spelled out "ribbon background token" / "ribbon accent token" instead of the literal `--ribbon-bg`/`--ribbon-accent` names, and removed the standalone `--` used as an em-dash substitute).
- **Files modified:** `apps/web/public/favicon.svg`
