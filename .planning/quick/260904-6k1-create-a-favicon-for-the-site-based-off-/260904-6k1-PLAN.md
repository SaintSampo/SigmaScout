  <action>
    Create `apps/web/public/favicon.svg` as a standalone SVG document (it needs its own
    `xmlns="http://www.w3.org/2000/svg"`; give it `viewBox="0 0 32 32"` plus explicit
    `width="32" height="32"`, since some icon renderers want an intrinsic size).

    Two painted elements only. First, a full-bleed background rect covering the whole
    32x32 viewBox, filled `#14532d` — a literal copy of theme.css's `--ribbon-bg`. The
    tile is required, not stylistic: `#81c784` is legible on this dark ground and is
    documented in both theme.css and Ribbon.tsx as failing on white, so a transparent
    icon would disappear against light browser chrome.

    Second, the sigma, stroked `#81c784` (a literal copy of `--ribbon-accent`) with
    `fill="none"`. Draw it as a single open polyline, NOT as a rendered glyph — a
    favicon document cannot pull in Inter, so a glyph-based mark would fall back to an
    arbitrary system face and change shape per machine. Start from
    `d="M25 7 H8.5 L16.5 16 L8.5 25 H25"` with `stroke-width="3.4"`,
    `stroke-linecap="butt"` and `stroke-linejoin="miter"`. That traces the sigma the way
    it is written: right-to-left along the top arm, down-right to the centre vertex,
    down-left to the bottom-left corner, then right along the bottom arm. The centre
    vertex's interior angle is wide enough (~84 degrees) that the miter stays well
    inside the default miter limit, so no spike appears there.

    Add a `<title>SigmaScout</title>` as the first child for accessibility. Add one
    short comment naming theme.css's two `--ribbon-*` tokens as the source of the two
    colors and pointing at `apps/web/src/favicon.test.ts` as the drift guard — matching
    the static-shell block's existing copy-not-derivation convention. Keep the whole
    document self-contained: geometry and colors only, no scripting element, no embedded
    font declaration, no remote or linked resource of any kind. Keep the comment itself
    free of any URL-like or resource-reference text, since Task 2's guards read the raw
    file rather than a parsed DOM.

    Then declare it in `apps/web/index.html`: add
    `<link rel="icon" type="image/svg+xml" href="/favicon.svg" />` in the head, placed
    after the viewport meta and before `<title>`. `/favicon.svg` is the right href
    because Vite serves `public/` at the site root — the same mechanism that makes
    `__root.tsx`'s `/alfredo-systems.png` resolve. Ship the SVG only; no .ico and no
    PNG fallback, both of which would need image tooling this repo does not carry, and
    every browser this SPA already targets supports SVG icons.

    Now confirm it actually reads as a sigma at real favicon size, rather than assuming
    it. Playwright is already a devDependency here (`apps/web/playwright.config.ts`), so
    no new dependency is needed. In the session scratchpad (never in the repo), write a
    small preview HTML page that embeds the favicon's markup INLINE three times — at
    16x16, 32x32 and 64x64 — laid out on a white strip and again on a dark strip. Inline
    the markup rather than pointing an image element at the file: a file-origin page
    loading a file-origin subresource is restricted in Chromium and would render empty,
    which looks exactly like a broken icon and is not one. Screenshot that page with
    `npx playwright screenshot`, then read the resulting PNG and look at it. Adjust
    `stroke-width` and the path's endpoints until the 16px rendering reads unmistakably
    as the ribbon's sigma — check specifically that the arms have not merged into the
    diagonals and that the glyph sits optically centred (the left corners' miters push
    the painted edge a little further left than x=8.5, so exact coordinate symmetry is
    not optical symmetry). If the Chromium binary is missing, run
    `npx playwright install chromium` first; if that is unavailable too, fall back to the
    human-check below.
