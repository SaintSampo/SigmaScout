# The tick before the first score

`processEvent` returns `{ status: "unchanged" }` whenever `newlyFolded` is empty, so a
promoted event whose schedule is posted but unscored writes nothing, and the Worker never
fetches TBA's team registration at all. Seven offseason events this weekend (2026miwyo,
2026nhgc, 2026flroc, 2026njrr, 2026vaale1, 2026wass, 2026isist) still serve the
2026-09-23 stub with zero teams and zero upcoming rows, although TBA already lists
17/28/32/18-team rosters and a 42-match schedule for 2026isist.

Two changes, both applying to probe (`inferred: true`) AND measured (`inferred: false`)
windows:

1. **Schedule-only pricing.** A 200 with an empty `newlyFolded` and a non-empty
   `stillUpcoming` runs Phase A's state read and accumulator resume, builds the same
   `UpcomingPricingModel`, and runs Phase B — priced upcoming rows, the event artifact,
   and a team artifact per real scheduled team. No `algorithm_state` write, no claim.
2. **Roster pickup.** One extra conditional `GET /event/{key}/teams/simple` per open
   window per tick, its etag in a new `event_cursor.roster_etag`, appending the missing
   registered teams to each algorithm's event artifact with their real numbers and names.

**Ordering inside one tick for one event:** roster pass first, then the match preflight, so
a schedule-only write sees the roster rows already merged. The artifact must never lose
rows between the two.

**Not in scope, named so it is not mistaken for an oversight:** upgrading an *existing*
`teams` row whose `nickname` is `""` / `teamNumber` is `0` (the shape a fold appends for a
team it has no registration for). Roster-first ordering makes that rare, and a republish
heals it. The roster path appends missing teams only.

**Accepted consequence, stated up front:** the schedule-only team-artifact write puts every
scheduled team through `touchedEventTeamMetrics`, which drops `percentile` from
`seasonStats.metrics`. That is the existing, tracked
`.planning/todos/pending/live-merges-drop-percentiles.md` limitation; this change makes it
bite when the schedule is posted rather than when the team's first match is folded. The
tier box still resolves from `tierCuts`. Do not invent a second metrics path to avoid it.
