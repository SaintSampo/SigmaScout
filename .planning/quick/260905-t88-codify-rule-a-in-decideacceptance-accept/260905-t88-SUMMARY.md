out-of-sample winner accuracy AND Brier over the live incumbent) instead of the retired D-T7 noise
bar, so future tunes' printed verdicts match the policy the operator already adopted by hand on
2026-09-05 to promote `vpr@9.0.0+rolling-2026-09c`.

## Accomplishments

- **The gate (Task 1, RULE-A/DIAG).** `decideAcceptance` now evaluates, first match wins: accuracy
  half (`accuracyMargin > 0`, strict) -> `no-accuracy-gain`; Brier half (`candidateBrier <
  incumbentBrier`, strict) -> `brier-regression`; the unchanged MAE veto -> `mae-veto`; otherwise
  `accept`. `KeepIncumbentReason` is now exactly `"no-accuracy-gain" | "brier-regression" |
  "mae-veto"` — the retired `"below-threshold"`/`"brier-veto"` values are removed from the type
  (not left unreachable), documented in the header as the pre-2026-09-05 artifact vocabulary.
  `AcceptanceEvidence` gained `clearedNoiseBar: boolean` (`accuracyMargin > threshold`), reported on
  every outcome and read in zero branch conditions; `threshold` and `brierVetoBound` are still
  computed from the unchanged formulas and still reported, now purely as diagnostics. The Brier
  veto's constants (`ACCEPTANCE_BRIER_VETO_RELATIVE_TOLERANCE`/`NOISE_MULTIPLE`) and its
  `brierVetoBound` computation stay — the veto branch itself is deleted because Rule A's strict
  Brier-improvement requirement strictly subsumes it. `acceptance.test.ts` pins all three todo
  fixtures, the 2026-09-05 motivating case (a sub-bar accuracy margin with an improving Brier still
  accepts, `clearedNoiseBar === false`), both strict ties, the retired veto's two halves merged into
  one test proving they no longer decide, and every existing MAE-guardrail case re-pointed to the
  new improving-Brier base fixture — 20 tests, all green.
- **The reporter (Task 2, PROSE).** `buildAcceptanceReport`'s shared verdict prefix now reports
  both the signed accuracy margin AND the signed Brier delta (Rule A has two halves, a reader needs
  both numbers), stays sign-neutral (260904-4ik's fix carried forward), and ends with a
  self-contained bar clause driven by `outcome.clearedNoiseBar` that states the bar is diagnostic
  only since 2026-09-05 and whether it was cleared or not — worded so "CLEARED" and "NOT CLEARED"
  cannot be confused by a bare substring match. All four branches (`accept`, `no-accuracy-gain`,
  `brier-regression`, `mae-veto`) now name RULE A explicitly. The budget-tradeoff print no longer
  claims a smaller `--evals` "relaxes the bar" — under Rule A `--evals` buys search breadth only and
  has no bearing on the ship/don't-ship gate; the retired bar's `sqrt(2 ln N)` scaling is kept as an
  illustrative diagnostic figure. The module header's "D-T7's pre-committed acceptance rule" section
  is rewritten to state Rule A as the gate, keeping the "keep-incumbent is a SUCCESSFUL result"
  contract and the three-distinct-SE-names paragraph intact. `tune.test.ts`'s
  `buildAcceptanceReport` describe block now asserts all four Rule A outcomes plus the below-the-bar
  accept case, matching the full CLEARED/NOT CLEARED fragment rather than a bare substring — 90
  tests in the file, all green.
- **Prose at the edges (Task 3, PROSE).** `objectiveDefinition.ts`'s doc comment above
  `SEARCH_OBJECTIVE_DEFINITION` no longer claims "the same rule... governs D-T7's ship/don't-ship
  acceptance bar" — replaced with an accurate statement that the search objective ranks candidates
  and the ship decision is a different, deliberate rule (Rule A). Both exported string constants
  are byte-identical (verified via `git diff`), since they are written into promoted version files'
