# The wire format (final; the spike's format with four changes)

Team tuple `T = [spr | null, sigma | null, vars | null]`, league tuple `L`, exactly as
`scripts/asOfSpike/format.ts`. Full precision numbers, plain JSON.

Changes from the spike:

1. KEYS are `[t, i]`: sort_time and the row index in that event's log. Order is
   `(t, eventKey, i)`; inside one event compare `i` only.
2. SEGMENTS. A team's INDEX entry is an ARRAY of segments, each
   `{ f: [t,i], l: [t,i], p: [prevEventKey, t, i] | null, s: T, x: T }`. A segment is a maximal
   run of the team's consecutive matches at this event in the team's own season sequence. A team
   that plays here, then at another event, then here again has two segments here. This fixes the
   overlap defect in SPIKE.md section 5 (division plus Einstein, DCMP parent plus division).
3. DEMO. A row with any demo robot key also carries an entry for `DEMO_PSEUDO_TEAM_KEY` with
   `[spr, null, null]`; raw demo keys carry `[null, sigma, vars]`. The pseudo team has its own
   segments and tail, so its SPR state resolves like any team's. The pricer sets the pseudo
   team's state whenever a roster holds a demo key.
4. INDEX also carries `m: [[matchKey, t], ...]` in fold order (row index = array index), and
   `lq` / `le` become `{ k: [t,i], L }`. The per season object is ONE object:
   `{ season, L0, tails: { [teamKey]: [eventKey, t, i] } }`.

Artifact keys (add to `packages/harness/pageArtifacts.ts` beside the others, algorithm scoped
preamble like the event artifact): `v1/asof/{eventKey}/{algo}@{version}.json` (INDEX),
`v1/asof-log/{eventKey}/{algo}@{version}.json` (LOG),
`v1/asof-season/{season}/{algo}@{version}.json` (season). SPR only.

# Part 1b: season start tuples (amendment found by Part 1's truncation test)

Part 1's truncation test compares only teams seen by the cut, because a team with no match yet
this season has no INDEX entry in a truncated capture and resolves as unseen, while the full
capture later hands back its carried pre season tuple through `s`. In a LIVE season the
truncated world is the real one, so a rewound stop would price such a team as a rookie and the
number would move once the team plays. That violates the acceptance rule.

- New per season object `v1/asof-start/{season}/{algo}@{version}.json`: `{ preamble, season,
  vars, teams: { [teamKey]: T } }` holding the pre season tuple of EVERY team the carried state
  holds at the season boundary (SPR carried team state, carried Sigma belief; RP part null),
  written by the offline publisher for every published season, including a season with zero
  played matches. The Worker never writes it. Add its key function, schema, publish budget
  family and ceiling like the other three.
- `resolveAsOf` takes `start: AsOfStart | null | undefined`: a team with no segment at or before
  the cut reachable and no tail resolves to `start.teams[teamKey]`, or unseen when the start
  object has no entry. `undefined` adds `missingStart: true` to the result so the caller fetches
  it only when some requested team needs it; `null` (unpublished) throws like the other objects.
- Extend the fixture truncation test to compare EVERY roster team, including teams with no match
  by the cut, and `scripts/verifyAsOfOracle.ts`'s truncation check likewise. Report the start
  object's raw, gzip and brotli size per season from the verify script.
