**Depth:** deep (cross-file call tracing). **Read-only:** no source file was edited, nothing committed.

## Confirmed defects

### C1. A stale season tail makes the reducer write a segment that leaks later state, silently
**Severity: high. Class: BLOCKER. Confidence: confirmed by probe.**
**Where:** `packages/harness/asOfState.ts:470-481` (grow test at 473), reached from
`apps/worker/src/asOfCapture.ts:199-216`; read back by `packages/harness/asOfLookup.ts:177-181, 209-211`.

`applyAsOfFold` decides "grow the last segment or open a new one" from the season object's tail
alone, so a tail that is behind the INDEX opens a second segment at the same event whose `p`
points INSIDE the first segment.

Failure scenario: tick N writes the LOG and the INDEX and the season object PUT fails (or the
documented overlapping invocation drops the tail, `apps/worker/src/asOfCapture.ts:36-39`). Team X
now has segment rows 0 to 3 in the INDEX and a tail at row 1. Tick N+1 folds X again: the tail is
not the segment's `l`, so a new segment opens with `p = [E, t, 1]` and `s` = X's state after row 3.
A rewound stop at row 2 then picks that second segment (it begins after the cut), sees `p` at or
before the cut, and returns `s`. Probe output:

```
S1 segments for frc1: [{"f":[100,0],"l":[130,3],"p":null,"s":0,"x":4},{"f":[140,4],"l":[140,4],"p":["2026e",110,1],"s":4,"x":5}]
S1 cut at row 2 -> matches-played value 4 (truth 3)
S1 cut at row 0 threw: resolveAsOf: frc1 has no segment at 2026e ending at row 1
```

So the stop at row 2 prices X from a match played after the cut, with no error, and a stop at
row 0 throws. Both last until the next republish. The Worker header lists these two triggers under
"KNOWN LIMITS, all healed by the next republish", which describes a slightly different league row
and does not say lookups go silently wrong.

Fix direction: make the INDEX authoritative when it is ahead of the tail (if the team's last
segment here ends later than a tail that points at this event, grow it and set `p` from `last.l`),
and protect the season object's read-modify-write with an R2 conditional put (`onlyIf` etag) plus
one retry.

### C2. One failed INDEX PUT after a successful LOG PUT stops the event's capture for good
**Severity: medium. Class: BLOCKER. Confidence: confirmed by probe.**
**Where:** `apps/worker/src/asOfCapture.ts:214-216` (three unconditional PUTs in sequence),
`packages/harness/asOfState.ts:462-464` (the refusal).

The LOG is written first; if the INDEX PUT then fails, R2 holds a LOG one or more rows longer than
its INDEX, and every later tick's `applyAsOfFold` throws on the length check, so nothing is ever
written for that event again.

Probe output: `S2 next tick threw: applyAsOfFold: 2026e's INDEX holds 2 rows and its LOG 3`.

Failure scenario: a transient R2 error (or an invocation killed between the two PUTs) during a
live event at match 30. Matches 31 onward are folded into D1 normally but each tick logs
`asof-write-failed` and writes nothing. Every rewound stop anchored on a row after match 29 is
"not in the INDEX", which `resolveStopCut` turns into the WHOLE stop unavailable for the district
(`apps/web/src/components/districts/asOfRewind.ts:90-91`), until a republish. The header says a
failed write "is not retried: those matches are already folded"; it does not say the event is
wedged.

Fix direction: when the LOG is longer than the INDEX, truncate the LOG to the INDEX length before
applying (those rows are orphans that can never be indexed), instead of refusing.

### C3. A bracket in progress, or awards not yet posted, reads as FINAL at later rewound stops
**Severity: medium. Class: BLOCKER. Confidence: confirmed by reading; no test covers the case.**
**Where:** `apps/web/src/components/districts/districtTimeline.ts:281-287` and `365-391`.

`playoffsAhead` requires `playoffMs === null`, so an event with SOME played playoff rows and
`playoffsDone === false` places both its Playoffs and Awards steps at its latest played playoff
row so far, and `awardsPosted` is never consulted for the Awards step. `districtStageAtPosition`
then marks `elim` and `award` final at every rewound position after that row, with no intersection
against `nowStageByEvent`.

Failure scenario: Saturday, event E has played 5 playoff matches (last at 2:10 pm), event F plays
a qualification match at 2:30 pm. Rewinding to F's 2:30 match (or F's Quals Done milestone) reads
E's playoff points and award points as final from the district artifact (partial or zero), while
"Now" still shows them open and simulated. Same shape after E's finals until TBA posts awards:
every stop after E's last playoff row reads E's awards as final zeros. A rewound view is then MORE
settled than the live one, which understates totals and can flip a lock status.

This is narrower than before the change (the old shared instant had it from the last
qualification match on), but the new placement code states "so no stop reads its playoff points as
final before they are played" and only covers the no-played-row case
(`districtTimeline.test.ts:444-452`).

Fix direction: a category open at "now" can never be final at an earlier stop. Either gate on
`playoffsDone === false` regardless of `playoffMs` (and the Awards step on `awardsPosted`), or AND
each rewound category with `nowStageByEvent`.

### C4. `resolveAsOf` returns a stale tuple without complaint when a LOG copy is shorter than its INDEX
**Severity: medium. Class: WARNING. Confidence: confirmed by probe; the production trigger is plausible, not observed.**
**Where:** `packages/harness/asOfLookup.ts:200-207`.

The scan starts at `Math.min(segment.l[1], log.rows.length - 1)` and never checks that the LOG
holds every row the INDEX names at or before the cut, so a short LOG yields the team's older row.

Probe output: `S3 short LOG -> matches-played value 3 (truth 4) missingLogs []`.

Failure scenario: the browser holds a fresh INDEX for a live event G and a LOG for G cached a
minute earlier (the two are separate objects with separate 60 s edge and query cache lifetimes).
A stop in another event F whose cut falls after G's newest row prices a G team from the state
before its latest match. Not a leak (the state is older, not newer), but it is a wrong number
with no "unavailable". The Worker's "LOG first" write order was meant to prevent exactly this and
cannot once the copies are cached independently. Same outcome for a team that played at an event
whose capture is wedged (C2).

Fix direction: before scanning, compare against the INDEX in hand (`index.m.length` versus
`log.rows.length`, or the INDEX `m` times for rows at or before the cut) and report the LOG as
missing (refetch) or throw.

### C5. `--write-budget` throws at the end of a run that published only start and season objects
**Severity: low. Class: WARNING. Confidence: confirmed by reading.**
**Where:** `packages/harness/publishBudget.ts:343-350`, called from `packages/harness/publish.ts:3037`.

`renderPublishBudgetBlock` requires all four as-of families whenever any is present. A run whose
published seasons have zero played matches writes `asof-season` and `asof-start` and no INDEX or
LOG, so the doc writer throws after every upload has finished.

Failure scenario: a pre-kickoff publish of only the new season with `--write-budget`. `pnpm
publish:seasons` (2016 to 2026) is not affected. The as-of objects themselves are written
correctly for a zero-match season (`publish.ts:2779-2790`).

### C6. A REAL event that `buildDistrictEventSimulationInput` refuses vanishes instead of reading unavailable
**Severity: low. Class: WARNING. Confidence: confirmed by reading.**
**Where:** `apps/web/src/components/districts/districtRunAssembly.ts:280`.

`if (!built.ok) continue;` drops the event from the run AND from `asOfUnavailable`, so its open
cells have no distribution and no unavailable marker.

Failure scenario: a REAL event whose artifact has no teams and no remaining rows at the stop
(`asOfBaselines.length === 0`, `districtLedgerRows.ts:765`). The GENERATED branch handles the
equivalent case properly (`plan.roster.length === 0` pushes an unavailable entry, line 286).

## Risks worth a look

### R1. During a live event, separately cached season and INDEX copies make the live event unavailable at rewound stops, and the result sticks
**Severity: medium. Class: WARNING. Confidence: mechanism confirmed by reading and by the probe's throw in C1; frequency in production not measured.**
**Where:** `packages/harness/asOfLookup.ts:157-164, 189-191` (exact-match tail lookup),
`apps/web/src/lib/api/asOf.ts:52, 97-119` (independent 60 s copies),
`apps/web/src/components/districts/useAsOfRewind.ts:73-102` (no refetch until the key changes).

A team whose only known segment straddles the cut resolves through its season tail, and the tail
must name the exact last row of a segment in the INDEX copy. After each fold the six teams of
that match disagree between an older and a newer copy for up to a minute. The mismatch throws
`AsOfResolveError`, which the Locks loader turns into "unavailable" for the whole event
(`asOfRewind.ts:464-468`).

Why it may be frequent: the plan re-runs exactly when a live event artifact refetches with a new
fold (the fingerprint in the query key), which is the minute the copies are most likely mixed.
The "unavailable" result is then cached under that key with no `refetchInterval`, so it stays
until the next fold somewhere in the fetch set, and after the day's last match until remount. The
same holds for a stop anchored on a row the INDEX copy does not have yet
(`asOfRewind.ts:90-91`, whole stop unavailable).

On the Simulation tab the same mismatch is a silent fallback to the stored odds
(`simulationAsOf.ts:131-134`), so the same click can return as-of numbers or stored-odds numbers
depending on cache phase. The only marker is the `data-simulation-source` DOM attribute
(`SimulationTab.tsx:403`); nothing on screen says which one ran, although the plan calls this a
"labelled fallback".

Fix direction: on a tail or segment mismatch, refetch the season object and that INDEX once with
the cache bypassed before giving up; do not cache an "unavailable" plan for longer than a few
seconds while any fetched event is live.

### R2. A straddling segment in a known event is ignored, so the walk goes to the season tail and through every later event
**Severity: medium. Class: WARNING. Confidence: confirmed by reading; this is the plan's own walk rule, so it is a design weakness, not a coding slip.**
**Where:** `packages/harness/asOfLookup.ts:177-192`.

A known segment with `f` at or before the cut and `l` after it already contains the answer (the
team's matches in a segment are consecutive in its own sequence), but the start search skips it
and falls to the tail.

Consequence 1, cost: a Simulation tab SPR rewind into the middle of a finished week 1 event sends
nearly every roster team to its season tail, then back through every event it played later
(second district event, DCMP, Worlds, offseason), fetching each INDEX over several sequential
rounds before the Worker starts, when the event's own INDEX and LOG (already fetched) suffice.
Consequence 2, fragility: the answer for event E now depends on unrelated events' objects. If a
team from E is playing at a live event G, R1's mismatch at G makes E's rewind fall back or read
unavailable.

Fix direction: before the tail, take a known segment that straddles the cut and read its LOG.

### R3. A started event whose artifact failed to load is simulated as if it had not started
**Severity: low. Class: WARNING. Confidence: confirmed by reading.**
**Where:** `apps/web/src/components/districts/asOfRewind.ts:291-305`,
`apps/web/src/components/districts/useDistrictLedgerData.ts:102-115`.

The "started event must have an INDEX" guard only runs when `eventArtifact` is defined. An event
whose artifact query errored (not pending) has no artifact, no fetched INDEX, and goes to
GENERATED from district registrations, even at a stop after it has played matches. Not a leak
(it uses less information), but it prints a full generated forecast where the stated rule is
"unavailable, never something else".

### R4. First load of a late-season rewound stop pulls and validates many INDEX objects on the main thread
**Severity: low. Class: WARNING. Confidence: plausible, not measured.**
**Where:** `apps/web/src/components/districts/asOfRewind.ts:403-481`, `apps/web/src/lib/api/asOf.ts:54-66`.

Every started event's INDEX is fetched up front, then the tail walk (R2) adds each out-of-district
event any resolved team played later. Each object is Zod-parsed on the main thread (the largest
measured INDEX is 179 KB, LOG 1.3 MB, start object 746 KB). The plan's own post-part step asks for
rewound load time and bytes; this is where to look. While a district event is live the whole set
is re-validated each minute (conditional requests) because the fingerprint re-runs the plan.

### R5. A timeline reorder restarts the rewound run despite the placeholder
**Severity: low. Class: WARNING. Confidence: confirmed by reading; effect is a visible re-run, not a wrong number.**
**Where:** `apps/web/src/components/districts/useAsOfRewind.ts:73, 96-101`.

`positionIndex` is part of the query key and only the fingerprint slot is exempt in the
placeholder test. When a live refetch moves a row's `sortTime` (predicted to actual) the same stop
id gets a new index, the placeholder is refused, the view drops to "loading", the Worker is
terminated and every event is baked again. Commit 823605bf meant to prevent that restart.

## Categories with nothing found

1. **Leaks, consistent objects.** With objects written by one offline publish, I found no path by
   which a rewound Locks stop or the SPR Simulation rewind reads a stored per-row prediction,
   `teams[].metrics`, a baked sidecar, or a row after the cut: `bakedKeys` is empty when rewound,
   REAL inputs carry empty `remainingMatches` and `ratings` that the Worker fills from the pricer,
   the remaining/baseline split uses `asOfAtOrBefore` only, and the DCMP is skipped before it
   starts so its hindsight roster is not used. The leaks found are C1 (corrupted objects) and C3
   (stage finality).
2. **Order and lookup, consistent objects.** `(t, eventKey, i)` matches the corpus `ORDER BY`
   (`packages/corpus/db.ts:614-622`), `t` is `matches.sort_time` in both writers, cross-event ties
   resolve the same way in `asOfAtOrBefore`, `compareAsOfPositions` and the timeline's tie-break,
   and the `p` chain, the demo pseudo team, the season-start cut, `lq`/`le`/`lb` and the start
   object all trace correctly. No wrong-tuple path found except through inconsistent objects (C1,
   C4).
3. **Live view regressions.** None found. The Live assembly was moved verbatim, the as-of hook is
   disabled and returns `undefined` at "now", EPA and OPR take the unchanged `launch(null)` path,
   and the default Workers gain only the dependency-free guards module. Bundle sizes were not
   measured.
4. **Worker secrets and accounting.** Reads and writes each spend one subrequest, the TBA key
   refusal is applied to every as-of body, the failure log carries a truncated message only, and
   an as-of failure cannot fail the event or revert the claim.
5. **Browser loops and guards.** Both fetch loops are bounded at 32 rounds, a 404 is `null` and
   any other status throws, `AsOfResolveError` is caught per event (Locks) and as a fallback
   (Simulation), Worker termination and run-id guards cover stop changes and unmount, and the
   request guards bound every array in the as-of block.
6. **Publisher bytes.** The capture only reads; I found nothing that changes an existing
   artifact's bytes. Not re-verified by running the byte identity test.
