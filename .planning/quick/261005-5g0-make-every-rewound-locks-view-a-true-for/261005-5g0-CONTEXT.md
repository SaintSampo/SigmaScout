<domain>
## Task Boundary

When a visitor rewinds District Locks or Champ Locks to any stop, every prediction on the page
comes only from what the site knew at that moment. Also switches the event page Simulation tab's
SPR rewind to the same data.

</domain>

<decisions>
## Implementation Decisions

### Jacob's rules (his words, locked)
1. "there is no point in rewinding during a qual round if the odds, team ratings, and rank point
   odds arnt from right before the match was played." State is captured per match.
2. "I dont want any scripts that run weekly or any other period." No periodic snapshot job.
3. "as many things as reasonably possible should be computed when a match is played." Capture
   lives in the fold: the offline replay's fold and the live Worker tick's fold.
4. "things that make sense to be calculated in the browser, should be." The browser rebuilds the
   state at the chosen position and prices from it.

### Decisions taken 2026-10-05 (AskUserQuestion, with measured numbers)
- **A, schedules: Generated.** At a stop before an event's Schedule stop the browser simulates
  that event over generated schedules, 40 schedules x 100 draws, the offline district bake's
  method. Results fill in event by event in the background worker.
- **B, event page Simulation tab: in this task, SPR only.** EPA rewinds keep today's behaviour.
- **C, version: no bump.** New files publish under the SPR version live at the time. No stored
  prediction or rating changes.
- **D, logs: whole logs, exact.** One log per event at full precision.

### Orchestrator's design (see RESEARCH.md section 1, proven by SPIKE.md Part 2)
- Per event INDEX and LOG plus one per season object (league start row and tails), SPR only.
- One order: `(sort_time, eventKey, row index)`. Keys are `[t, i]`.
- A team's presence at an event is a list of SEGMENTS (runs of consecutive matches in the team's
  own sequence), each `{ f, l, p, s, x }`, so overlapping events resolve exactly.
- The demo pseudo team is its own chain; raw demo keys carry no SPR part.
- The rookie rule applies everywhere in as-of pricing, as in `buildDistrictPricingState`.
- Playoffs and Awards stops sit at the event's last played playoff match, not its last
  qualification match.
- No D1 change. `STATE_SNAPSHOT_SHAPE_VERSION` stays 18.

### Claude's Discretion
- Artifact key names and schema field names.
- How the browser batches index and log fetches.
- "Schedule known" rule: an event's real schedule is used when the event has a match at or
  before the cut, or the stop is the position immediately before its first match (its Schedule
  stop). Otherwise generated.

</decisions>
