<objective>
During a live event the Worker tick folds played matches into the event artifact's `matches` rows every minute but never refetches TBA's rankings, so each team's `rank`, `record` and `rp` stay frozen at publish time (or absent entirely on a Worker-promoted stub event). The browser already polls that artifact every 60 s and already holds every played qualification row, so it can count the standings itself.

Derive record, ranking points and rank in the browser from the played qualification rows, in one pure function applied where the artifact enters the page, so the Insights table and the rank simulation both see current standings.

Purpose: fight staleness during a live event without spending one extra byte of Cloudflare Worker CPU.
Output: one new lib module with tests, a two-line wire-in at the artifact entry point, and one honest live case in the Insights order source.
</objective>

Facts established before planning, do not re-derive:

1. The trigger is `artifact.live !== undefined`. `EventLiveBlockSchema`'s own doc comment
   defines `rows` as "one row per match folded since the last republish", and the key is
   declared only on `LiveEventArtifactSchema` while the offline publisher writes through
   `EventArtifactSchema`, which strips unknown keys. So the key's presence is a precise,
   self-cleaning statement that this artifact carries played rows the published standings do
   not account for, and a republish erases it. `maintainedLiveBlock` also carries the block
   forward on a tick that folds nothing, so it persists for the whole event.

2. The count-based alternative (derived appearances exceed the published record total) is
   UNSOUND and must not be substituted later: a surrogate appearance makes the counted total
   exceed TBA's surrogate-adjusted record total even on a finished, fully published event, so
   it would fire falsely across ordinary history. Write this reason into the module comment.

3. A played row carries `compLevel`, `redTeams`, `blueTeams`, `actualWinner` ("red"/"blue"/
   "tie"), and `actualRedRp`/`actualBlueRp`, which are BONUS ranking points only, integer, and
   three-state (absent / explicit null / present). It carries NO surrogate field and NO
   disqualification field. Total RP for an alliance is the outcome RP from the artifact-level
   `rpOutcomeRp` (`win`/`tie`, 0 for a loss) plus that bonus value.

4. `EventTeamSchema.rp` is TBA's Ranking Score: a per-match AVERAGE, a real number, rounded at
   publish to 2 decimals. It is not the same quantity as `actualRedRp`. The derived value must
   be the same quantity, rounded the same way, or the Insights cell and the simulation's unit
   conversion both read it wrong.

5. `resolveEventArtifact` is the one place the artifact enters the page, and its result is
   shared by every observer of the query key. Applying the derivation there is what keeps
   `simulationInputs.ts` and every other consumer free of edits.
