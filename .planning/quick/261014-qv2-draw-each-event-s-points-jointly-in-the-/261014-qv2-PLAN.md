<objective>
Draw each event's points jointly in the District Locks advancement run, and measure it.

Background. The weighted pick draft (quick task 261014-ol6, on this branch, push held) widened the District Locks predicted cutoff's 10th to 90th range: it held the settled cutoff at 194 of 205 backtest positions (94.6%), against registered gate 2's 72% to 88%. The cause is in `packages/core/districts/advancementChance.ts`: every team's season total is drawn independently from its own grand total marginal, which ignores that points are conserved inside an event (one team's qualification points are another's loss; if one team is picked another is not). The wider per team alliance marginals pile up in the line. Jacob's call (2026-10-14): fix the cause. Read every team at an event from the same simulated run of that event. "Likely" keeps meaning the 10th to 90th percentile, 8 runs in 10. The weighted draft ships only together with this fix, and only if the gates below pass.

Decisions made here (planner's discretion, stated so a reviewer can disagree):
- THE EVENT TOTAL PER TEAM PER RUN IS ENOUGH. The advancement run ranks season totals and reads nothing else; the chance and the line are both functions of totals. Categories would cost four times the memory for no reader. The conservation test still checks selection points exactly, by pricing an event where selection is the only category that varies.
- RUN INDEX RULE: per advancement run, per joint event, one uniform u from the module's own generator, index = floor(u x runs), clamped to runs - 1, with replacement. For one team this is exactly a draw from its empirical event marginal (reading a uniformly random run's value), so each team's marginal is unchanged in distribution; only the coupling between teams at the same event changes. Events never share an index, so the one seed every Live and REAL event is simulated under still cannot carry correlation between events.
- THE CHAMP LOCKS RUN STAYS INDEPENDENT. Its own advancement run (champ mode: district part plus a DCMP part drawn per team, award draws) has its own walk forward tuning (`champCutoffTuning.generated.ts`) and gate, and its scored backtest position has every district event finished, so joint district draws would not move it there anyway. The core refuses joint events in champ mode so it can never be half applied. What DOES move on the Champ tab: its field chances and its simulated DCMP field, which read the DISTRICT run, now joint like the District tab's.
- THE BAKE KEEPS ALL 4,000 RUNS rather than subsampling to 1,000, so a team's joint marginal is the same pooled histogram its row's pmf was encoded from (the row pmf is that histogram rounded to five decimals).

Purpose: a likely range that means what it says, so the weighted draft can ship.
Output: joint draws on Live, the as of rewind and both backtests through one builder; tests; a measured, pre registered verdict.
</objective>
