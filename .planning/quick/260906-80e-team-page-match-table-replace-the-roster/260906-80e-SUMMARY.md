# Quick Task 260906-80e: Alliance ground tint on the team match table

Ships sketch 010 variant C. On the team page's per-event match table, the roster line for the
team's own alliance now rides a fully-rounded, alliance-tinted pill at 10%, and the team's own
number within that line sits on the same hue at 20%. The previous `font-semibold` treatment is
gone entirely, and the gap between alliance members widened from a literal space (~4px) to a real
10px layout gap.

The bold did two jobs badly: it was a weak signal (600 against 400 at 14px), and because it
painted all three numbers it never said *which* one was the team's. The tint does both jobs with
one mechanism at two depths.

## What Changed

### `apps/web/src/styles/theme.css`

Four new custom properties after `--loser-ink`, each derived with `color-mix` from the existing
alliance tokens rather than restating raw colour:

```
--alliance-red-ground:      color-mix(in srgb, var(--alliance-red)  10%, transparent);
--alliance-blue-ground:     color-mix(in srgb, var(--alliance-blue) 10%, transparent);
--alliance-red-ground-own:  color-mix(in srgb, var(--alliance-red)  20%, transparent);
--alliance-blue-ground-own: color-mix(in srgb, var(--alliance-blue) 20%, transparent);
```

Plus a `.match-alliance-*` rule block after `.alliance-chip--blue`:

- `.match-alliance-nums` — `inline-flex`, `gap: 10px`; applied to **both** roster lines so spacing
  is uniform whether or not the line is marked.
- `.match-alliance-num` — `padding: 0 1px`, applied to every number so the own-number ground does
  not shift its neighbours.
- `.match-alliance-nums--mine` — the pill: `padding: 0 5px`, `margin-left: -5px`,
  `border-radius: 999px`. **Horizontal only**, with the vertical-rhythm prohibition spelled out in
  the comment.
- `--red` / `--blue` background bindings, and the two `--own` descendant selectors.

No existing token value changed.

### `apps/web/src/components/team/MatchTable.tsx`

Each roster line's three number spans now sit inside one wrapper span carrying
`match-alliance-nums` plus, when the team is on that side, `match-alliance-nums--mine` and the
side modifier. Each number carries `match-alliance-num`, and the team's own number additionally
carries `match-alliance-num--own`.

Removed: the conditional `font-semibold`, the `{index > 0 ? " " : ""}` literal-space text node,
and the now-unused `index` map parameter. Separation is CSS `gap` alone.

Own-number detection is strict `key === teamKey`, deliberately not loosened — the same WR-02
reasoning that gates the Result cell, so the letter-suffixed second-robot key (`frc5199B`) marks
nothing.

### `apps/web/src/components/team/MatchTable.test.tsx`

Verification is split in two because **jsdom applies no CSS** — `getComputedStyle` in the test env
would report only the UA stylesheet, so a DOM-only assertion can pass while the tint is invisible:

- A **CSS-text guard** reading the shipped `theme.css` (the fallback pattern already established by
  `theme.scrollbar.test.ts`), asserting the four token values, that none contains `rgba(` or `#`,
  the pill's padding/margin/radius, and the **absence** of any vertical-rhythm property.
- **DOM tests**: red and blue own-line marking, the opponent line unmarked, zero bold survivors,
  exact `textContent === "118254971"` (catches a "kept the space *and* added the gap" half-fix that
  no class assertion would notice), and the `frc5199B` negative case.

### Live geometry measurement

The plan marked the vertical-rhythm and x-alignment checks as human-only. They were instead
measured directly in a real browser (dev server with the local artifact proxy, real published
`frc5951` / `2026isrtp` data, via CDP `getBoundingClientRect`):

| Constraint | Measured |
|---|---|
| Pill adds no height | marked and unmarked lines both **21.00px**; `padding-top`/`padding-bottom` **0px** |
| Band centres still land on roster lines | line centres 621.28 / 643.28 vs band centres 621.19 / 643.19 — **0.09px** |
| First digit x-aligned across lines | **254.5px** on both the tinted and the untinted line |
| Gap | **10px** on both lines |
| Tint depths | alliance hue at **0.1**, own number at **0.2** |

The −5px margin exactly cancels the 5px padding, which is what keeps the column from reading
ragged. All four of the sketch README's "constraints implementation must honour" are satisfied and
now measured, not asserted.
