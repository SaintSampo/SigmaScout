<objective>
Make Sigma1's season-boundary carry gap-aware: apply the existing mean reversion and
consistency decay once per YEAR ELAPSED across a boundary, so the permanently-excluded 2021
season (2020 -> 2022 spans two years) is handled as two years of student-cohort turnover
rather than one.

Purpose: the corpus is contiguous today (2022-2026), so every boundary is one year and this
is a provable no-op. It stops being a no-op the moment `extend-corpus-2019-2020` lands. Land
the mechanism now, with the zero-diff proof, while the proof is cheap.

Output: a gap-aware Sigma1 carry, a truthful `fromSeason` on every production boundary, and a
test suite that pins both the `gap === 1` bitwise identity and the intentional `gap === 2`
divergence from frozen EPA.

**Scope note - one addition beyond CONTEXT.md's literal file list.** CONTEXT.md names the
carry math only. Task 3 additionally fixes `tune.ts` and `publish.ts`, which build their
`SeasonBoundary` as `fromSeason: season - 1`. With a non-contiguous corpus that hardcoding
reports `fromSeason: 2021` for the 2022 boundary, making `gap` permanently 1 on exactly the
two paths that tune and publish - the feature would be dead code where it matters.
`cli.ts:695-699` already anticipated this in a 02-REVIEW IN-01 comment ("correct ... if a
non-contiguous `seasons` array ever reaches this loop and a future `carrySeason` starts
consuming `fromSeason`"); this task is that future. Verified 2026-09-03: `.fromSeason` has
ZERO read sites anywhere in production code today, so task 3 changes no behaviour on the
contiguous corpus and cannot affect EPA (whose `carrySeason` reads only `isColdStart` and
`toSeason`).
</objective>
