# Quick task 260925-ms7: reserve a slot for every award still to come

Quick task 260925-ma5 measured Jacob's two Road to District Champs tenets over 921,658
team-positions across 109 district seasons, using the browser's own status code. Tenet B
(a team displayed `Locked out` never qualifies on points) holds with zero reversals. Tenet A
(a team displayed `Locked` always qualifies on points) is broken **13 times**, every one on a
`playoffs` step, and every one by the same mechanism:

> until an event's Impact award is posted, `qualifierPool` in
> `packages/core/districts/locks.ts` hands that slot back to the points race, `pointsSlots`
> reads one too many, and a team on the knife edge prints `Locked` one step before the award
> consumes the slot and eliminates it.

Traced on `2025fnc` `frc3229` at `2025ncpem`: `threatCount 34 < pointsSlots 35` -> `locked`;
one step later `pointsSlots 34`, same `threatCount 34` -> `eliminated`. Twelve more in 2020.
The `now` position runs the same code, so it can happen live.

Jacob's tenet is absolute. The Liatys and Papa white paper reserves one slot per district
event up front (`N = spots - events`). We adopt the reservation, narrowed to events whose
Impact award can still be awarded.

## The rule

`reservedSlots` is the number of district-tier events of this district that

- **(a)** have not posted their awards — the award category is not final at the position
  being evaluated — and
- **(b)** will still hold an Impact award: the event has started, or is scheduled in the
  future.

An event known never to happen reserves nothing. `pointsSlots` becomes

```
pointsSlots = max(slots - awardQualifiedRankedCount - reservedSlots, 0)
```

A posted Impact winner keeps today's handling exactly (it consumes a slot only if it would
not qualify on points), so a posted award never double counts with a reservation: an event is
either **awards posted** (winner known, current handling) or **pending** (one reservation),
never both.

**The cancelled carve out**, stated exactly. An event is treated as never happening when, at
the `now` position, all three hold: it has not started (`districtEventStateStarted` false, or
the artifact carries no `state` for it at all), it has no published qualification schedule
(`state` absent or `qualMatchesTotal === null`), and **every other** district-tier event of
the district is finished at `now`. The last clause is what keeps a live season safe: while any
other event is still running, nothing is ever called cancelled, so the reservation stands.
Note that `districtEventStateStarted` includes `awardsPosted`, so an event that posted an
Impact award without ever playing a match — which is what the 2020 cancellations actually did
— is never cancelled by this rule.

**Direction of the change.** A reservation shrinks `pointsSlots`, which can only make `Locked`
harder and `Locked out` easier. `pointsSlots` is also non decreasing toward `now`: posting a
pending event's award either adds one ranked award qualifier (net zero) or none (the slot
returns to the pool), so a reservation is never revoked in the direction that would break
tenet A.

## What changes in production

Every district-tier event in all 119 published artifacts carries `awardsPosted: true` at
`now` — verified by reading the corpus — so **no published number moves at the `now` position
for any finished season, including the 2020 cancellations** (their awards really were posted).
The reservation only bites at a rewound position and during a live event before its awards are
posted, which is exactly where the 13 violations were.

## Deviation found during execution (recorded here, stated in full in the SUMMARY)

The plan above says the reservation reduces `pointsSlots` for everything, and is passed into
both `computeLocksWithQualifiers` and `cutLinePointsWithQualifiers`. **That was built first and
measured, and it broke the other tenet.** With the reservation on the elimination side, the
sweep went from 0 tenet-B violations to **551**: teams told `Locked out` that went on to
qualify on points. The cause is a double count — the reservation withholds the slot while the
pending award's winner is still sitting in the pool as a rival, so one award is priced twice.

The shipped rule therefore splits the two sides, and nothing else about the plan changed:

- `lockSlots = max(pointsSlots - reservedSlots, 0)` decides `"locked"` and `pointsToLock`.
- `pointsSlots` (award-consumed only, exactly today's number) decides `"eliminated"` and the
  published cut line, which is why `cutLinePointsWithQualifiers` keeps its three arguments.

Both tenets then measure zero, and `Locked out`, the published cut line and the In range line
are untouched by the reservation.
