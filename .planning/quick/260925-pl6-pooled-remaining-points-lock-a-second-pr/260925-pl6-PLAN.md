# Quick task 260925-pl6: the pooled remaining-points lock

Add the Liatys and Papa white paper's **pooled remaining points** argument as a SECOND,
additive way for a team to report `Locked` on the district points race. Today's rule treats
every rival's ceiling as independently reachable; points are conserved inside an event, so the
district's TOTAL remaining points are far smaller than the sum of rival ceilings.

## The rule

A team `A` is **pooled locked** when the minimum number of points needed to push it below the
last points slot EXCEEDS the total points still available in the district.

```
aheadCount(A) = #{ other pool teams with pointTotal >= pointTotal(A) }     // a tie counts as ahead
needed(A)     = lockSlots - aheadCount(A)                                  // rivals that must still pass A
candidates    = pool teams with pointTotal < pointTotal(A), descending, that still have a remaining event
minimumToEliminate(A) = sum over the first `needed` candidates of (pointTotal(A) - pointTotal(rival))
                      = Infinity when fewer than `needed` candidates exist
pooledLocked(A) = needed > 0 AND minimumToEliminate(A) > remainingPoints
```

A tie against `A` is enough for a rival, so the cost is exactly `P_A - P_rival`. `aheadCount`
counts ties as ahead, which is `locks.ts`'s own tie philosophy and the conservative direction.
`needed <= 0` (a team already outside the slot count) never pooled locks.

## What the measurement changed about the plan

The prompt's pool constants were checked against `data/corpus.sqlite` (951 district-tier
events, 2016 to 2026) before any code was written. Two of them are wrong for this data:

| Category | Prompt | Measured maximum at a real district event | Decision |
| --- | --- | --- | --- |
| Alliance selection | 236 | 236, 0 events over | Keep 236, recomputed from `selectionPoints.ts` |
| Playoffs | 213 | 212, 0 events over | Keep 213 (3 x 70 plus a 3 point backup robot margin) |
| Awards, 0 rookies | 63 | **78** | Use 78 |
| Awards, 1 rookie | 71 | **86** | Use 86 |
| Awards, 2+ rookies | 76 | **91** | Use 91 |
| Qualification | `sum f(r,m) - m*f(m,m)` | observed exceeds `sum f(r,m)` at 38 events, by up to 10 | Use `sum_{r=1..m} f(r, m+3)` |

**The award pool keeps the Impact award's 10 points.** The prompt excludes them because the
Impact winner's slot is reserved by 260925-ms7. That reservation withholds a SLOT; the winner's
ten POINTS are still in the artifact and still rank it, and before the award posts that winner
is still in the points pool. The measured maxima above include Impact, and the rookie structure
they show (78, then +8, then +5) is exactly the paper's own Rookie All Star and Rookie
Inspiration increments sitting on a base of 78 rather than 63.

**The guaranteed last-place adjustment is NOT applied — the "neither" branch.** The attendee
count available to a corpus-free reader is the district artifact's own row count, and a real
field can be larger (a non-district team at a district event earns no district points and
appears in no `district_rankings` row). Measured, that undercount makes the observed
qualification total exceed `sum f(r,m)` at 38 of 951 events. Evaluating `f` at `m + 3` closes
it with headroom (0 events over at `m + 2` already). Subtracting `m*f(m,m)` as well would take
about 148 points per event back out of the pool and reopen the same hole 14 times wider, so the
un-subtracted baseline is kept as the margin that covers the unknown field size, and no floor
bonus is added to any team.
