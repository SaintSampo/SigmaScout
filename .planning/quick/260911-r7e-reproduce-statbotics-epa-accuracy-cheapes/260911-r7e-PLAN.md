# Quick Task 260911-r7e — Close the EPA/Statbotics accuracy gap with the fewest changes

## The ask, verbatim in substance

Make SigmaScout EPA produce accuracy **identical to Statbotics EPA**, with as FEW changes as
possible, quickly. Tolerance ~0.1 accuracy points. Skip any expensive mechanism that will not
move the number. **Maximizing accuracy and SigmaScout's own principles are explicitly NOT the
goal** — reproducing Statbotics is.

## Why this is not the prior approach

Prior tasks (`260911-i9f`, `-pon`, `-gfe`, `-l2k`, `-3kc`) have been closing an 11-mechanism x
9-season verdict matrix one cell at a time. The 2024 tracer in `-pon` measured mechanism 1's
closure at **-0.036 accuracy points — a LOSS**. Eight more seasons of the same shape are queued.
That is the expensive-and-it-does-not-move-the-number path this task refuses.

This task works **backward from the measured accuracy deficit** instead, and only touches a
mechanism that measurement says owns a share of it.

## What is already known (not re-derived here)

- Winner accuracy is `sign(margin)` only. The win-probability scale **cannot** move it
  (`260910-4x0`, confirmed in the ablation's `epa-winprob-*` arms: verdict `identical`).
  Everything about mechanism 8 is therefore irrelevant to this task's metric.
- The two levers that were measured to matter for 2024 have **already shipped**: per-season
  score SD (`epa@9.0.0`) and the 13->5 component collapse.
- `epa-vs-statbotics.md` measured that **Statbotics' EPA reflects the official season only**,
  while our replay stream is offseason-inclusive. Excluding offseason moves per-team OLS slope
  from 0.81-0.96 to 0.97-1.01 and Pearson to 0.99+. The ablation register carries this as
  `offseason-population`, status `unmeasurable-in-this-harness` — i.e. **never measured against
  accuracy.**

## Hypothesis under test

The residual accuracy deficit is dominated by a **population/stream difference, not a model
difference**: we rate teams on matches Statbotics never saw. If so, the "change" needed to
reproduce their accuracy is a replay-stream scope change, not new per-season component maps.

## Tasks

1. **Measure the current baseline.** `epaVsStatbotics.ts --seasons 2016-2026`, offseason-inclusive,
   under the shipped `epa@10.0.0+baseline`. The standing table in `epa-vs-statbotics.md` is
   `6.0.0` and predates every lever that has since landed, so it cannot be used.
2. **Measure the official-only arm.** Same script, `--no-offseason`. One flag, zero model change.
3. **Decide from the two numbers.** If the official-only arm lands inside the ~0.1-point
   tolerance on most seasons, the answer is a measurement/stream scope finding and the task is
   done with no model change at all. If a named residual remains, attack only the single largest
   contributor and re-measure.
4. **Write the result up** in `docs/models/epa-vs-statbotics.md` and hand back what is left.

## Guardrails

- No tuning, no grid search, no variant selection. Arms are pre-named above.
- Report every arm measured, including losses.
- No republish, no R2 write, no deploy, no BPR/SPR contact, no sealed-holdout spend.
- Brier convention is whatever the script already uses; arms are comparable to each other only.
