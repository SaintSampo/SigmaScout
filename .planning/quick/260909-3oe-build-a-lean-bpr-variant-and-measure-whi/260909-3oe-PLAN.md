## HAZARD: `foulOn` is a boolean and `tune.ts` cannot flip it

`GRID` holds numeric keys only. A rung that adds the foul submodel therefore needs
an explicit **seed file** with `foulOn: true` written before its tune runs; the
tune then searches `foulObsSd`, `foulQ` and `foulPriorVar` from there. Every other
component can be reached from its inert value by the grid alone.

This creates a real asymmetry the rule must handle in advance: turning `foulOn`
on at un-refit foul knobs may start that rung BELOW the rung it seeds from, and
`better()` accepts only strict improvements, so a 3-sweep search may not recover.
`LADDER-RULE.md` pre-registers how that case is reported (Task 1, step 2, item 7).

## HAZARD: the `elimWeight` grid contains no 1.0

## The paired statistics already do what is needed, including for no-calls

`meanAccuracyDelta` scores each side through `accuracyCall` from
`packages/core/scoring/brier.ts`. That predicate returns `null` for a **tied
match** only. A `pRed === 0.5` no-call falls through both branches and returns
`false` — a miss, per D-Q3. So **no-call units are already in the paired accuracy
denominator**, which is exactly what makes the as-scored number the honest one and
the ex-no-call number a deliberate, separately-defined slice.

## The side bias is NOT purely a tie-break, and `model.ts` says why

`model.ts:88-100` documents `biasLr` as an online red-side margin offset fitted
**separately for quals and elims**, with design-year evidence that quals run
49.2-50.3% red while **eliminations run 63-78% red** because the higher seed is
conventionally placed on red. So the knob carries two distinct effects: cold-start
tie-breaking in 2016 quals, and a genuine elimination seeding signal. The
deterministic-tie-break question is therefore about the first effect only, and the
answer must not collapse the two. Split it by `compLevel`.

## The deterministic tie-break is ARITHMETIC, not an arm to build

Implementing "always call red on an exact tie" would mean changing `accuracyCall`
or the model — a scoring-convention change affecting all four algorithms, out of
scope here and a `SEALED_CODE_PATHS` edit besides. It does not need building. On
the units where the incumbent predicts exactly 0.5, a deterministic always-red
rule scores exactly the red-win rate among those units, and always-blue scores its
complement. Both are computable from the emitted paired jsonl for free.
