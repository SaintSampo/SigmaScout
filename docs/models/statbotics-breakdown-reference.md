## 1. The shape and INDEX ORDER of `all_keys[year]`

`src/breakdown.py` builds the list. This is the whole construction, verbatim:

```python
all_keys: Dict[int, List[str]] = {}
for year in range(2002, CURR_YEAR + 1):
    if year not in key_to_name:
        all_keys[year] = ["no_foul_points"]
    else:
        all_keys[year] = [
            "no_foul_points",
            "auto_points",
            "teleop_points",
            "endgame_points",
            "rp_1",
            "rp_2",
            "rp_3",
            "tiebreaker_points",
        ]
        for i in range(0, 10):
            if f"comp_{i}" in key_to_name[year]:
                all_keys[year].append(key_to_name[year][f"comp_{i}"])
```

Then — and this is what makes the index order a closed fact rather than an inference —
`src/tba/breakdown.py` **pads every year's list to exactly 18 entries at import time**:

```python
for year in range(2002, CURR_YEAR + 1):
    if len(all_keys[year]) > 18:
        # 8 standard (no_foul, auto, teleop, endgame, rp_1, rp_2, rp_3, tiebreaker) + 10 components
        raise ValueError(f"Too many keys for year {year}")
    all_keys[year] += ["empty"] * (18 - len(all_keys[year]))
```

So for every season the rated vector has **exactly 18 slots**, in this fixed order:

| index | key |
|---|---|
| 0 | `no_foul_points` |
| 1 | `auto_points` |
| 2 | `teleop_points` |
| 3 | `endgame_points` |
| 4 | `rp_1` |
| 5 | `rp_2` |
| 6 | `rp_3` |
| 7 | `tiebreaker_points` |
| 8–17 | `key_to_name[year]["comp_0"]` … `["comp_9"]`, then `"empty"` padding |

Section 14's `pre_record_team` confirms this order independently, from the other end: it reads
index 0 as `epa`, 1/2/3 as auto/teleop/endgame, 4/5/6 as `rp_1`/`rp_2`/`rp_3`, 7 as
`tiebreaker`, and `i + 8` as `comp_{i}`. Section 19's `get_mean_components` returns an
18-element array in that same order. Three independent places agree, so the order is established.

**A consequence worth stating, because `keys.index()` is a NAME lookup:** where a season's
`comp_i` name duplicates one of the eight standard names, `keys.index(name)` returns the
**first** occurrence — the standard slot, never the comp slot. 2020's `comp_8` and 2022's
`comp_5` are both spelled `endgame_points`, so a read of `keys.index("endgame_points")` in
either season resolves to index 3. No branch in section 15 depends on this, but a future reader
adding one must know it.

## 3. CORRECTED — `all_keys[year]` indexes a rated VECTOR, and Statbotics rates one per TEAM

**The 2026-09-11 morning version of this file concluded that Statbotics "rates a single quantity"
and has no component vector. That conclusion is WRONG, it was published to the developer by quick
task 260911-gfe, and correcting it precisely is a named deliverable of this task.**

`predict_match` sums a **per-team vector**, component-wise, across the alliance:

```python
        red_teams = match.get_red()[: self.num_teams]
        blue_teams = match.get_blue()[: self.num_teams]
        for teams, opp_teams in [(red_teams, blue_teams), (blue_teams, red_teams)]:
            pred_mean = np.array([self.epas[t].mean for t in teams]).sum(axis=0)  # type: ignore
            # pred_sd = np.array([np.sqrt(self.epas[t].var) for t in teams]).sum(axis=0)  # type: ignore
            opp_pred_mean = np.array([self.epas[t].mean for t in opp_teams]).sum(axis=0)  # type: ignore

            pred_mean = post_process_breakdown(year, key, pred_mean, opp_pred_mean)
```

`self.epas[t].mean` is a numpy array of 18 entries indexed exactly as section 1 describes.
`.sum(axis=0)` is a component-wise sum across the three teams. Every entry is then addressed by
key NAME through `keys.index(...)`. **Statbotics rates a vector per team and sums it across the
alliance — structurally the same shape as SigmaScout's per-team component map.**

What IS true is narrower, and must be stated with that narrowness:

> `get_score_from_breakdown` READS only a subset of that vector when it computes the predicted
> score, and for most seasons that subset is the single entry `no_foul_points`. **But not all
> seasons.** 2018 reads seven of its own entries plus two of the opponent's; 2023 reads seven;
> 2016 and 2017 read one, plus two RP entries in ELIMINATION matches only.

The per-season table of exactly which entries each branch reads is **section 18**. The branches
themselves are **section 15**.

**What this retires.** "Statbotics rates one number per alliance" is false as a general statement.
It is true only of the seasons whose branch is `score = breakdown[keys.index("no_foul_points")]`,
and even there it describes what the PREDICTED SCORE reads, not what the model RATES — the other
17 entries are still rated, still updated every match by `attribute_match` (section 14), and
still published by `post_record_team` (section 14). Three surfaces in this repo still carry the
retired claim; they are named with exact locations as stage 1 of

## 5. CORRECTED — what this means for SigmaScout's 2024 map

Section 2 establishes that auto/teleop/endgame is a real additive partition, enforced by
Statbotics' own validation. `docs/models/epa-divergences.md` section 6 records that 2024's
SigmaScout map was narrowed to exactly those three phase groups. On the partition question the
two agree, and that much of the 2026-09-10 conclusion survives.

**What does NOT survive is the framing around it.** That version said the difference between the
two projects was one of KIND — "one rates several pieces and adds them up, the other rates one
total". Section 3 shows that is wrong. Both projects rate a per-team vector and sum it across the
alliance. The difference is in **which entries the predicted score reads**, and for 2024 that is a
difference of one read (`no_foul_points`, index 0) versus a sum over four components
(`auto`, `teleop`, `endgame`, `adjust`) plus the opponent's `foulsCommitted`. That is a
difference of DEGREE in a shared structure, and it is exactly what section 18 tabulates.

The measured cost of adopting Statbotics' 2024 read is in section 10, unchanged: 0.7403 against
the shipped 0.7520.

## 9. Why "just use the phase partition" is not a shortcut

*(Provenance block B — reasoning over this project's own code, carried forward unchanged in
substance. One sentence is now stronger than it was: the per-year phase formulas it complains
were never transcribed ARE now transcribed, in section 17.)*

Section 2 and section 5 establish that auto/teleop/endgame IS a real additive partition, enforced
by Statbotics' own validation. It is tempting to conclude that SigmaScout could measure
faithfulness for every season simply by replaying each one under `componentGroupsForSeason(season)`'s
three phase groups.

It could not, and the reason is worth recording so a future reader does not try.

`packages/core/algorithms/breakdown/groups.ts` declares its grouping as a JUDGEMENT, and its own
header says so at length. Several of those judgements deliberately disagree with the source's own
roll-up:

- 2019's `habClimb` is grouped ENDGAME, and the file notes "TBA's own `teleopPoints` roll-up
  bundles HAB climb together with hatch panels and cargo".
- 2016's `teleopChallenge`/`teleopScale` are grouped ENDGAME despite TBA counting them elsewhere.
- 2022's bare `endgame` component gets the same treatment, again against a `teleopPoints` roll-up.

So SigmaScout's phase groups are not TBA's phase fields, and TBA's phase fields are not
necessarily Statbotics' either. Building a "phase partition" arm out of `groups.ts` would measure
SigmaScout's own phase judgement, label it Statbotics', and reproduce the mislabelling section 6
already documents.

## 12. `backend/src/models/epa/math.py`

The module-level comment is included deliberately: it is the only statement anywhere in the source
of what the update rule's SHAPE means — a 5-sample asymptote arising from an EWMA with decay
`p = 0.8` — and it belongs in the record.

```python
# 5 represent the asymptote of the sample size of the moving average
# 1 / (1 - p) where p = 0.8, the decay rate of the EWMA. By the Bayesian
# conjugate prior of the normal distribution, the posterior predictive of
# the mean is a t-distribution with equal degrees of freedom


class EPARating:
    # all inputs are 1d np arrays, does not handle covariance between variables
    def __init__(self, mean: Any):
        self.mean = mean

    @staticmethod
    def update_mean(mean: Any, x: Any, alpha: float) -> Any:
        new_mean = x
        return (1 - alpha) * mean + alpha * new_mean

    def add_obs(self, x: Any, percent: float, weight: float) -> None:
        mean = self.mean
        new_mean = self.update_mean(mean, x, percent)
        self.mean = weight * new_mean + (1 - weight) * mean

    def __repr__(self) -> str:
        return f"EPARating(mean={self.mean})"
```

The three sigmoids. `zero_sigmoid` is the 2018 switch/scale contest function; `unit_sigmoid` and
`inv_unit_sigmoid` are the ranking-point pair, **NOT ADOPTED by SigmaScout per L-02**, transcribed
here because the reference must be complete:

```python
# used for 2018 switch/scale power
# -2 instead of -4 since both alliances contribute
def zero_sigmoid(x: float) -> float:
    return 1 / (1 + np.exp(-2 * x))


# used for ranking point system
def unit_sigmoid(x: float) -> float:
    return 1 / (1 + np.exp(-4 * (x - 0.5)))


def inv_unit_sigmoid(x: float) -> float:
    return 0.5 + np.log(x / (1 - x)) / 4
```

```python
def get_init_epa(
    year: Year,
    team_year_1: Optional[TeamYear],
    team_year_2: Optional[TeamYear],
    mean_reversion: float,
) -> EPARating:
    num_teams, year_mean, year_sd = get_constants(year)

    INIT_EPA = NORM_MEAN - INIT_PENALTY * NORM_SD
    norm_epa_1 = norm_epa_2 = INIT_EPA
    if team_year_1 is not None and team_year_1.norm_epa is not None:
        norm_epa_1 = team_year_1.norm_epa
    if team_year_2 is not None and team_year_2.norm_epa is not None:
        norm_epa_2 = team_year_2.norm_epa

    prev_norm_epa = YEAR_ONE_WEIGHT * norm_epa_1 + (1 - YEAR_ONE_WEIGHT) * norm_epa_2
    curr_norm_epa = (1 - mean_reversion) * prev_norm_epa + mean_reversion * INIT_EPA

    curr_epa_z_score = (curr_norm_epa - NORM_MEAN) / NORM_SD

    # enforces starting EPA >= 0
    curr_epa_z_score = max(-year_mean / num_teams / year_sd, curr_epa_z_score)

    mean = year.get_mean_components()
    sd_frac = (year_sd or 0) / (year_mean or 1)
    sd = mean * sd_frac

    if year.year >= 2016:
        # For ranking points, take inv sigmoid since later we will apply sigmoid
        mean[4] = max(-1, inv_unit_sigmoid(max(EPS, min(1 - EPS, mean[4]))))
        mean[5] = max(-1, inv_unit_sigmoid(max(EPS, min(1 - EPS, mean[5]))))
        mean[6] = max(-1, inv_unit_sigmoid(max(EPS, min(1 - EPS, mean[6]))))

    curr_epa_mean = mean / num_teams + sd * curr_epa_z_score

    return EPARating(curr_epa_mean)
```

Note the non-negativity floor at `max(-year_mean / num_teams / year_sd, curr_epa_z_score)`, and
that `mean[4]`/`mean[5]`/`mean[6]` — the three RP slots — are pre-imaged through
`inv_unit_sigmoid` so that `post_process_breakdown`'s forward sigmoid recovers them. Both are
season-aggregate-dependent; see section 19.

```python
def post_process_breakdown(
    year: int, key: str, breakdown: Any, opp_breakdown: Any
) -> Any:
    # Updates breakdown for both score prediction and EPA update

    keys = all_keys[year]
    total_change = 0

    if year >= 2016:
        breakdown[keys.index("rp_1")] = unit_sigmoid(breakdown[keys.index("rp_1")])
        breakdown[keys.index("rp_2")] = unit_sigmoid(breakdown[keys.index("rp_2")])
        if year >= 2025:
            breakdown[keys.index("rp_3")] = unit_sigmoid(breakdown[keys.index("rp_3")])

    if year == 2018:
        my_switch_power = breakdown[keys.index("switch_power")]
        opp_opp_switch_power = opp_breakdown[keys.index("opp_switch_power")]
        new_switch_power = zero_sigmoid(my_switch_power - opp_opp_switch_power)

        my_scale_power = breakdown[keys.index("scale_power")]
        opp_scale_power = opp_breakdown[keys.index("scale_power")]
        new_scale_power = zero_sigmoid(my_scale_power - opp_scale_power)

        my_opp_switch_power = breakdown[keys.index("opp_switch_power")]
        opp_switch_power = opp_breakdown[keys.index("switch_power")]
        new_opp_switch_power = zero_sigmoid(my_opp_switch_power - opp_switch_power)

        breakdown[keys.index("switch_power")] = new_switch_power
        breakdown[keys.index("scale_power")] = new_scale_power
        breakdown[keys.index("opp_switch_power")] = new_opp_switch_power

    elif year == 2023:
        bottom_pieces = breakdown[keys.index("bottom_pieces")]
        middle_pieces = breakdown[keys.index("middle_pieces")]
        top_pieces = breakdown[keys.index("top_pieces")]
        if top_pieces > 9:
            extra_top = top_pieces - 9
            middle_pieces += extra_top
            top_pieces = 9
            total_change -= 2 * extra_top
        if middle_pieces > 9:
            extra_mid = middle_pieces - 9
            bottom_pieces += extra_mid
            middle_pieces = 9
            total_change -= extra_mid
        if bottom_pieces > 9:
            extra_bot = bottom_pieces - 9
            middle_pieces += extra_bot
            bottom_pieces = 9
            total_change += extra_bot

        teleop_grid_points = breakdown[keys.index("teleop_grid_points")]
        cube_points = breakdown[keys.index("cube_points")]
        cone_points = breakdown[keys.index("cone_points")]
        grid_points = (
            cube_points + cone_points
        )  # computed inline (not a stored component)
        teleop_grid_points += total_change
        if grid_points > 0:
            cube_points += total_change * cube_points / grid_points
            cone_points += total_change * cone_points / grid_points

        breakdown[keys.index("bottom_pieces")] = bottom_pieces
        breakdown[keys.index("middle_pieces")] = middle_pieces
        breakdown[keys.index("top_pieces")] = top_pieces
        breakdown[keys.index("teleop_grid_points")] = teleop_grid_points
        breakdown[keys.index("cube_points")] = cube_points
        breakdown[keys.index("cone_points")] = cone_points

    elif year == 2025:
        # we internally assign 3 points per processor algae. in reality, it's worth 6 points
        # for your alliance and 3 points for the opponent (assuming 75% success rate at 4 point net).
        # Adjust by adding 3 points per processor algae scored by both alliances
        my_processor_algae = breakdown[keys.index("processor_algae")]
        opp_processor_algae = opp_breakdown[keys.index("processor_algae")]
        processor_algae = my_processor_algae + opp_processor_algae
        breakdown[keys.index("processor_algae_points")] += 3 * my_processor_algae
        breakdown[keys.index("net_algae_points")] += 3 * opp_processor_algae
        breakdown[keys.index("teleop_points")] += 3 * processor_algae
        total_change += 3 * processor_algae

    breakdown[0] += total_change

    return breakdown
```

```python
def post_process_attrib(year: Year, epa: Any, err: Any, elim: bool) -> Any:
    keys = all_keys[year.year]
    attrib = epa + err
    if year.year == 2018:
        # Overwrite total points using switch/scale power
        auto_index = keys.index("auto_points")
        teleop_index = keys.index("teleop_points")
        no_foul_index = keys.index("no_foul_points")

        attrib[auto_index] = (
            epa[keys.index("auto_run_points")]
            + 2 * epa[keys.index("auto_switch_secs")]
            + 30 * zero_sigmoid(epa[keys.index("auto_scale_power")] - year.comp_6_mean)
        )

        attrib[teleop_index] = (
            145 * zero_sigmoid(epa[keys.index("switch_power")] - year.comp_7_mean)
            + 145 * zero_sigmoid(epa[keys.index("scale_power")] - year.comp_8_mean)
            + epa[keys.index("vault_points")]
        )

        attrib[no_foul_index] = (
            attrib[auto_index]
            + attrib[teleop_index]
            + epa[keys.index("endgame_points")]
        )

    if year.year == 2025:
        # modifies processor algae to be worth 3 points (from 6)
        update = 3 * err[keys.index("processor_algae")]  # loses 3 points per algae
        err[keys.index("processor_algae_points")] -= update
        err[keys.index("teleop_points")] -= update
        err[keys.index("no_foul_points")] -= update
        attrib = epa + err

    if year.year >= 2016 and elim:
        # Don't update RP score during elim match
        rp_1_index = keys.index("rp_1")
        attrib[rp_1_index] = epa[rp_1_index]

        rp_2_index = keys.index("rp_2")
        attrib[rp_2_index] = epa[rp_2_index]

        if year.year >= 2025:
            rp_3_index = keys.index("rp_3")
            attrib[rp_3_index] = epa[rp_3_index]

    return attrib
```

```python
def post_clean_breakdown(
    key: str, year: int, red_breakdown: BreakdownDict, blue_breakdown: BreakdownDict
) -> Tuple[BreakdownDict, BreakdownDict]:
    if year == 2018:
        # "comp_0": auto_run_points,
        # "comp_1": auto_switch_secs,
        # "comp_2": auto_scale_secs,
        # "comp_3": teleop_switch_secs,
        # "comp_4": teleop_scale_secs,
        # "comp_5": vault_points,
        # "comp_6": auto_scale_power,
        # "comp_7": switch_power,
        # "comp_8": scale_power,
        # "comp_9": opp_switch_power,
        red_auto_scale_secs = red_breakdown["comp_2"] or 0
        blue_auto_scale_secs = blue_breakdown["comp_2"] or 0
        red_switch_secs = red_breakdown["comp_3"] or 0
        blue_switch_secs = blue_breakdown["comp_3"] or 0
        red_scale_secs = red_breakdown["comp_4"] or 0
        blue_scale_secs = blue_breakdown["comp_4"] or 0
        red_opp_switch_secs = 145 - (blue_breakdown["comp_3"] or 0)
        blue_opp_switch_secs = 145 - (red_breakdown["comp_3"] or 0)

        red_breakdown["comp_6"] = min(
            1, max(0, (15 + red_auto_scale_secs - blue_auto_scale_secs) / 30)
        )
        blue_breakdown["comp_6"] = min(
            1, max(0, (15 + blue_auto_scale_secs - red_auto_scale_secs) / 30)
        )

        red_breakdown["comp_7"] = min(1, red_switch_secs / 145)
        blue_breakdown["comp_7"] = min(1, blue_switch_secs / 145)

        red_breakdown["comp_8"] = min(
            1, max(0, (145 + red_scale_secs - blue_scale_secs) / 290)
        )
        blue_breakdown["comp_8"] = min(
            1, max(0, (145 + blue_scale_secs - red_scale_secs) / 290)
        )

        red_breakdown["comp_9"] = min(1, red_opp_switch_secs / 145)
        blue_breakdown["comp_9"] = min(1, blue_opp_switch_secs / 145)

    if year == 2025:
        # tiebreaker is not set correctly in the API so we compute it manually
        # requires at least two processor algae (comp_6) per alliance
        red_processor_algae = red_breakdown["comp_6"] or 0
        blue_processor_algae = blue_breakdown["comp_6"] or 0
        coopertition = min(red_processor_algae, blue_processor_algae) >= 2
        red_breakdown["tiebreaker"] = int(coopertition)
        blue_breakdown["tiebreaker"] = int(coopertition)

    return red_breakdown, blue_breakdown
```

**Every season >= 2016 still PREDICTS ranking points**, whether or not the score reads them:
`predict_match` lines 104-113 pull `rp_1`/`rp_2` (and `rp_3` from 2025) out of the vector
for every season, `AlliancePred` carries them, and `record_match` writes
`epa_red_rp_1_pred` etc. to the database. What changes across seasons is only whether those
values also enter the SCORE, and that happens in exactly two seasons, in elimination matches only.

**Three precise observations a faithful reproduction must not miss:**

1. **2018 applies `zero_sigmoid` TWICE to `switch_power` and `scale_power`.**
   `post_process_breakdown` (section 15) overwrites
   `breakdown[switch_power] = zero_sigmoid(my_switch_power - opp_opp_switch_power)` — so by the
   time `get_score_from_breakdown` runs, that entry is already in (0, 1). The score branch then
   computes `145 * zero_sigmoid(breakdown[switch_power] - opp_breakdown[opp_switch_power])`, a
   second sigmoid over a difference of two already-sigmoided values. `auto_scale_power` is NOT
   touched by `post_process_breakdown`, so its score term is single-sigmoided. Reproducing 2018
   means reproducing that asymmetry.

2. **`post_process_breakdown` runs BEFORE the score read, and writes back into index 0.**
   `breakdown[0] += total_change` is the last line before it returns, so 2023's 9-piece cascade
   and 2025's processor-algae correction both move `no_foul_points` itself. For 2025 that means
   the `else` branch's single read of index 0 is NOT the raw summed rating — it is the rating
   after an **opponent-coupled** correction (`total_change += 3 * (my + opp) processor_algae`).
   2025 therefore looks like a one-entry read and behaves like a two-alliance one.

3. **`post_process_breakdown` mutates in place and is called once per alliance.** In
   `predict_match` the loop calls it for red (passing blue's raw summed vector as
   `opp_pred_mean`) and then for blue (passing red's raw summed vector). Both calls read the
   OTHER alliance's PRE-post-processing vector, because `opp_pred_mean` is recomputed from
   `self.epas` at the top of each iteration rather than taken from `breakdowns[0]`. Order does
   not matter here, and a reproduction that fed the already-post-processed red vector into blue's
   call would silently differ.
