# Derived bonus-RP thresholds — 2019 and 2020

Generated by `scripts/recon-rp-thresholds-2019-2020.ts`. Read-only; no corpus writes.

> **Provenance note, 2026-09-06 (quick task 260906-w38).** The generating script was renamed and
> season-parameterized: `scripts/recon-rp-thresholds-2019-2020.ts` is now
> `scripts/recon-rp-thresholds.ts`, taking `--seasons`. Reproduce with
> `pnpm recon:rp-thresholds -- --seasons 2020 --top 0`. **Every number below is unchanged** — a
> full 2020 re-walk reproduced 7,640 alliance-sides and all five of this document's 2020 rows
> byte-identically, checked mechanically rather than by eye.
>
> **7,640 here vs 7,612 in `tba-rp-rates-2019-2020.md` is correct and deliberate.** The two probes
> filter events differently — this one admits preseason (`EVENT_TYPE_TIERS`), the rates probe does
> not (`IN_SEASON_EVENT_TYPES`, types 0-6). Unifying those filters would silently move every number
> in this document. The two filters are kept distinct in `scripts/recon-shared.ts` with this
> evidence commented at the definition site.
>
> **Candidate pairs are now enumerated, not hand-listed.** The script no longer carries a
> per-season `CANDIDATES`/`BOOLEAN_CANDIDATES` record; it sweeps every observed boolean-vs-numeric
> and boolean-vs-boolean pair and reports the top `--top` per flag per tier (`--top 0` = all). Rows
> recorded here are a subset of what a re-run now emits; none were removed or altered.

Each `RpRuleModule` must RECOMPUTE its bonus flags from threshold variables, because
`predictThresholds` sees only threshold-variable values and never a raw breakdown — a module
that merely echoed TBA's recorded flag could score history but could not predict a match.
That makes the recomputation rule load-bearing, so these thresholds are DERIVED from every
observed alliance-side rather than cited from a game manual.
