> **Provenance note, 2026-09-06 (quick task 260906-w38).** The generating script was renamed and
> season-parameterized: `scripts/recon-rp-rates-2019-2020.ts` is now `scripts/recon-rp-rates.ts`,

> **Every number below is unchanged** — a full 2020 re-walk reproduced 186 in-season events listed,
> 52 that played quals, 3,806 qualification matches, 7,612 alliance-sides, and every flag rate and
> `rp`-distribution row exactly.
>
> **One behavioural change, and it is a superset, not a substitution.** The script no longer reads
> a hardcoded per-season flag list; it enumerates EVERY boolean field in the breakdown. A re-run
> therefore reports one row this document does not have — `tba_shieldEnergizedRankingPointFromFoul`
> (fired 0 of 7,612) — which the old hardcoded list simply never tracked. Nothing recorded here was
> removed or altered. The reason for the change: TBA's ranking-point field naming is not stable
> across FRC eras, so a name filter both misses real RPs (2016 names its Breach/Capture RPs
> `teleopDefensesBreached`/`teleopTowerCaptured`, with no RP-shaped name at all) and falsely admits
> non-RPs (`quintetAchieved`, `coopertitionCriteriaMet`, 2025's `g###Penalty` fields).
(`.planning/todos/pending/extend-corpus-2019-2020.md`). Read-only; no corpus writes.

Measures how OFTEN each bonus RP fires across the FULL season, which the single-event
shape probe could not answer. A threshold variable that fires almost never is worse than
not modelling the RP at all, so these rates decide what `rp/rules/{2019,2020}.ts` should
actually model.

Denominator is alliance-sides (2 per qualification match), matching how the RP flags are
recorded in `score_breakdown`.
